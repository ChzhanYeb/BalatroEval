## 阶段 1：理解 Benchmark 与 Evaluation 的基本概念（约 4h）

### 学习目标
能用自己的话区分 evaluation / benchmark / dataset / harness / protocol / metric / leaderboard / judge，并说明它们在图上的位置。

### 需要理解的概念
- 评测 = 可重复程序 + 特定任务 + 量化 + **有边界的推断**；
- benchmark 不只是数据集，还含协议、指标、维护机制；
- harness 是"跑评测的程序"，可以跑多个 benchmark；
- 协议（prompt/预算/重试/超时）会显著改变分数；
- 分数高 ≠ 设计好 ≠ 有能力。

### 推荐阅读
1. 本知识库 [01-evaluation-fundamentals.md](01-evaluation-fundamentals.md) §1.1–§1.2（必读，2h）；
2. [AI Agents in Depth 第 7 章](https://bojieli.github.io/ai-agent-book/astro/book/chapter7/) 的"评估指标""评估环境"两节（1h，中文，直觉好）；
3. HELM 论文摘要 + §1（https://arxiv.org/abs/2211.09110），看"为什么拒绝单一总分"（0.5h）。

### 必须掌握的问题
1. 为什么"benchmark 分数高"不能证明 benchmark 设计好？各举一个反例。
2. harness 和 benchmark 的区别是什么？同一个 harness 能否跑不同 benchmark？
3. 协议里哪三项最容易导致不可比？为什么？
4. 为什么说"评测是有边界的推断"，而不是"打分"？

### 实践任务
画一张**概念地图**（纸或 Mermaid），包含 8 个术语与它们的关系，并在每个术语旁写一句"它回答什么问题"。

### 完成标准
- 能不看资料画出地图；
- 能向一个非 AI 背景的人解释"为什么同一个模型在两个榜单上排名不同"；
- 能指出自己项目中"哪些属于资产层、哪些属于规则层"。

## 阶段 2：拆解经典 Benchmark（约 6h）

### 学习目标
不再"记住分数"，而是能看懂一个 benchmark 的**设计取舍**：它为什么这样定义任务、这样判定、这样报告。

### 需要理解的概念
- 数据集复用 vs 新造；
- 私有测试集与 hidden set；
- 人类基线的作用；
- 宏平均 vs 加权平均；
- 执行验证 vs 文本比对；
- 饱和与换代（GLUE→SuperGLUE→MMLU→GPQA）。

### 推荐阅读（选 3 个精读，其余读摘要）
| Benchmark | 读什么 | 重点看 |
|---|---|---|
| GLUE（arXiv:1804.07461） | §1、§3.4、§4 | 为什么复用数据集；私有测试集；诊断集的定位 |
| SuperGLUE（arXiv:1905.00537） | §3.1–§3.3 | 提案制；双基线；等权平均的理由 |
| MMLU（arXiv:2009.03300） | §3、§4.1、§5 | 数据来源；57 学科；加权准确率 |
| GPQA（arXiv:2311.12022） | §1、§2.1–§2.3 | Google-proof；专家 65% vs 非专家 34%；canary |
| HumanEval（arXiv:2107.03374） | §2.1–§2.2 | pass@k 无偏估计量；手写题防污染 |
| SWE-bench（arXiv:2310.06770） | §2.1–§2.2、§3 | 三阶段自动构造；fail-to-pass；仓库隔离 |

配套：本知识库 [02-classic-benchmarks.md](02-classic-benchmarks.md) §2.1（可当导读，但**必须回原文核对至少 3 个数字**）。

### 必须掌握的问题
1. GLUE 为什么不新造数据？这个选择的代价是什么？
2. SuperGLUE 的"人类基线"解决了什么问题？没有它会怎样？
3. MMLU 的题目从哪来？这带来什么污染风险？
4. GPQA 的 canary string 是干什么的？它能证明"无污染"吗？
5. 写出 pass@k 的估计量，并解释为什么不用 $1-(1-\hat p)^k$。
6. SWE-bench 如何保证"每个实例都可判定"？

### 实践任务
做 **3 张 benchmark 解剖卡**（每张 A4 半页），固定栏目：

```text
名称/年份/venue：
想解决什么问题：
测什么能力（可观测行为）：
数据从哪来（人工/自动/复用）：
怎么判定（程序/LLM/人）：
指标与聚合方式：
防污染手段：
作者自述的局限（引用原文位置）：
如果我要在自己的项目里借用它的一个设计，借哪个？为什么？
```

建议选：GLUE（聚合）、HumanEval（执行验证）、SWE-bench（自动构造）。

### 完成标准
- 3 张卡都能追溯到论文原文（标出章节）；
- 能说出至少 2 个"我不能照搬"的设计及原因；
- 能解释"为什么 pass@k 不能用来论证可靠性"。

## 阶段 3：学习 Agent 评测环境（约 6h）

### 学习目标
理解"环境"是 Agent 评测的核心资产，能设计一个环境的状态、动作、重置与判定。

### 需要理解的概念
- 五要素：数据集、环境状态、工具接口、评分标准、执行协议；
- 动作空间形态（自由文本 / DSL / 代码 / 工具调用）；
- 重置机制（Docker / VM 快照 / 脚本 / 无重置）；
- 判定强度（DB 状态 > 执行测试 > locator 断言 > 精确匹配 > LLM judge）；
- 双控环境（用户也操作环境）。

### 推荐阅读
1. [AI Agents in Depth 第 7 章](https://bojieli.github.io/ai-agent-book/astro/book/chapter7/) "一条评估任务的解剖" + "评估环境"（2h，τ²-bench 的任务文件逐字段讲解，非常适合入门）；
2. AgentBench（arXiv:2308.03688）§2、§4.1 与表 2（1h）；
3. WebArena（arXiv:2307.13854）§2.1–§2.2、§3.2（1.5h，看 DSL 与 r_prog）；
4. OSWorld（arXiv:2404.07972）§2.2、表 1（1h，看 getter/evaluator）；
5. 选读：τ-bench（arXiv:2406.12045）§3 的 pass^k 定义。

### 必须掌握的问题
1. 一个可重复环境必须有哪五个要素？缺一个会怎样？
2. 为什么"自由文本动作"需要额外的错误分类（格式错 vs 动作错）？
3. WebArena 的 `r_prog` 与"让 judge 看截图"的本质区别是什么？
4. OSWorld 为什么把"取数"（getter）和"判断"（evaluator）分开？
5. 如果一个环境不能重置，你还能做评测吗？需要付出什么代价？
6. τ-bench 的奖励 $r = r_{\text{action}} \times r_{\text{output}}$ 中，两个因子各防住了什么失败？

### 实践任务
填一张**12 问对照表**（行 = AgentBench / WebArena / OSWorld / τ-bench / GAIA，列 = 任务定义、动作空间、状态表示、重置、判定、多轮、部分成功、可复现、trace）。

然后回答：**如果我要给 BalatroEval 选一个参照架构，选哪个？为什么？**

### 完成标准
- 表格每格都有论文依据（章节号）；
- 能说明"为什么 GAIA 不需要环境，而 OSWorld 必须有"；
- 能指出本项目 `bridge/` 若要做真游戏终验，最该抄的是 τ-bench 的哪一部分（DB 状态判定）与 OSWorld 的哪一部分（getter/evaluator）。

## 阶段 4：学习任务与场景设计（约 6h）

### 学习目标
能把一个抽象能力翻译成"可程序判定"的场景，并证明它测的是目标能力。

### 需要理解的概念
- 场景十构件（模板/场景/初始状态/目标/约束/动作/观测/转移/终止/难度）；
- 单一能力原则与消融变体；
- 反事实场景；
- 难度参数化；
- margin（最优与次优的差距）；
- **"贪心是否近似最优"作为有效性检验**。

### 推荐阅读
1. 本知识库 [03-agent-benchmark-design.md](03-agent-benchmark-design.md) §3.1–§3.3（2h，含两个完整示例）；
2. WebArena §2.1（模板 → 实例的设计）；
3. BALROG（arXiv:2411.13543）§3.1（不固定局面的路线）；
4. 选读：WorkArena（arXiv:2403.07718）§4.2 的 `setup/teardown/validate/cheat`（看自检机制）。

### 必须掌握的问题
1. 把"测长期规划"改写成一句可证伪的假设（含环境、行为、指标、对照）。
2. 为什么"资源每阶段重置"会让任务测不到资源分配？
3. 一个场景的"预期行为"为什么有时是一组动作而不是一个动作？
4. 如何证明"这个场景测的是规划，不是算分"？（提示：消融 + margin）
5. 反事实场景与普通场景的区别是什么？为什么要记 `parent_scenario_id`？

### 实践任务
为当前项目的引擎设计 **3 个场景**：
- 1 个单步（L1 风格），必须含完整十构件；
- 1 个"盲注内多步"（L3 风格）；
- 1 个"跨阶段资源"（设计示意即可，标清当前引擎不支持哪些机制）。

每个场景必须写出：初始状态 JSON、合法动作数、oracle 与保证范围、失败条件、**它究竟测了什么、没测什么**。

### 完成标准
- 三个场景都能被程序判定（不需要人看）；
- 单步场景能用现有 `bench` 代码实际运行并得到 oracle 分；
- 能说清第三个场景为什么现在跑不了（引用 `RULES_VERSION.excluded`）；
- 能指出"如果去掉目标能力，这个场景是否仍然可解"。

## 阶段 5：学习 Oracle 与指标（约 6h）

### 学习目标
能为每个指标写出"定义 + 边界 + 误用 + 代码"，并说清 oracle 的保证范围。

### 需要理解的概念
- Ground Truth / Reference / Exact Oracle / Approximate Oracle 的区别；
- 局部最优 vs 全局最优；
- 目标函数与 oracle 的绑定关系；
- exact / approx / heuristic 标注；
- 指标边界（分母为 0、负 regret、并列最优）。

### 推荐阅读
1. 本知识库 [04-metrics-and-statistics.md](04-metrics-and-statistics.md) §4.2（2h，指标卡）；
2. [03](03-agent-benchmark-design.md) §3.5（Oracle 保证范围）；
3. HumanEval §2.1（pass@k）；τ-bench §3（pass^k）；
4. 选读：AgentBoard（arXiv:2401.13178）§2.2（progress rate 的设计与脆弱性）。

### 必须掌握的问题
1. 写出 regret 的公式，解释 $V^*=0$ 时为什么返回 None。
2. 为什么负 regret 不应该被截断？它说明了什么？
3. pass@k 与 pass^k 的方向为什么相反？各举一个业务场景。
4. "oracle 是穷举的"能保证什么、不能保证什么？
5. 如果一个指标只能报点值（无区间），它适合做近似量的指标吗？

### 实践任务
用 Python（stdlib）实现 6 个指标：`success_rate`、`pass_at_k`、`pass_hat_k`、`regret`、`action_optimality`、`legality_rate`，并为每个写 4 个边界测试（空输入、分母 0、并列、超额）。

在**当前项目的 60 个决策点设计**上，标注每个指标"能算/不能算/需要什么才能算"。

### 完成标准
- 6 个函数全部通过边界测试；
- 能解释"为什么 Local Regret 不能平均成长程指标"；
- 能写出 O1/O2/O3 各自的"保证/不保证"两列表。

## 阶段 6：学习统计实验（约 6h）

### 学习目标
能设计一次配对实验，报出 n、效应量、CI，并知道什么时候不能下结论。

### 需要理解的概念
- 配对设计与方差削减；
- McNemar（二值）vs Wilcoxon（连续）；
- Holm 校正；
- bootstrap 与 CLT 的取舍；
- 聚类标准误；
- 功效分析与最小可检测效应；
- 相关 vs 因果。

### 推荐阅读
1. 本知识库 [04](04-metrics-and-statistics.md) §4.3–§4.6（2h）；
2. Miller, *Adding Error Bars to Evals*（arXiv:2411.00640）§2.1、§4.2（2h，重点看"题目是抽样单位""聚类 SE""重复采样收益递减"）；
3. Kapoor et al., *AI Agents That Matter*（arXiv:2407.01502）§2、§5（1h，看成本控制与 holdout）；
4. 工具书：scipy 的 `wilcoxon` / `mcnemar` 文档（0.5h，知道参数即可）。

### 必须掌握的问题
1. 为什么配对能提高功效？用方差公式解释。
2. McNemar 为什么只看不一致对？$b$ 和 $c$ 分别是什么？
3. Holm 与 Bonferroni 的区别？为什么 Holm 更好？
4. 什么时候必须用聚类标准误？忽略会怎样（给出数量级）？
5. n=30、σ_d=0.25 时能检测多小的 Δ？如果真实差异是 0.08，你该怎么写结论？
6. 为什么"重复跑 5 次取平均"不能把 5×30 当 150 个独立样本？

### 实践任务
用**合成数据**（固定 seed）做一次完整分析：
1. 3 个配置 × 30 场景的配对 regret；
2. 报均值、中位数、95% CI；
3. 做 3 次两两 Wilcoxon + Holm；
4. 报 rank-biserial；
5. 写一段"可以写"和"不可以写"的结论对照。

（本知识库 [04](04-metrics-and-statistics.md) §4.5 有一个可复现的算例，可以先跑通再改数据。）

### 完成标准
- 能解释输出里每个数字的含义；
- 能指出"哪个比较显著但效应量小"；
- 能写出"本实验只能检测 Δ≥X"的句子；
- 能说明若数据成簇，CI 会怎么变。

## 阶段 7：学习 Evaluation Harness（约 8h）

### 学习目标
能写一个最小可用的评测框架：加载数据 → 跑 episode → 记 trace → 判分 → 出表。

### 需要理解的概念
- 执行期与分析期分离；
- Environment / Agent / Model 三层 adapter；
- Episode Runner 的终止条件与非法动作策略；
- trace schema（原始/解析/推断分层）；
- 并发与限流、断点续跑；
- 负对照（random / oracle / 固定错误）。

### 推荐阅读
1. 本知识库 [05-evaluation-framework-engineering.md](05-evaluation-framework-engineering.md)（3h，边读边写）；
2. lm-evaluation-harness 的 README 与 `lm_eval/` 目录结构（1h，看工业界怎么组织 task）；
3. HELM 的 scenario/adapter 抽象（1h，看"统一 prompt + 多指标"如何实现）；
4. 选读：AgentBench 的 Docker 隔离方案（1h）。

### 必须掌握的问题
1. 为什么 evaluator 要读落盘 trace，而不是在 runner 里直接判？
2. `Scenario.agent_view()` 为什么必须是方法而不是约定？
3. 非法动作的四种处理策略各有什么后果？为什么必须预注册？
4. trace 里哪些字段属于"原始"、哪些属于"推断"？为什么分文件？
5. 哪些操作可以并发、哪些必须串行？
6. 断点续跑为什么不能 pickle 环境？

### 实践任务
实现一个**最小 harness**（200–400 行，stdlib）：
- 支持 1 个内置环境（可以就用 `bench/` 的简化版，或一个玩具网格世界）；
- 支持 2 个脚本化 agent（random、oracle）；
- 输出：每局 trace JSONL + 汇总 CSV（含 success、steps、非法动作数）；
- 至少 3 个单元测试 + 1 个负对照测试（oracle 应得满分、random 应显著低）。

### 完成标准
- 一条命令跑完 10 局并出表；
- oracle agent 的 success=1、random 明显低；
- trace 能被重放（state_hash 序列一致）；
- 能指出自己的实现省略了哪些生产必需项（对照 [05](05-evaluation-framework-engineering.md) §4.9）。

## 阶段 8：学习 Trace 与失败分析（约 6h）

### 学习目标
能从 trace 出发，做出"有证据层级"的失败归因，而不是凭感觉解释。

### 需要理解的概念
- 四层证据：观察 / 行为推断 / 干预验证 / 机制解释；
- 错误分类学（互斥、可判定、可行动）；
- 最小反例；
- 证据链（rule_id + state_hash + 引用原文）；
- 诊断器一致性（Cohen's κ、混淆矩阵、弃权率）；
- 不要把环境问题算成 Agent 失败。

### 推荐阅读
1. 本知识库 [04](04-metrics-and-statistics.md) §4.7（1.5h）；
2. [AI Agents in Depth 第 7 章](https://bojieli.github.io/ai-agent-book/astro/book/chapter7/) "失败归因""Agent 的可观测性"两节（2h，有 AndroidWorld 真实失败案例，非常适合练手）；
3. AgentRewardBench（arXiv:2504.08942）摘要 + 方法（0.5h，看"规则判定会低报成功"）；
4. 选读：本项目 `plan/详细版/04-失败归因器.md`（1h，看 F1–F4/F0/E1 设计与证据链要求）。

### 必须掌握的问题
1. "第 3 步选了低分动作"属于哪一层证据？"模型没有规划能力"属于哪一层？
2. 为什么 F4（规划不足）只能是 heuristic？它能不能进显著性检验？
3. 最小反例能证明什么、不能证明什么？
4. 诊断器的 κ 低说明什么？应该先修什么？
5. 如何区分"Agent 失败"与"环境分歧"？各举一例。

### 实践任务
拿 5 条真实/半真实 trace（可以用阶段 7 的 harness 跑 random agent 得到），写一份**归因报告**：
- 每条：首错步号、错误类别、证据引用、置信度、证据层级；
- 至少 2 条要给出"最小反例"（替换动作后的结果）；
- 最后写一段"我无法归因的部分"。

### 完成标准
- 每条归因都标了 `layer`（观察/推断/验证）；
- 没有一条从 L1 直接跳到 L4；
- 能指出"如果这条是环境 bug，会表现成什么样"；
- 报告里区分了 root cause 与 consequence。

## 本章应该掌握什么

学完这条路线，你应当能够独立完成下面六件事（它们也是本路线的验收总纲）：

1. **判断效度**：拿到一份评测方案，能指出它测的是不是声称的能力，并说出至少一个反例。
2. **设计场景**：把一个抽象能力翻译成含十构件、可程序判定的场景，并证明贪心策略在该场景上不是最优（或承认它是最优、因此不测规划）。
3. **定义指标**：为每个指标写出公式、方向、单位、精确性、适用条件、不适用场景与边界处理。
4. **做统计**：设计配对实验、算所需样本量、报 CI 与效应量、做多重比较校正，并写出"能/不能下什么结论"。
5. **写框架**：实现一个可跑、可重放、可断点续跑的最小 harness，并用负对照证明它能区分强弱。
6. **做归因**：从 trace 出发写四层证据的失败分析，不把行为推断说成机制解释。

## 常见学习误区

| 误区 | 为什么错 | 正确做法 |
|---|---|---|
| 只读论文不动手 | 评测是工程活，读不会"判定强度"的直觉 | 每阶段必须有产出物 |
| 追求"读完所有 benchmark" | 20 个 benchmark 的摘要不如 3 个精读 | 选 3 个拆透，其余用时再查 |
| 一上来学统计 | 没有指标定义，统计无对象 | 先阶段 5 再阶段 6 |
| 只学"怎么算分"，不学"怎么判对" | 判定是评测的核心 | 阶段 3–4 重点 |
| 把"跑通框架"当成"会评测" | 框架只是执行层 | 阶段 4–6 才是方法论 |
| 不敢质疑项目文档 | 文档可能是目标态 | 用代码与行号核对（阶段 9） |
