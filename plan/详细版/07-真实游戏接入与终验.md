## 0. 一句话结论

**v3.0 把“自建子集引擎”从“唯一评测环境”降级为“快速、确定性、与真规则对齐的训练/开发环境（ATE）”；把“真实游戏（Balatro + balatrobot）”升级为最终真实环境测试（RGFT）。**

```text
ATE（快、可枚举、可 CI） ──A0–A4 对齐契约──► RGFT（慢、不可并行、最终证据）
  开发 Agent / 算 oracle / 跑 ATS 60 决策点      回答“离开自建环境还成立吗”
```

**三条不可越过的边界**：

1. 自建引擎只实现**真规则的严格子集**：实现到的必须与真游戏逐位一致，没实现的必须在场景中排除，不能“用自定义公式近似”。
2. 训练/开发集可自建，但**每个入集局面必须有真游戏来源或回放证据**；无证据不得进入主表。
3. 真实游戏只做**小规模终验**（非批量主环境），按小样本描述统计报告，不做显著性主张。

## 1. 为什么改（决策触发）

| 旧决策（v2.2） | 问题 |
|---|---|
| D1：**自建子集**，真游戏只做人工对拍 | W2 旧引擎（`c65fb9b`）是 **L0 自定义公式**（合成 Joker、3 槽位、300/800/2000、4 手/2 弃）；当时 25 项单测只证自洽 |
| D2：**不接入真游戏** | 保真度只靠 20 例人工对拍，且 0/20 |
| 训练/评测集全由引擎生成 | 生成器与引擎共享同一套规则，**误差自洽**：引擎错，场景也错 |
| 失败归因只在自建环境做 | 无法区分“Agent 决策错”与“环境规则不一致” |

v3.0 只回答一个问题：**把“规则可信”从“内部自洽”提升为“与真游戏对齐 + 真游戏终验”。**

> 历史与现状：W2 旧引擎已于 2026-11-17 升级为 **vanilla 1.0.1o 严格子集 v1**（§7）。升级只完成实现与测试，**没有**完成 A2/A3 对齐；其中的真游戏对齐、捕获、台账项仍为 📋。

## 2. 两阶段架构

```text
阶段一 ATE：真游戏捕获 ─┐
             反事实变体 ─┴─► ATS（60 决策点）─► bench 引擎 / O1–O3 / Agent
产物：scenarios/v3/*.jsonl + 对齐台账 + 规则金样

阶段二 RGFT：Balatro 1.0.1o + Lovely + Steamodded + balatrobot（JSON-RPC）
             + bridge/realgame_adapter（薄壳）+ dsh Agent（MCP）
产物：runs/w5-real/* + 终验报告
```

- **不维护第二份规则实现**：真游戏侧不复算规则，只读 `gamestate` 与动作结果；自建引擎是唯一“可枚举 oracle”，但必须服从对齐契约。
- **适配器是薄壳**：只做 JSON-RPC、字段映射、动作 id↔下标转换、错误码统一。
- **训练集不是“引擎生成后自嗨”**：以真游戏捕获为锚点，变体须通过 `save`/`load` 在真游戏回放验证。

## 3. 对齐契约（Alignment Contract）

**训练/开发集只允许包含通过 A0–A4 的局面。**

| 级别 | 对象 | 要求 | 验收证据（当前状态） |
|---|---|---|---|
| **A0 版本锁定** | 游戏/注入链/适配器 | 记录 `game_version`、`build_id`、`deck`、`stake`、依赖版本；同批不跨版本 | 📋 `scenarios/v3/MANIFEST.json`（未创建） |
| **A1 状态/动作 schema** | `gamestate` ↔ `GameState` | 手牌、牌堆计数、Joker、盲注、目标分、资源、阶段可映射；动作绑稳定 id + 下标快照 | 📋 `tests/test_realgame_schema.py` + 逐字段 diff（未创建） |
| **A2 单步分数** | `score_hand` ↔ 真游戏得分 | 同局面、同出牌，`engine_score == real_score`；否则追根因或排除 | 📋 `docs/quality/engine-fidelity.md` A 表（捕获）+ B 表（`save`/`load` 回放），**0 行 / PENDING** |
| **A3 规则子集** | 计分/牌型/筛选/Joker/盲注/资源/**经济** | 已实现规则与 vanilla 1.0.1o 一致；未实现入 `RULES_VERSION.excluded` 且不入集 | 本地金样（`test_w2_rules.py`、`test_economy.py`、`test_rules_declaration.py`）；📋 真游戏 A3 实测 0 行（经济口径 5 条未测） |
| **A4 场景来源与回放** | 训练/开发集 | `origin` + `capture_id` + 验证过的动作/分数；无证据不入集 | 📋 `validation` 字段 + `evidence/W3/`（未创建） |

### 3.1 对齐等级（用于报告措辞）

| 等级 | 含义 | 可以写 | 不可以写 |
|---|---|---|---|
| **L0 未对齐** | 已实现 vanilla 1.0.1o 严格子集 v2（计分 + 经济），但 A2/A3 实测 0 行 | “子集内自洽；157 项测试通过” | “与真游戏一致” |
| **L1 分数对齐** | A2 在覆盖局面上 100% 一致 | “覆盖局面上单步分数一致（n=…）” | “完整规则一致” |
| **L2 规则子集对齐** | A2+A3 全部通过 | “实现规则是 vanilla 的严格子集” | “复刻了全部 150 个 Joker” |
| **L3 终验通过** | 真游戏终验完成且可复现 | “在真实游戏上完成 n 局终验” | “真实环境 SOTA / 统计显著” |

> 当前 **L0**。**实现完成 ≠ 验证**：代码存在、测试全绿，不等于 A2/A3 有实测行。W3 目标 **L2**；W5 目标 **L3**。

## 4. 真实游戏适配器（balatrobot）

### 4.1 运行栈与版本

Balatro（Steam 正版，仅本机）→ Lovely（MIT，注入）→ Steamodded（GPL-3.0，mod 框架）→ `coder/balatrobot`（MIT，JSON-RPC 2.0）。基线 Balatro `1.0.1o`；依赖以安装当日 release 为准，写入 `MANIFEST.json`；断链不追新，锁旧版或重跑对齐。

### 4.2 API 与动作绑定（22 个方法中的最小集）

`health`/`rpc.discover`/`gamestate`/`start`/`save`/`load`/`select`/`skip`/`cash_out`/`next_round`/`play`/`discard`/`buy`/`pack`/`sell`/`reroll`/`use`；`add`/`set` 只做自检，`screenshot` 留证。`start` 的 seed 只保证真游戏内可复现，不与引擎同局面；`play`/`discard` 参数是手牌下标，适配器调用前用 `gamestate` 把稳定 id 映射为下标，JSONL 同时记 `card_ids` 与 `hand_indices`，下标不作回放主键。

### 4.3 状态映射（`gamestate` → `GameState`）

`state`→`phase`（SELECTING_HAND/SHOP/GAME_OVER→play/shop/done，其余不进 oracle）；`round.*`→`hands_left`/`discards_left`/`total_score`；`blinds.current.score`→`target`；`hand.cards[]`→`hand`（花色 H/D/C/S→0/1/2/3，点数 2–9/T/J/Q/K/A→2–10/11/12/13/1，`id` 稳定）；`jokers.cards[]` 只接受具名 vanilla，`modifier`（edition/seal/enhancement）非空→`unsupported`；`cards.count`→`len(deck)`，`deck`/`stake`/`seed` 写 header。

**不支持即排除**：Boss 负面效果、消耗牌、补充包、增强/版本/印章、金钱与利息、商店 reroll 等引擎不实现；含这些要素的局面只作“真游戏记录”进入终验 trace，不进 oracle 训练集。

### 4.4 捕获/回放/验证流水线（📋）

`start → select → gamestate/记录 → save → play/discard` 捕获；选 30 个决策点建集；`load(save)` 执行不同动作做变体；引擎重放同一动作，比对 score/hand/deck_count/资源；通过 A1–A4 入集，否则 `rejected` + 原因。`save`/`load` 让变体在真游戏执行，不依赖 RNG 复刻；`add`/`set` 只用于自检。

## 5. 自建训练/开发集（ATS，Aligned Training Set）

> 本项目**不训练/微调模型**；“训练集”指 Agent 开发、提示词调试与轻量评测用的**对齐场景集**。当前 **0/60**。

### 5.1 组成（60 个决策点）

| 类别 | 数量 | 来源 | 说明 |
|---|---:|---|---|
| **R 类：真游戏锚点** | 30 | `real_capture` | Ante 1（白注、Red Deck）；覆盖无 Joker / 单 Joker / 双 Joker / 含 xMult / 多弃牌 |
| **C 类：反事实变体** | 30 | `real_counterfactual` | 锚点 `load` 后执行不同合法动作并实测；覆盖“同局面、不同选择” |
| 合计 | 60 | — | 不再由引擎“生成后直接入集” |

分层语义是**决策难度**而非引擎合成难度：L1 基础 20（无 Joker、标准牌型、单步 play）／L2 组合 20（1–2 个 vanilla Joker，含 +Chips/+Mult/xMult 顺序）／L3 长程 15（同盲注内多次 play/discard）／L4 极限 5（高目标/搏牌型，仍以真游戏可回放为前提）。

### 5.2 场景 Schema（v3）

在旧 Schema 上增加“来源与验证”字段；`oracle` 必须区分是否全动作验证。

```jsonc
{
  "scenario_id": "L2-0007", "schema_version": 3,
  "origin": "real_capture",              // real_capture | real_counterfactual
  "game": {"version": "1.0.1o", "build_id": "...", "deck": "RED", "stake": "WHITE",
           "seed": "ABC123", "capture_id": "cap-20261120-001",
           "saved_state": "data/realgame/saves/cap-...-step03.jkr"},
  "initial_state": { /* GameState 投影 */ },
  "available_actions": ["play:c3h,c7s", "discard:c5d"],
  "oracle": {"best_actions": ["play:c3h,c7s"], "best_score": 48,
             "exact": true, "validated_actions": 218, "unvalidated_actions": 0},
  "validation": {"engine_score_equals_real": true, "legal_actions_match": true,
                 "state_transition_match": true, "evidence": "evidence/W3/align/L2-0007.json"},
  "tags": {"decision_depth": 1, "branch_count": 436, "horizon_need": 0},
  "metadata": {"rules_version": "vanilla_1.0.1o_subset_v2"}
}
```

- `exact: true`：该局面 218 个出牌动作全部在真游戏回放并记录得分（弃牌只校验合法性与状态转移；成本高，只做少量，如 6 个 L1 局面）。
- `exact: false`：只验证 top-k（k=3）+ 2 个随机出牌动作；`best_actions` 是“已验证子集最优”，报告须注明不是全局最优。
- `best_score == 0` 的局面不进 regret 分母，单独计数。

### 5.3 入集门槛（缺一不可）

- [ ] G1 版本/来源完整（A0）；G2 状态字段可映射（A1）；
- [ ] G3 至少一个动作真游戏分数与引擎一致（A2；全动作一致才可标 `exact`）；G4 合法动作集一致（A1/A3）；
- [ ] G5 状态转移覆盖字段一致（分数、手牌、剩余资源；牌堆只比计数）；G6 证据可重放（`evidence/W3/align/<scenario_id>.json`）。

不满足任一项 → `rejected` 清单 + 原因，**不得**“先入集、以后补验证”。

### 5.4 禁止事项

❌ 用 `add`/`set` 造“真游戏从未出现”的局面当锚点；❌ 只用引擎生成、未在真游戏回放的局面；❌ 把 `exact: false` 写成“全局最优”；❌ 混用不同版本/牌组/赌注的捕获；❌ 在训练集保留未实现规则要素。

## 6. 真实游戏终验协议（RGFT）

### 6.1 规模与预算（小样本，描述性）

3 组（A 本地直答 / B 本地 CoT / C 云端 CoT），每组 4 局 = **12 局**；单局 Ante 1 三盲注（Small/Big/Boss），上限 15 分钟或 3 盲注结束，超时记 `timeout` 不剔除、单列；总预算约 4–6h（setup 另计 3–5h）；统计用描述统计 + bootstrap 95% CI，**不做显著性主张**（n=12，功效不足）。

### 6.2 工具集（训练 5 个 / 真实 5 个）

训练环境现有 5 个：`get_state` / `play_cards` / `discard_cards` / `choose_joker` / `reset_episode`。真实环境同样 5 个，把 `choose_joker` 换成 `shop_action`、`reset_episode` 换成 `advance_phase`：`get_state`→`gamestate`；`play_cards`/`discard_cards`→`play`/`discard`（稳定 id 转下标）；`shop_action`→`buy`/`sell`/`reroll`/`pack`/`use`；`advance_phase`→`select`/`skip`/`cash_out`/`next_round`/`menu`。

> schema ≤ 1200 token；每个工具声明 `required_state` 与统一错误码（训练环境的 11 个码；真游戏适配器计划新增 `ADAPTER_ERROR`，📋 未实现）。两套工具的**动作语义**必须一致。

### 6.3 终验指标

| 指标 | 定义 | 精确性 | 备注 |
|---|---|---|---|
| `blinds_cleared` / `ante1_win` / `legality_rate` / `timeout_rate` | 通过盲注/3、Ante 1 胜否；合法率；超时局/12 | exact | 主指标 + 基础设施 |
| `first_failure_step` / `agent_failure_class` | 首次 regret≥0.5 的步；F1–F4 + F0 | exact / heuristic | 仅 play/discard；见 `04-失败归因器.md` |
| `env_divergence` / `real_vs_training_gap` / `cost` | 环境分歧次数；训练集与终验差异；token/秒/$ 每局 | exact / 描述性 | 分歧**非 Agent 失败**，单列；成本必报 |

### 6.4 终验验收

- [ ] 12 局全部有完整 trace（状态/动作/得分/截图或等价证据），无“只记结果”；至少 9 局走到 Ante 1 结束（3 局以内失败/超时可接受并单列）；
- [ ] `legality_rate`、`timeout_rate`、`env_divergence` 齐全；每条失败有 F1–F4/F0 标签或 `insufficient_evidence`；
- [ ] 报告写明 n=12、单局范围、版本链、不可复现风险；未达成时如实写“终验未完成”，不得用训练集结果替代。

### 6.5 降级方案（不可用时）

1. **不得**把终验标为通过；
2. 退回“真游戏捕获回放验证”（只做 A2/A4，不做 Agent 终验），报告写 `fidelity_status: CAPTURE_REPLAY_ONLY`；
3. 训练集仍须来自真游戏捕获，不得退回纯引擎生成；在 README、报告、简历明确写“真实游戏终验未执行（环境不可达）”。

- 已实现：起始 $4、奖励 3/4/5、每剩余 1 手/每未用 1 弃牌 +$1、利息 `min(money//5, 5)`、Small/Big 后 2 报价商店、买/卖(半价)/reroll($5 起 +$1)/离开、Boss 通关即 win。
- 未验证（`Ruleset.unverified`，**不得**当作已对齐）：利息用入账前金额、价格按稀有度取中值、商店候选均匀抽样（无原版权重）、reroll 走自带 RNG、卖掉的 Joker 可再次出现。
- A3 扩项：以上 5 条都要在真游戏商店界面/捕获里逐条核对，才能把 `fidelity_status` 往 L1/L2 推。

> 简化原则：**简化只能“少做”，不能“做错”**。已实现规则必须与真游戏逐位一致；未实现规则必须在场景层面排除。合成 Joker 只可作单元测试夹具，不得进入训练集/主表。

### 7.4 仍未验证（⏳）

末尾 `floor(chips×mult)` 是候选口径（`final_score_rounding_floor_candidate`）；4K/5K 与“含对子/含三条”的结构超集关系（`contains_relation_for_four_kind_and_five_kind`）；跨盲注补牌/重抽、Boss 效果缺失的语义边界；A2 单步分数相等（**0 行**）。以上均 ⏳，不得写成已验证。

| 风险 | 影响 | 对策 |
|---|---|---|
| 四层依赖安装 3–5h，版本链脆弱 | W3 延期 | 版本锁定；先跑 `health`/`gamestate` 冒烟；失败即降级“捕获回放” |
