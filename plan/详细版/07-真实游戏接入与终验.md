# 07 真实游戏接入与终验（v3.0）

> 项目正式名：**BalatroEval**（无副标题）；定位：面向大模型 Agent 的长线规划测试集；失败归因仅作诊断报告层。
> 文档性质：v3.0 **决策基线**。本文件优先于 v2.1/v2.2 中“不接入真游戏”的旧表述；与 `00-项目全貌.md` 的 D1/D2/**D18** 同步生效（D12 已被 D18 取代）。
> 版本：v3.0-2026-11-13 ｜ 状态：📋 规划（真实游戏接入尚未执行，任何“已接入/已对齐/已终验”的表述都属越线）
> v4.0（2026-11-13）：项目改名 **BalatroEval** 并重定位为长线规划测试集；本文件的两阶段 / A0–A4 / L0–L3 / 12 局终验决策**不变**。
> 依据：`docs/research/04-balatro-ecosystem.md`（26 个项目核实）、`docs/data-sources.md`、balatrobot 官方 API 文档（2026-11-13 读取）

## 0. 一句话结论

**v3.0 把“自建子集引擎”从“唯一评测环境”降级为“快速、确定性、与真规则对齐的训练/开发环境”；把“真实游戏（Balatro + balatrobot）”升级为最终真实环境测试。**

两条环境不是二选一，而是上下游：

```
自建训练/开发环境（快、可枚举、可 CI）  ──对齐契约──►  真实游戏终验（慢、不可并行、最终证据）
        │                                                        │
        │ 用来开发 Agent、算 oracle、跑 60 场景                    │ 用来回答“离开自建环境还成立吗”
        └────────────── 训练集自建，但每条都必须与真游戏对齐 ──────┘
```

**三条不可越过的边界**：

1. 自建引擎只实现**真规则的一个严格子集**：实现到的规则必须与真游戏逐位一致；没实现的规则必须在场景中排除，不能“用自定义公式近似”。
2. 训练/开发集可以自建，但**每个进入评测集的局面必须有真游戏来源或真游戏回放证据**；只有自建、没有真游戏验证的局面不得进入主表。
3. 真实游戏是**终验**，不是批量主环境：受单局时长、图形依赖、版本链限制，只跑固定的小规模终验；结论按小样本描述统计报告，不做显著性主张。

## 1. 为什么改（决策触发）

| 旧决策（v2.2） | 问题 |
|---|---|
| D1：**自建规则子集**，真游戏只做人工对拍 | 自建公式是自定义的（无牌型基础 Chips、倍率表不同、合成 Joker），即使 25 项单测全绿，也无法回答“Agent 在真游戏里是否也这样失败” |
| D2：**不接入真游戏** | 保真度只能靠 20 例人工对拍，且当前 0/20；外部效度（external validity）没有最终证据 |
| 训练集/评测集完全由自建引擎生成 | 生成器与引擎共享同一套自定义规则，**误差自洽**：引擎错，场景也错，评测结论一起错 |
| 失败归因只在自建环境做 | 归因结论无法区分“Agent 决策错”与“环境规则不一致” |

v3.0 的改动只回答一个问题：**把“规则可信”从“内部自洽”提升为“与真游戏对齐 + 真游戏终验”。**

## 2. 两阶段架构

```
┌──────────────────────────────────────────────────────────────────┐
│ 阶段一：对齐训练/开发环境（ATE）                                  │
│                                                                  │
│  真实游戏捕获（balatrobot） ──┐                                   │
│                              ├─► 对齐场景集 ATS（60 个决策点）    │
│  自建反事实变体（save/load） ─┘         │                         │
│                                          ├─► bench 引擎（严格子集）│
│                                          ├─► O1/O2/O3 oracle      │
│                                          └─► 训练/开发 Agent      │
│  产物：scenarios/v3/*.jsonl + 对齐台账 + 规则金样                 │
└──────────────────────────────────────────────────────────────────┘
                              │ 同一套 MCP 工具语义
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│ 阶段二：真实游戏终验（RGFT）                                      │
│                                                                  │
│  Balatro（Steam 1.0.1o 基线）                                      │
│    + Lovely + Steamodded（balatrobot 运行前置）                    │
│    + balatrobot（JSON-RPC 2.0 @ 127.0.0.1:12346）                 │
│    + bridge/realgame_adapter（本仓库，薄壳）                       │
│    + dsh Agent（MCP 工具调用）                                     │
│                                                                  │
│  产物：runs/w5-real/*（全量状态/动作/分数/trace）+ 终验报告        │
└──────────────────────────────────────────────────────────────────┘
```

**关键架构决策**：

- **不维护第二份规则实现**：真游戏侧不做规则复算，只读 `gamestate` 与动作结果；自建引擎是唯一“可枚举 oracle”的实现，但它必须服从对齐契约。
- **适配器是薄壳**：只做 JSON-RPC 调用、字段映射、动作 id↔下标转换、错误码统一；不写规则。
- **训练集不是“引擎生成后自嗨”**：以真游戏捕获的局面为锚点，自建变体必须通过 `save`/`load` 在真游戏中回放验证。

## 3. 对齐契约（Alignment Contract）

“对齐”不是一句口号，而是五级可验收的契约。**训练/开发集只允许包含通过 A0–A4 的局面。**

| 级别 | 对齐对象 | 要求 | 验收证据 |
|---|---|---|---|
| **A0 版本锁定** | 游戏/注入链/适配器 | 记录 `game_version`、`build_id`、`deck`、`stake`、`lovely_version`、`smods_version`、`balatrobot_version`；同一批实验不跨版本 | `scenarios/v3/MANIFEST.json` |
| **A1 状态/动作 schema** | `gamestate` ↔ `GameState` | 手牌、牌堆计数、Joker 列表、盲注、目标分、剩余出牌/弃牌、阶段可一一映射；动作绑定稳定卡牌 id，并保留下标快照 | `tests/test_realgame_schema.py` + 逐字段 diff 报告 |
| **A2 单步分数** | 引擎 `score_hand` ↔ 真游戏单手得分 | 对同一局面、同一出牌，`engine_score == real_score`；不一致必须追到根因或把该局面排除 | `docs/engine-fidelity.md` A 表（真游戏捕获）+ B 表（`save`/`load` 反事实回放）；第三方抽检见附录 D（辅助） |
| **A3 规则子集** | 计分/牌型/计分牌筛选/Joker/盲注/资源 | 已实现规则与 vanilla 1.0.1o 一致；未实现规则在 `RULES_VERSION.excluded` 明列，且不出现在训练集中 | `scenarios/RULES_VERSION` + 规则金样测试 |
| **A4 场景来源与回放** | 训练/开发集 | 每个局面有 `origin`（real_capture / real_counterfactual）、真游戏 `capture_id`、验证过的动作与分数；无证据的局面不得入集 | `scenarios/v3/*.jsonl` 的 `validation` 字段 + `evidence/W3/` |

### 3.1 对齐等级（用于报告措辞）

| 等级 | 含义 | 可以写 | 不可以写 |
|---|---|---|---|
| **L0 未对齐** | 当前 W2 引擎（自定义公式、合成 Joker） | “自定义子集内自洽” | “与真游戏一致” |
| **L1 分数对齐** | A2 在覆盖局面上 100% 一致 | “覆盖局面上单步分数与真游戏一致（n=…）” | “完整规则一致” |
| **L2 规则子集对齐** | A2+A3 全部通过 | “实现规则是 vanilla 的严格子集” | “复刻了全部 150 个 Joker” |
| **L3 终验通过** | 真实游戏终验完成且结果可复现 | “在真实游戏上完成 n 局终验” | “真实环境 SOTA / 统计显著” |

> 当前实际等级：**L0**。W3 目标：**L2**；W5 目标：**L3**（小样本终验）。

## 4. 真实游戏适配器（balatrobot）

### 4.1 运行栈与版本

| 层 | 作用 | 许可 | 本项目用法 |
|---|---|---|---|
| Balatro（Steam 正版） | 真游戏本体 | 商业软件 | 只在本机运行，**不把游戏文件/素材放进仓库** |
| Lovely（`lovely-injector`） | Lua 运行时注入 | MIT | 运行前置；记录版本 |
| Steamodded（`smods`） | mod 框架 | GPL-3.0 | 运行前置；**不复制/不分发其代码** |
| `coder/balatrobot` | JSON-RPC 2.0 控制面 | MIT | 适配器调用；**不修改其源码** |

**版本基线**：Balatro `1.0.1o`（Wiki 对齐版本）为记录基线；Lovely / Steamodded / balatrobot 以安装当日 release 为准，写入 `scenarios/v3/MANIFEST.json`。游戏更新导致断链时，**不追新**，先锁定旧版本或重跑对齐。

### 4.2 用到的 API（22 个方法中的最小集）

| 方法 | 用途 | 备注 |
|---|---|---|
| `health` | 健康检查 | 启动/重连 |
| `rpc.discover` | 拉 OpenRPC schema | 校验方法名/参数，避免硬编码过时 |
| `gamestate` | 读完整状态 | 字段见 §4.3 |
| `start` | 新局：`{deck, stake, seed}` | 终验/捕获用固定 deck+stake；seed 只保证真游戏内可复现，**不承诺与自建引擎同局面** |
| `save` / `load` | 保存/载入当前局 | **对齐关键**：在决策点存档，用于反事实变体回放 |
| `select` / `skip` | 选/跳盲注 | 终验用 |
| `play` / `discard` | 出牌/弃牌（手牌下标） | 适配器转稳定 id |
| `cash_out` / `next_round` | 结算/离开商店 | 终验用 |
| `buy` / `pack` / `sell` / `reroll` / `use` | 商店/消耗牌 | 终验用；训练集只记录，不用引擎模拟 |
| `add` / `set` | 调试钩子 | **只用于环境自检，不用于构造训练集主数据**（避免“用调试器造局面”削弱外部效度） |
| `screenshot` | 证据截图 | 终验失败时留证 |

> 动作参数是**手牌下标**（`play{cards:[0,2,4]}`），不是卡牌 id；适配器必须在调用前用当前 `gamestate` 把稳定 id 映射为下标，并在 JSONL 里同时记录 `card_ids` 与 `hand_indices`。下标不能作为回放主键。

### 4.3 状态映射（`gamestate` → `GameState`）

| balatrobot | 自建引擎 | 映射规则 |
|---|---|---|
| `state` | `phase` | `SELECTING_HAND`→`play`；`SHOP`→`shop`；`GAME_OVER`→`done`；其余阶段在训练集中不进入 oracle |
| `round.hands_left` / `round.discards_left` | `hands_left` / `discards_left` | 直接映射 |
| `round.chips` | `total_score` | 当前盲注已得分 |
| `blinds.current.score` | `target` | 当前盲注目标分 |
| `hand.cards[]` | `hand` | `value.suit` H/D/C/S→0/1/2/3；`value.rank` 2–9/T/J/Q/K/A→2–10/11/12/13/1；`id` 作为稳定卡牌 id |
| `jokers.cards[]` | `jokers` | 只接受 vanilla 具名 Joker；`modifier` 非空（edition/seal/enhancement）→ 该局面标记 `unsupported`，不入训练集 |
| `cards.count` | `len(deck)` | 只取计数；训练集不要求牌序一致 |
| `deck` / `stake` / `seed` | 元数据 | 写入场景 header |

**不支持即排除**：Boss 负面效果、消耗牌、补充包、增强/版本/印章、金钱与利息、商店 reroll 策略等，在引擎侧不实现；含这些要素的局面只能作为“真游戏记录”进入终验 trace，不进入引擎 oracle 训练集。

### 4.4 捕获/回放/验证流水线

```
[捕获] start(deck,stake,seed) → select → 循环:
          gamestate → 记录状态 → save(path) → play/discard → 记录动作与得分
[建集] 从捕获中选 30 个决策点 → 生成稳定 id + 合法动作集
[变体] load(save) → 执行不同动作 → 记录真游戏得分/下一状态
[验证] 引擎重放同一动作 → 比对 score/hand/deck_count/资源
[入集] 通过 A1–A4 → scenarios/v3/*.jsonl；否则标记 rejected 并写原因
```

**关键点**：`save`/`load` 让“自建变体”也能在真游戏中执行；不依赖 RNG 复刻。`add`/`set` 只用于自检（例如临时加 Joker 验证语义），不作为训练集主数据来源。

## 5. 自建训练/开发集（ATS，Aligned Training Set）

> 名称说明：本项目**不训练/微调模型**（非目标不变）。“训练集”指 Agent 开发、提示词调试与轻量评测用的**对齐场景集**，不是 ML 训练语料。

### 5.1 组成（60 个决策点）

| 类别 | 数量 | 来源 | 说明 |
|---|---:|---|---|
| **R 类：真游戏锚点** | 30 | `real_capture` | 从真游戏 Ante 1（白注、固定牌组）捕获；覆盖无 Joker / 单 Joker / 双 Joker / 含 xMult / 多弃牌 |
| **C 类：真游戏反事实变体** | 30 | `real_counterfactual` | 在锚点局面 `load` 后执行不同合法动作，真游戏实测得分后入集；覆盖“同一局面、不同选择”的 oracle 对照 |
| 合计 | 60 | — | 与旧计划 60 场景规模一致；不再由引擎“生成后直接入集” |

分层仍保留 L1/L2/L3/L4 标签，但**语义改为“决策难度”而不是“引擎合成难度”**：

| 层 | 数量 | 构造 |
|---|---:|---|
| L1 基础 | 20 | 无 Joker、标准牌型、单步 play |
| L2 组合 | 20 | 1–2 个 vanilla Joker，含 +Chips/+Mult/xMult 顺序 |
| L3 长程 | 15 | 同一盲注内多次 play/discard（从真游戏捕获的连续决策点） |
| L4 极限 | 5 | 高目标/必须搏牌型；仍以真游戏可回放为前提 |

### 5.2 场景 Schema（v3）

在旧 Schema 上增加“来源与验证”字段；`oracle` 必须区分是否全动作验证。

```jsonc
{
  "scenario_id": "L2-0007",
  "schema_version": 3,
  "origin": "real_capture",              // real_capture | real_counterfactual
  "game": {
    "version": "1.0.1o",
    "build_id": "...",
    "deck": "RED",
    "stake": "WHITE",
    "seed": "ABC123",
    "capture_id": "cap-20261120-001",
    "saved_state": "data/realgame/saves/cap-...-step03.jkr"
  },
  "initial_state": { /* GameState 投影 */ },
  "available_actions": ["play:c3h,c7s", "discard:c5d"],
  "oracle": {
    "best_actions": ["play:c3h,c7s"],
    "best_score": 68,
    "exact": true,                        // true 仅当所有合法动作都在真游戏验证过
    "validated_actions": 218,             // 真游戏实际执行并记录的动作数
    "unvalidated_actions": 0
  },
  "validation": {
    "engine_score_equals_real": true,
    "legal_actions_match": true,
    "state_transition_match": true,
    "evidence": "evidence/W3/align/L2-0007.json"
  },
  "tags": {"decision_depth": 1, "branch_count": 218, "horizon_need": 0},
  "metadata": {"rules_version": "3.0-vanilla-subset", "notes": "..."}
}
```

**Oracle 精确性规则**：

- `exact: true`：该局面 218 个合法动作全部在真游戏回放并记录得分（成本高，只做少量，如 6 个 L1 局面）。
- `exact: false`：只验证 top-k（k=3）+ 2 个随机动作；`best_actions` 是“已验证动作中的最优”，报告必须写“oracle 为已验证子集最优，不是全局最优”。
- `best_score == 0` 的局面不进入 regret 分母，单独计数。

### 5.3 入集门槛（缺一不可）

- [ ] G1 版本/来源完整（A0）；
- [ ] G2 状态字段可映射（A1）；
- [ ] G3 至少一个动作的真游戏分数与引擎分数一致（A2；全动作一致才可标 `exact`）；
- [ ] G4 合法动作集一致（A1/A3）；
- [ ] G5 状态转移的覆盖字段一致（分数、手牌、剩余出牌/弃牌；牌堆只比计数）；
- [ ] G6 证据文件存在且可重放（`evidence/W3/align/<scenario_id>.json`）。

不满足任一项 → `rejected` 清单 + 原因，**不得**用“先入集、以后补验证”的方式绕过。

### 5.4 禁止事项

- ❌ 用 `add`/`set` 构造“真游戏从未出现”的局面后直接当锚点；
- ❌ 只用引擎生成、未在真游戏回放过的局面；
- ❌ 把 `exact: false` 的 oracle 写成“全局最优”；
- ❌ 把不同游戏版本/不同牌组/不同赌注的捕获混在同一批；
- ❌ 在训练集里保留未实现的规则要素（Boss 效果、消耗牌、增强牌等）。

## 6. 真实游戏终验协议（RGFT）

### 6.1 规模与预算（小样本，描述性）

| 项 | 值 | 理由 |
|---|---:|---|
| 配置组 | 3 组（A 本地直答 / B 本地 CoT / C 云端 CoT） | 与主实验一致，便于对比 |
| 每组局数 | 4 局 | 单局 5–15 分钟；总 12 局是本机时间上限 |
| 单局范围 | Ante 1 三盲注（Small/Big/Boss） | 完整走完一个 Ante；不做 Ante 12 长局 |
| 单局上限 | 15 分钟或 3 盲注结束 | 超时记 `timeout`，不剔除，单列 |
| 总预算 | 约 4–6h（含重连/失败重跑） | 含 setup 另计 3–5h（W3） |
| 统计口径 | 描述统计 + bootstrap 95% CI；**不做显著性主张** | n=12，统计功效不足 |

### 6.2 工具集（真实环境 5 个）

训练环境 4 个工具不变；真实环境用 `shop_action` 取代训练环境的 `choose_joker`，并多一个 `advance_phase`（选盲/结算/商店阶段推进），总数仍为 5：

| 工具 | 作用 | 对应 balatrobot |
|---|---|---|
| `get_state` | 读紧凑状态 | `gamestate` |
| `play_cards` | 出牌（稳定 id → 下标） | `play` |
| `discard_cards` | 弃牌 | `discard` |
| `shop_action` | 买/卖/reroll/开包/用消耗牌（终验允许的最小集） | `buy`/`sell`/`reroll`/`pack`/`use` |
| `advance_phase` | 选盲/跳过/结算/下一轮/回菜单 | `select`/`skip`/`cash_out`/`next_round`/`menu` |

> 工具 schema ≤ 1200 token；每个工具声明 `required_state` 与统一错误码（`BAD_REQUEST` / `INVALID_STATE` / `NOT_ALLOWED` / `TIMEOUT` / `ADAPTER_ERROR`）。训练环境仍用 4 工具；两套工具的**动作语义**必须一致（同一 `card_ids` 编码）。

### 6.3 终验指标

| 指标 | 定义 | 精确性 | 备注 |
|---|---|---|---|
| `blinds_cleared` | 通过的盲注数 / 3 | exact | 主进度 |
| `ante1_win` | 是否打完 Ante 1 | exact | 二值 |
| `legality_rate` | 合法工具调用 / 总调用 | exact | 适配器统计 |
| `timeout_rate` | 超时局数 / 12 | exact | 基础设施指标 |
| `first_failure_step` | 首次 regret≥0.5 的决策步 | exact（需 oracle） | 仅对 play/discard 决策；商店决策单独记 |
| `agent_failure_class` | F1–F4 + F0 | exact/heuristic | 见 `04-失败归因器.md` |
| `env_divergence` | 真游戏结果与训练环境预期不一致的次数 | exact | **非 Agent 失败**，单列 |
| `real_vs_training_gap` | 同一模型在训练集 regret 与终验表现的方向性差异 | 描述性 | 样本少，只描述不检验 |
| `cost` | token/局、秒/局、$ /局 | exact | 终验成本必须报 |

### 6.4 终验验收

- [ ] 12 局全部有完整 trace（状态/动作/得分/截图或等价证据），无“只记结果”；
- [ ] 至少 9 局走到 Ante 1 结束（3 局以内失败/超时可接受并单列）；
- [ ] `legality_rate`、`timeout_rate`、`env_divergence` 三项齐全；
- [ ] 每条失败有 F1–F4/F0 标签或 `insufficient_evidence`；
- [ ] 报告写明 n=12、单局范围、版本链、不可复现风险；
- [ ] **未达成时**如实写“真实游戏终验未完成”，不得用训练集结果替代。

### 6.5 降级方案（不可用时）

若本机无法安装/运行真游戏（无正版、版本链断裂、图形环境不可用）：

1. **不得**把终验标为通过；
2. 退回“真游戏捕获回放验证”（只做 A2/A4，不做 Agent 终验），报告写 `fidelity_status: CAPTURE_REPLAY_ONLY`；
3. 训练集仍必须来自真游戏捕获，不得退回纯引擎生成；
4. 在 README、报告、简历中明确写“真实游戏终验未执行（环境不可达）”。

## 7. 规则对齐改造清单（W3 执行）

> 当前 W2 引擎（提交 `c65fb9b`）是 **L0**：自定义计分公式 + 合成 Joker + 3 Joker 槽位 + 300/800/2000 目标 + 4 手/2 弃。以下改造完成后才可称 **L2**。

### 7.1 计分

| 项 | W2 现状 | v3.0 目标（vanilla 1.0.1o，等级 1） |
|---|---|---|
| 牌型基础 Chips×Mult | 无基础 Chips；自定义倍率表 | High Card 5×1 / Pair 10×2 / Two Pair 20×2 / Three of a Kind 30×3 / Straight 30×4 / Flush 35×4 / Full House 40×4 / Four of a Kind 60×7 / Straight Flush 100×8 |
| 计分牌筛选 | 打出的每张牌都计点数码 | 只计参与牌型的牌：高牌只计最高 1 张；对子 2 张；两对 4 张；三条 3 张；顺子/同花/葫芦/同花顺 5 张；四条 4 张 |
| 牌面 Chips | A=11, J/Q/K=10, 其余=面值 | 同左（vanilla 基础值） |
| 取整 | 末尾 `floor` 一次 | 同左；中间不取整 |
| 等级 | 无 | 固定等级 1；不实现 Planet（排除） |

### 7.4 允许的简化（必须写入 `RULES_VERSION.excluded`）

- Boss 盲注负面效果（只记录，不模拟）；
- 金钱/利息/商店价格/reroll/补充包/消耗牌；
- 卡牌增强、版本、印章、稀有度、负片；
- 跳盲、标签、凭证、牌组解锁；
- 手牌等级 >1、Planet 牌；
- 150 个 Joker 中未实现的 142 个；
- 多牌组、多赌注（只做 Red Deck + White Stake）。

> 简化原则：**简化只能“少做”，不能“做错”**。已实现的规则必须与真游戏逐位一致；未实现的规则必须在场景层面排除。

- [ ] 8 个 vanilla Joker 的数值/条件有来源链接与金样测试；
- [ ] 9 种牌型的基础 Chips×Mult、计分牌筛选有金样测试；
- [ ] 至少 30 个真游戏捕获局面通过 A1–A4，进入 ATS；
- [ ] 至少 30 个反事实变体通过真游戏 `save`/`load` 回放；

## 9. 成本、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 安装四层依赖 3–5h，版本链脆弱 | W3 延期 | 版本锁定；先跑 `health`/`gamestate` 冒烟；失败即降级到“捕获回放”，不硬撑 |
| 真游戏单局 5–15 分钟，不可并行 | 终验样本少 | 只跑 12 局；训练集用捕获+回放，不靠真游戏批量 |
| 图形界面依赖、无头不可用 | CI 不可行 | 真游戏只在本机跑；CI 只跑训练环境与离线校验 |
| `save`/`load` 版本兼容性 | 变体回放失败 | 每局记录版本；失败局进入 `rejected`，不硬凑 |
| 真游戏与引擎状态字段漂移 | 对齐误判 | 只映射白名单字段；新增字段先写 diff 报告 |
| 小样本终验被误读为“显著” | 结论夸大 | 预注册写“描述统计”；报告限制章单列 n=12 |
| 游戏更新导致断链 | 复现失败 | 锁定版本；记录 build；不自动更新 |
| 版权/许可污染 | 仓库不可分发 | L7/L8/L9；只提交脱敏 JSON 与代码 |
