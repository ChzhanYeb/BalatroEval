## 1. 设计原则

| 原则 | 说明 |
|---|---|
| **确定性优先** | 能用状态差分/字符串比对判定的，绝不交给 LLM |
| **区分精确与启发式** | 每类标注 `exact` 或 `heuristic`；heuristic 类不下强结论 |
| **判定优先级（v2.1/v3.0）** | 一条 trace 命中多类时，按 `illegal > miscalculation > rule_hallucination > planning_shortfall > env_divergence` 定 primary，其余入 secondary；**冲突率必须上报**。`env_divergence` 优先级**最低**：只有排除 Agent 侧错误后才归到环境 |
| **多标签 + 主次因** | 允许一条 trace 命中多类，记录 primary + secondary |
| **P0 规则** | **Agent 失败率的分母只含 Agent 决策错误**（F1–F4 + F0）；E1 单独统计、单独报告，不得混入 |
| **证据链** | 每个判定必须能回放到具体 step 与原文，并附**最小反例**与**受影响后续步**（v2.1） |
| **允许“证据不足”** | 判不了就标 `insufficient_evidence`，不硬塞；低置信样本进入**弃权队列**转人工复核（v2.1） |

**LLM 只能做解释**（把判定结果转成一段自然语言），**不能做判定**。这条在 v2.1 里加了一句依据：现有最强自动归因方法在步级只有 14.2%（Who&When）、通用轨迹上模型定位只有 11%（TRAIL），因此把判定权交给模型等于把可靠性交给一个已知不可靠的环节。

### 1.1 分类语义（v4.0）

> 口径来源：[README](../../README.md)「v3.0 / v4.0 改了什么」⑥、[AGENTS.md](../../AGENTS.md) §4「诊断报告层（v4.0）」与 [03](03-评测集与指标.md) §3。

| 类别 | 语义归属 | 一句话定义 | 精确性 | 统计归属 |
|---|---|---|---|---|
| **F1 / F2 / F3** | **合规 / 规则理解诊断** | 协议与工具调用（F1 非法动作）、分数计算（F2 算分错误）、规则与 Joker 引用（F3 规则幻觉）——都是“读懂规则并按协议操作”的诊断 | exact | 计入 Agent 失败率 |
| **F4 `planning_shortfall`** | **规划诊断（heuristic）** | 选择显著次优动作且与“只看即时收益”一致；只能作分组标记，**不是因果结论** | **heuristic** | 计入 Agent 失败率，但**不进任何显著性检验** |
| **F0 `insufficient_evidence`** | **证据不足** | 未命中任何规则，或证据不足以归类（含低置信弃权） | — | 计入分母；不归入 F1–F4 |
| **E1 `env_divergence`** | **数据质量门禁** | 真游戏与训练环境预期不一致且已排除 Agent 错误——回答“环境是否按预期工作”，**不是 Agent 失败类** | exact | **不进 Agent 失败率 / regret**，单独统计、单独成表 |

- **失败归因不是第一创新点，也不是主产品**：项目主定位是**面向大模型 Agent 的长线规划测试集**（跨回合资源分配、多步决策、长期构建、失败恢复）；本模块只作为**诊断报告层 / 题目元数据 / 错误分析章节**，用于解释分数与定位错误。
- 由此推出报告纪律：失败分布属于“错误分析”的一节，**不是主结果**；主结果是指标表（见 03 §3 的五层结构），其中 ③ 跨期资源分配层与 ④ 长程进度/失败恢复层**当前均未覆盖**（W3 候选），失败归因不能替它们承担能力结论。

## 2. 4 类 Agent 失败 + 兜底 + 1 类环境分歧（v3.0）

| ID | 类别 | 精确性 | 优先级 | 一句话定义 |
|---|---|---|---|---|
| **F1** | `illegal_action` 协议/合法性错误 | exact | 1（最高） | 工具调用参数非法、工具不存在、调用被环境拒绝 |
| **F2** | `miscalculation` 计算错误 | exact | 2 | Agent 明确声称的分数与环境真实得分不一致 |
| **F3** | `rule_hallucination` 规则幻觉 | exact | 3 | 引用了不存在的 Joker / 牌型 / 规则 |
| **F4** | `planning_shortfall` 规划不足 | **heuristic** | 4 | 选择了显著次优动作，且其选择与“只看即时收益”一致 |
| **F0** | `insufficient_evidence` | — | — | 未命中任何规则，或证据不足以归类（含低置信弃权） |
| **E1** | `env_divergence` 环境分歧（**非 Agent 失败**） | exact | **5（最低）** | 真游戏的结果/状态转移与训练环境预期不一致，且已排除 Agent 动作错误；根因在引擎/适配器/版本链 |

> 从原来的 5 类减到 4 类 Agent 失败：删掉“状态遗忘”（本环境状态一直显式可见，难以构造可判定探针），并入“证据不足”或后续版本。
> **E1 不是 Agent 失败**：它回答“环境是否按预期工作”。报告必须分两张表：Agent 失败分布（F1–F4 + F0）与环境分歧（E1），**不得把 E1 计入 Agent 失败率/regret**。
> 各类的语义归属（F1–F3 合规/规则理解诊断、F4 规划诊断、F0 证据不足、E1 数据质量门禁）见 §1.1。

### 2.1 E1 `env_divergence` 判定边界（v3.0 新增）

**触发条件**（全部满足才记 E1）：

1. 同一局面、同一动作，真游戏记录的结果与训练环境重放的结果**不一致**（分数、手牌、剩余出牌/弃牌、阶段之一）；
2. 该动作在真游戏侧被接受（不是 F1 非法），且 Agent 的声称分与**真游戏**实际分一致（不是 F2）；
3. 差异可归因到环境侧：引擎规则未覆盖/实现错误、适配器字段映射错误、版本链不一致（A0/A1/A2/A3 任一未过）；
4. 已按 A2 追根因或把该局面标 `rejected`；不得只标 E1 而不处理。

**记录字段**：`expected`（训练环境值）、`observed`（真游戏值）、`divergence_type`（`score` / `state_transition` / `legal_actions` / `schema` / `version`）、`alignment_level`（A0–A3 哪一级失败）、`capture_id`、`state_hash`。

**不触发 E1 的情形**：Agent 选错动作（F4）、Agent 声称分数错误（F2）、超时/断连（基础设施，单列 `infra`）、样本不足判不了（F0）。

## 3. 判定规则（每条有 rule_id）

### F1 `illegal_action` / rule_id `LEGAL_001`

```python
def detect_illegal(ep) -> list[Hit]:
    hits = []
    for step in ep.steps:
        if step.tool_result.get("isError"):
            hits.append(Hit(step, "F1", "LEGAL_001",
                            evidence={"error": step.tool_result.get("error"),
                                      "args": step.args}))
        if step.tool_name not in ALLOWED_TOOLS:      # 幻觉工具
            hits.append(Hit(step, "F1", "LEGAL_002",
                            evidence={"tool": step.tool_name}))
    return hits
```

**来源**：trace 的 `tool/result.isError` + 工具白名单。**零推断**。

### F2 `miscalculation` / `MATH_001`

```python
SCORE_RE = r"(?:得分|分数|score)\D{0,6}(\d+)"

def detect_miscalc(ep) -> list[Hit]:
    hits = []
    for step in ep.steps:
        claimed = extract_int(step.assistant_text, SCORE_RE)
        actual = step.score_delta          # 环境真实得分
        if claimed is not None and claimed != actual:
            hits.append(Hit(step, "F2", "MATH_001",
                            evidence={"claimed": claimed, "actual": actual,
                                      "quote": snippet(step.assistant_text)}))
    return hits
```

**注意**：Agent 未声称分数 → 返回空（**不能默认它算错**）。

### F3 `rule_hallucination` / `RULE_001` `RULE_002`

```python
def detect_hallucination(ep) -> list[Hit]:
    hits = []
    for step in ep.steps:
        mentioned = extract_joker_names(step.assistant_text)   # 用 joker 名称表匹配
        owned = {j.jid for j in step.state_before.jokers}
        ghosts = mentioned - owned - KNOWN_JOKERS              # 既没拥有、也不存在
        if ghosts:
            hits.append(Hit(step, "F3", "RULE_001",
                            evidence={"ghost_jokers": sorted(ghosts)}))
        if mentions_nonexistent_hand_type(step.assistant_text): # 如"五条"
            hits.append(Hit(step, "F3", "RULE_002",
                            evidence={"quote": snippet(step.assistant_text)}))
    return hits
```

**依赖**：Joker 名称表 + 牌型词典（都来自 `bench/` 的规则实现，不另建）。**v3.0**：Joker 名称表换成 8 个 vanilla 具名（Joker / Jolly / Zany / Sly / Wily / Half / The Duo / The Trio，见 02 §0.3），合成夹具名称不得出现在判定词典里。

### F4 `planning_shortfall` / `PLAN_001`（**启发式，必须标注**）

```python
def detect_myopia(ep, threshold=0.5) -> list[Hit]:
    hits = []
    for step in ep.steps:
        if step.decision_type != "play":     # 只在多回合场景适用
            continue
        if ep.n_remaining_decisions < 2:     # 单回合无"未来"
            continue
        regret = step.regret                 # (best - actual)/best
        if regret >= threshold:
            hits.append(Hit(step, "F4", "PLAN_001",
                            evidence={"regret": regret,
                                      "chosen": step.action,
                                      "best": step.oracle_best},
                            confidence="heuristic"))
    return hits
```

**这是启发式**：高 regret 只说明"这步不好"，不能证明"因为短视"。报告中必须写：
> "F4 是**启发式标记**，用于分组统计，不作为因果结论。"

**为什么不做真正的短视判定**：需要"选即时最优 vs 选全局最优"的对比实验设计（例如强制两组策略），成本超出预算。列为 Roadmap。

### E1 `env_divergence` / `ENV_001`（**非 Agent 失败，v3.0 新增**）

```python
def detect_env_divergence(ep) -> list[Hit]:
    hits = []
    for step in ep.steps:
        # 只比较 play/discard 决策；商店/阶段推进不在训练环境复算
        if step.decision_type not in ("play", "discard"):
            continue
        real = step.real_result          # 真游戏记录（终验/捕获）
        sim = step.sim_result            # 引擎重放同一动作
        if real is None or sim is None:
            continue
        for field in ("score_delta", "hands_left", "discards_left", "phase"):
            if real[field] != sim[field]:
                hits.append(Hit(step, "E1", "ENV_001",
                                evidence={"field": field,
                                          "expected": sim[field],
                                          "observed": real[field],
                                          "capture_id": step.capture_id,
                                          "state_hash": step.state_hash},
                                confidence="exact"))
                break
    return hits
```

**判定顺序强制**：先跑 F1/F2/F3/F4；若某步已命中 Agent 类失败，则该步**不再**标 E1（避免把 Agent 错算成环境错）。E1 只在“真游戏接受动作、Agent 声称与真游戏一致、但引擎重放不一致”时成立。

**报告要求**：E1 单独一张表（按 `divergence_type` / `alignment_level` 分组），并写清“该 E1 是否导致对应场景被 rejected”；**不得**把 E1 折算成 Agent regret 损失。

## 4. 输出 Schema（v3.0 增补 scope / environment）

```jsonc
{
  "episode_id": "w5-A-L2-0007",
  "scenario_id": "L2-0007",
  "model": "qwen3-4b-q4",
  "scope": "training",                // v3.0：training | real_game（终验 trace 用 real_game）
  "step_id": 3,
  "primary_failure": "miscalculation",
  "secondary_failures": ["planning_shortfall"],
  "priority": 2,                      // v2.1：判定优先级（1 最高；E1 为 5）
  "confidence": "exact",              // exact | heuristic | low
  "abstain": false,                   // v2.1：低置信弃权标记，true 时进人工复核队列
  "rule_id": "MATH_001",
  "evidence": {
    "claimed": 120,
    "actual": 68,
    "quote": "这手两对能拿 120 分",
    "state_hash": "a1b2c3",
    "capture_id": null                // v3.0：real_game 时必填
  },
  "counterfactual": {                 // v2.1：最小反例
    "best_action": "play:c3h,c7s",
    "best_score": 68,
    "delta_if_best": 0.0              // 若改成最优动作，已发生分数不变、后续 regret 变化量
  },
  "affected_steps": [4, 5],           // v2.1：该错误影响到的后续决策步
  "impact": { "regret": 0.42 },       // v3.0：E1 不写 regret，写 null
  "environment": {                    // v3.0：仅 E1 或 real_game 时填写
    "expected": { "score_delta": 68 },
    "observed": { "score_delta": 72 },
    "divergence_type": "score",       // score | state_transition | legal_actions | schema | version
    "alignment_level": "A2"
  },
  "judge_version": "attrib-1.0",      // v2.1：判定器版本，便于回溯
  "explanation": null                 // 可选，由 LLM 事后生成，不参与判定
}
```

**`scope`（v3.0）**：训练环境 trace 记 `training`；真游戏终验 trace 记 `real_game`。报告与失败率统计按 `scope` 分开，**不得**把两套环境的 F 类标签合并成一个失败率。

**`state_hash`** 用于把归因结果回链到 `episode.jsonl` 的具体状态，保证可重放。

**`counterfactual`（v2.1 最小反例）**：对每个被判定为失败/次优的决策步，用 oracle 的最优动作做一次对照——"若这一步改选最优，后续会怎样"。它回答的是"这个错误到底值多少分"，而不只是"这个错误属于哪一类"。实现上不需要重新跑 LLM，只需用记录的轨迹做一次**确定性重放**（见 02 §5 与 03 §5）。

**`affected_steps`（v2.1 传播路径）**：错误不会只停在发生的那一步，因此对 F1–F3 额外记录"该错误之后、哪些步的 regret 因此变大"（用重放对照得到）。这直接对应失败归因研究里"错误传播"的视角。

## 5. Trace 解析与对齐

| 步 | 做法 | 注意 |
|---|---|---|
| 1 | 找 `%USERPROFILE%\.dsh\session-*.jsonl.zstd` | 默认 zstd 压缩，需解帧 |
| 2 | 逐行解析事件：`turn/*`、`step/*`、`assistant/message`、`tool/call`、`tool/result` | 行尾 `\r` 要 strip |
| 3 | 抽决策序列：每个 `tool/call` 对应一次决策 | 参数在 `tool/call`，结果在 `tool/result` |
| 4 | 与 `episode.jsonl` 的 `step_index` 对齐 | 两边索引基数要统一（都从 0 开始） |
| 5 | 对齐率统计 | <95% 先修对齐，不要谈归因 |

**对齐失败的两个常见原因**：①索引从 0/1 不一致；②Agent 一次消息里并行发多个工具调用（需按顺序展开）。

**v2.1 定位原则（v3.0 更新）**：归因的“定位”不靠模型猜，靠**确定性重放**——用 `trace_id / step_index / state_hash / action` 把该步还原到环境里；训练环境用“同一动作序列重放到该步”，真游戏用 `save`/`load` 回放（不再说“同一 seed”，D13 已改为 captured-state alignment）。这样“哪一步错了”从生成任务变成查询任务，而查询是可复现的。

### 5.1 真游戏 trace 对齐（v3.0 新增，📋）

| 步 | 做法 | 注意 |
|---|---|---|
| 1 | 终验 trace 与真游戏记录按 `capture_id + step` 对齐（终验从固定 `start(deck,stake,seed)` 新开一局，逐决策落 `gamestate` 快照） | seed 只保证真游戏内可复现，不承诺与训练环境同局面 |
| 2 | 用 `state_hash`（白名单字段规范化后哈希）把 trace 步回链到 `gamestate` 快照 | 哈希算法与字段白名单写进 `scenarios/v3/MANIFEST.json`；手牌顺序/计数、资源、目标分必须进哈希 |
| 3 | 反事实回放：决策点 `save` → `load` → 执行 oracle 最优动作与 Agent 动作，记录真游戏分数与下一状态 | 用于最小反例（`counterfactual`）与 F4；同一存档可反复 `load` |
| 4 | 环境分歧判定：引擎重放同一 action，逐字段比对（见 §3 E1） | 先排除 F1–F4 再判 E1 |
| 5 | 三方对齐率：`trace step ↔ gamestate ↔ episode.jsonl`，≥95% 才进入归因 | 低于阈值先修对齐，不谈归因 |

**注意（v3.0）**：真游戏的动作参数是**手牌下标**，必须先用当前 `gamestate` 映射回稳定卡牌 id 再写 trace（07 §4.2）；真游戏阶段多于训练环境（选盲 / 商店 / 结算），F1–F4 只对 `SELECTING_HAND` 内的 play/discard 决策判定，其余阶段单列 `phase_skipped`，不硬塞进 4 类。

## 6. 人工标注与一致性检验

### 抽样方案（v3.0：30 → 24 降级档）

| 项 | 方案 |
|---|---|
| 样本 | 从 **90 个训练集 episode**（3 组 × 30 场景）中分层抽 **24 条**（3 组 × 4 层，尽量均衡；原 v2.2 的 30 条已按 W4 预算压到 24）；**降级档 18 条**（每类 ≥3），降级必须在报告写明 |
| 另抽 | 真游戏终验 12 局 trace 全量纳入归因（不抽样，但只做描述统计） |
| 标注者 | 本人（首选找一位同学做双人）；做不到则做 **intra-rater**（隔 3 天重标一次） |
| 标注内容 | 每条只标 primary_failure 一类（多标签会增加分歧）；E1 单独标注，不计入 Agent 失败 |
| 工具 | 一张 24 行（降级档 18 行）的 CSV：`episode_id, scope, step_id, 人工标签, 备注` |

### 一致性指标（v2.1 扩展）

```python
from sklearn.metrics import cohen_kappa_score, confusion_matrix

# 总体一致性（不够，仅作参照）
kappa_all = cohen_kappa_score(human, auto)

# v2.1 必须报：per-class κ + 混淆矩阵 + 弃权率
for c in ["F1", "F2", "F3", "F4"]:
    y_h = [1 if x == c else 0 for x in human]      # one-vs-rest
    y_a = [1 if x == c else 0 for x in auto]
    print(c, cohen_kappa_score(y_h, y_a), len([x for x in human if x == c]))

print(confusion_matrix(human, auto, labels=["F1","F2","F3","F4","F0"]))
abstain_rate = len([x for x in auto if x == "F0"]) / len(auto)

# v3.0：E1 不进 Agent 混淆矩阵，单独统计
env_div_rate = len([x for x in scope_real if x == "E1"]) / len(scope_real)
```

| 必须报告的项 | 格式 | 为什么 |
|---|---|---|
| 总体 κ | 点估计 + 95% CI | 与文献可比 |
| **per-class κ**（v2.1） | 每类一个 κ + 该类样本数 | 合并 κ 会掩盖个别类别崩塌 |
| **混淆矩阵**（v2.1） | 5×5（F1–F4 + F0） | 看出"哪两类总被互相错分" |
| **弃权率**（v2.1） | `abstain=true` 占比 + 弃权样本的人工标签分布 | 弃权太多说明判定器不可用；弃权太少说明阈值太松 |
| **判定器冲突率**（v2.1） | 一条 trace 同时命中 ≥2 类的比例 | 冲突率高说明分类学互斥性不足 |
| **E1 计数**（v3.0） | E1 条数 / 真游戏终验 trace 数 + `divergence_type` 分布 | **非 Agent 失败**；单列，不进 Agent κ 与失败率 |

### 诚实报告要求

- **不要为了达到 κ≥0.7 而调标签**。
- 24 条（降级档 18 条）样本的 κ 置信区间很宽（约 ±0.2），报告里要写（数字为示例格式，须以实测替换）：
  > "n=24，总体 κ=0.62（95% CI 约 [0.40, 0.84]），受样本量限制，该一致性仅作方向性参考。"
- **per-class κ 的样本门槛（v2.1）**：某类样本数 <5 时，**不单独报该类 κ**，只报该类计数与混淆矩阵对应行，并在报告中注明"样本不足，无法估计该类一致性"。
- 若判定器某类占比为 0% 或 100%，**先怀疑判定器**，在报告里单列"未检出任一例"而不是断言"该类不会发生"。
- **v3.0**：E1 的 κ 不参与 Agent 一致性报告（它来自环境比对，不是人工-自动标注一致性）；E1 只报计数与 `divergence_type` 分布。

### 分歧处理

分歧条目要逐条看：是"判定器太宽"还是"人工标错"。前者修规则（并重测），后者记入备注。

**图 1（Agent 失败）**：堆叠柱状图，X = 难度层（L1–L4），Y = 失败占比，堆叠 = F1/F2/F3/F4/F0。**E1 不进这张图**。

它要回答：
1. 随难度上升，Agent 失败构成怎么变？（预期：L1 以 F2 为主，L3 以 F4 为主）
2. 不同模型的构成差异？（预期：本地 4B 的 F1/F3 更多，云端 F4 更多）
3. 哪一类占比最高 → 后续优化方向
4. 环境分歧是否影响了终验结论（E1 条数 / 涉及局面，是否已 rejected）

**v2.1 增加一张"失败类型 × 指标损失"表**（回答"该修哪一类"而不只是"哪一类多"）：

| 失败类 | 命中次数 | 折算 regret 损失（均值） | 涉及 episode 数 | 判定精确性 |
|---|---|---|---|---|
| F1 illegal_action | n | 该步 regret 之和 | m | exact |
| F2 miscalculation | n | 同上 | m | exact |
| F3 rule_hallucination | n | 同上 | m | exact |
| F4 planning_shortfall | n | 同上 | m | **heuristic**（只作分组） |
| **E1 env_divergence** | n | **不折算**（写 —） | m | exact（环境比对） |

> 折算方法：每条命中的 `impact.regret` 累加；F4 的损失只用于排序，不进显著性检验。**E1 不折算 Agent regret**，它的影响面单独用“受影响局面数 + 是否触发 rejected”描述。

## 10. 常见坑

1. **判定器太宽**：某类占比 100% 或 0% → 先怀疑判定器，不要急着解释。
2. **把"没声称分数"当算错**：必须返回空。
3. **F4 用在了单回合场景**：无未来，不能判。
4. **对齐错位**：trace 的 step 与环境的 step 不是一回事（一个 turn 可能多 step）；真游戏还有选盲/商店阶段，需先按 `phase` 过滤。
5. **过度依赖 LLM 解释**：解释文字不进任何统计。
6. **（v3.0）把 E1 当 Agent 失败**：环境分歧可能来自引擎/适配器/版本链，混进 Agent 失败率会低估 Agent 能力，也会掩盖对齐问题。
7. **（v3.0）只凭“分数不同”就判 E1**：必须先排除 F2（Agent 声称错误）与 F1（非法动作），并追到 A0–A3 的具体失败级别。
8. **（v3.0）拿训练环境 trace 冒充真游戏 trace**：`scope` 必须如实标注；`real_game` 的步必须有 `capture_id` 与 `gamestate` 快照。
