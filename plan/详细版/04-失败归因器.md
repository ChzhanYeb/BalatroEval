## 1. 设计原则

| 原则 | 说明 |
|---|---|
| **确定性优先** | 能用状态差分/字符串比对判定的，绝不交给 LLM |
| **区分精确与启发式** | 每类标注 `exact` 或 `heuristic`；heuristic 类不下强结论 |
| **判定优先级** | 一条 trace 命中多类时按 `illegal > miscalculation > rule_hallucination > planning_shortfall > env_divergence` 定 primary，其余入 secondary；**冲突率必须上报**。`env_divergence` 优先级**最低**：排除 Agent 侧错误后才归到环境 |
| **多标签 + 主次因** | 允许一条 trace 命中多类，记录 primary + secondary |
| **P0 规则** | **Agent 失败率的分母只含 Agent 决策错误**（F1–F4 + F0）；E1 单独统计、单独报告 |
| **证据链** | 每个判定必须能回放到具体 step 与原文，并附**最小反例**与**受影响后续步** |
| **允许“证据不足”** | 判不了就标 `insufficient_evidence`，不硬塞；低置信样本进**弃权队列**转人工复核 |

**LLM 只能做解释**（把判定结果转成一段自然语言），**不能做判定**：现有最强自动归因方法步级仅 14.2%（Who&When）、通用轨迹上模型定位仅 11%（TRAIL），把判定权交给模型等于把可靠性交给一个已知不可靠的环节。

### 1.1 分类语义

> 口径来源：[README](../../README.md)「定位与当前实现差距」与红线表、[AGENTS.md](../../AGENTS.md) 开头「定位」（失败归因只作诊断报告层）与 [03](03-评测集与指标.md) §3。

| 类别 | 语义归属 | 一句话定义 | 精确性 | 统计归属 |
|---|---|---|---|---|
| **F1 / F2 / F3** | **合规 / 规则理解诊断** | 协议与工具调用（F1 非法动作）、分数计算（F2 算分错误）、规则与 Joker 引用（F3 规则幻觉） | exact | 计入 Agent 失败率 |
| **F4 `planning_shortfall`** | **规划诊断** | 选择显著次优动作且与“只看即时收益”一致；只作分组标记，**不是因果结论** | **heuristic** | 计入分母，但**不进任何显著性检验** |
| **F0 `insufficient_evidence`** | **证据不足** | 未命中任何规则，或证据不足以归类（含低置信弃权） | — | 计入分母；不归入 F1–F4 |
| **E1 `env_divergence`** | **数据质量门禁** | 真游戏与训练环境预期不一致且已排除 Agent 错误——回答“环境是否按预期工作”，**不是 Agent 失败类** | exact | **不进 Agent 失败率 / regret**，单独成表 |

- **失败归因不是第一创新点，也不是主产品**：主结果是指标表（03 §3 五层结构），其中 ③ 跨期资源分配层与 ④ 长程进度/失败恢复层**当前均未覆盖**（W3 候选），归因不能替它们承担能力结论；失败分布只是“错误分析”的一节。

## 2. 4 类 Agent 失败 + 兜底 + 1 类环境分歧

| ID | 类别 | 语义归属 / 统计 | 精确性 | 优先级 | 一句话定义 |
|---|---|---|---|---|---|
| **F1** | `illegal_action` 协议/合法性错误 | 合规诊断；计入失败率 | exact | 1（最高） | 工具调用参数非法、工具不存在、调用被环境拒绝 |
| **F2** | `miscalculation` 计算错误 | 规则理解诊断；计入失败率 | exact | 2 | Agent 明确声称的分数与环境真实得分不一致 |
| **F3** | `rule_hallucination` 规则幻觉 | 规则理解诊断；计入失败率 | exact | 3 | 引用了不存在的 Joker / 牌型 / 规则 |
| **F4** | `planning_shortfall` 规划不足 | 规划诊断；计入分母但**不进显著性检验** | **heuristic** | 4 | 选择了显著次优动作，且其选择与“只看即时收益”一致 |
| **F0** | `insufficient_evidence` | 证据不足；计入分母、不归入 F1–F4 | — | — | 未命中任何规则，或证据不足以归类（含低置信弃权） |
| **E1** | `env_divergence`（**非 Agent 失败**） | 数据质量门禁；**不进失败率/regret** | exact | **5（最低）** | 真游戏结果/状态转移与训练环境预期不一致，且已排除 Agent 动作错误；根因在引擎/适配器/版本链 |

> 从 5 类减到 4 类 Agent 失败：删掉“状态遗忘”（本环境状态始终显式可见，难以构造可判定探针），并入“证据不足”。**E1 不是 Agent 失败**：报告必须分两张表（Agent 失败 F1–F4 + F0 / 环境分歧 E1）。

### 2.1 E1 `env_divergence` 判定边界

**触发条件**（四条全满足）：①同一局面、同一动作，真游戏结果与引擎重放不一致（分数 / 手牌 / 剩余出牌弃牌 / 阶段之一）；②该动作在真游戏侧被接受（非 F1），且 Agent 声称分与**真游戏**实际分一致（非 F2）；③差异可归因到环境侧（规则未覆盖或实现错误、适配器映射错误、A0–A3 任一未过）；④已按 A2 追根因，或把该局面标 `rejected`——不得只标 E1 而不处理。

**记录字段**：`expected`（环境值）/ `observed`（真游戏值）/ `divergence_type`（`score` / `state_transition` / `legal_actions` / `schema` / `version`）/ `alignment_level`（A0–A3 哪一级失败）/ `capture_id` / `state_hash`。

**不触发 E1**：Agent 选错动作（F4）、声称分数错误（F2）、超时断连（基础设施，单列 `infra`）、样本不足（F0）。对齐契约 A0–A4 与降级规则**不在本文重复**，见 07 §3 / §6.5。

## 3. 判定规则（每条有 rule_id）

判定器统一输出 `Hit(step, 类, rule_id, evidence, confidence)`；**零推断**——只读 trace 已有字段与 `bench/` 的规则目录，不调模型、不猜。

### F1 `illegal_action` / `LEGAL_001` `LEGAL_002`

```python
def detect_illegal(ep) -> list[Hit]:
    hits = []
    for s in ep.steps:
        if s.tool_result.get("isError"):        # 环境拒绝 / 参数非法
            hits.append(Hit(s, "F1", "LEGAL_001", evidence={"error": s.tool_result.get("error"), "args": s.args}))
        if s.tool_name not in ALLOWED_TOOLS:    # 工具不存在（幻觉工具）
            hits.append(Hit(s, "F1", "LEGAL_002", evidence={"tool": s.tool_name}))
    return hits
```

**来源**：trace 的 `tool/result.isError` + 工具白名单（`bench/tools.py` 的 5 个工具），不靠语义推断。

### F2 `miscalculation` / `MATH_001`

```python
SCORE_RE = r"(?:得分|分数|score)\D{0,6}(\d+)"
def detect_miscalc(ep) -> list[Hit]:
    out = []
    for s in ep.steps:
        claimed = extract_int(s.assistant_text, SCORE_RE)   # Agent 明确声称的分数
        if claimed is not None and claimed != s.score_delta:
            out.append(Hit(s, "F2", "MATH_001", evidence={"claimed": claimed, "actual": s.score_delta,
                                                          "quote": snippet(s.assistant_text)}))
    return out
```

**注意**：Agent 未声称分数 → 返回空，**不能默认它算错**。

### F3 `rule_hallucination` / `RULE_001` `RULE_002`

```python
def detect_hallucination(ep) -> list[Hit]:
    out = []
    for s in ep.steps:
        mentioned = extract_joker_names(s.assistant_text)    # 用 8 个具名 Joker 名称表匹配
        ghosts = mentioned - {j.jid for j in s.state_before.jokers} - KNOWN_JOKERS
        if ghosts:                                           # 既没拥有、也不在目录里
            out.append(Hit(s, "F3", "RULE_001", evidence={"ghost_jokers": sorted(ghosts)}))
        if mentions_nonexistent_hand_type(s.assistant_text):  # 如“六条”（子集无此牌型）
            out.append(Hit(s, "F3", "RULE_002", evidence={"quote": snippet(s.assistant_text)}))
    return out
```

**依赖（只有 8 个具名 Joker，不许合成夹具名）**：`KNOWN_JOKERS` 直接取自 `bench/jokers.py` 的 `CATALOG_BY_ID`——`joker`（Joker）/ `jolly_joker`（Jolly Joker）/ `zany_joker`（Zany Joker）/ `sly_joker`（Sly Joker）/ `wily_joker`（Wily Joker）/ `half_joker`（Half Joker）/ `the_duo`（The Duo）/ `the_trio`（The Trio）；牌型词典取自 `bench/hand_eval.py`，两者都不另建第二份。

> **禁止**：旧合成夹具名（`jc_*` / `jm_*` / `jx_*`）出现在判定词典、κ 标注或报告里——它们已移出生产目录，只作历史测试构造参考；引用它们等于把“合成测试夹具”误写成“原版 Joker”。**注意**：其余 142 个 Joker 在 `RULES_VERSION.excluded`，Agent 提到它们属于“超出子集范围”而非“不存在”，判定器需另存 `EXCLUDED_JOKERS` 名单把两类分开（否则 F3 过宽，见 §10 坑 1）；该名单 📋 待建。

### F4 `planning_shortfall` / `PLAN_001`（**启发式，必须标注**）

```python
def detect_myopia(ep, threshold=0.5) -> list[Hit]:
    out = []
    for s in ep.steps:
        if s.decision_type != "play" or ep.n_remaining_decisions < 2:
            continue                            # 单回合无“未来”，不判
        if s.regret >= threshold:               # regret = (best - actual) / best
            out.append(Hit(s, "F4", "PLAN_001", confidence="heuristic",
                           evidence={"regret": s.regret, "chosen": s.action, "best": s.oracle_best}))
    return out
```

**这是启发式**：高 regret 只说明“这步不好”，不能证明“因为短视”。报告中必须写：“F4 是**启发式标记**，用于分组统计，不作为因果结论。”**为什么不做真正的短视判定**：需要“选即时最优 vs 选全局最优”的对照实验设计，成本超预算，列为 Roadmap。

### E1 `env_divergence` / `ENV_001`（**非 Agent 失败**）

```python
def detect_env_divergence(ep) -> list[Hit]:
    out = []
    for s in ep.steps:
        if s.decision_type not in ("play", "discard"):
            continue                        # 商店/阶段推进不在训练环境复算
        real, sim = s.real_result, s.sim_result     # 真游戏记录 / 引擎重放
        if real is None or sim is None:
            continue
        for field in ("score_delta", "hands_left", "discards_left", "phase"):
            if real[field] != sim[field]:
                out.append(Hit(s, "E1", "ENV_001", confidence="exact",
                               evidence={"field": field, "expected": sim[field], "observed": real[field],
                                         "capture_id": s.capture_id, "state_hash": s.state_hash}))
                break
    return out
```

**判定顺序强制**：先跑 F1–F4；某步已命中 Agent 类失败，则该步**不再**标 E1（避免把 Agent 错算成环境错）。**报告要求**：E1 单独一张表（按 `divergence_type` / `alignment_level` 分组），写清“是否导致对应场景被 rejected”；**不得**把 E1 折算成 Agent regret。

## 4. 输出 Schema

```jsonc
{
  "episode_id": "w5-A-L2-0007",
  "scenario_id": "L2-0007",
  "model": "qwen3-4b-q4",
  "scope": "training",                // training | real_game（终验 trace 用 real_game）
  "step_id": 3,
  "primary_failure": "miscalculation",
  "secondary_failures": ["planning_shortfall"],
  "priority": 2,                      // 判定优先级（1 最高；E1 为 5）
  "confidence": "exact",              // exact | heuristic | low
  "abstain": false,                   // 低置信弃权标记，true 时进人工复核队列
  "rule_id": "MATH_001",
  "evidence": { "claimed": 120, "actual": 68, "quote": "这手两对能拿 120 分",
                "state_hash": "a1b2c3", "capture_id": null },   // capture_id：real_game 时必填
  "counterfactual": {                 // 最小反例
    "best_action": "play:c3h,c7s", "best_score": 68, "delta_if_best": 0.0 },
  "affected_steps": [4, 5],           // 该错误影响到的后续决策步
  "impact": { "regret": 0.42 },       // E1 不写 regret，写 null
  "environment": {                    // 仅 E1 或 real_game 时填写
    "expected": { "score_delta": 68 }, "observed": { "score_delta": 72 },
    "divergence_type": "score",       // score | state_transition | legal_actions | schema | version
    "alignment_level": "A2" },
  "judge_version": "attrib-1.0",      // 判定器版本，便于回溯
  "explanation": null                 // 可选，由 LLM 事后生成，不参与判定
}
```

**`scope`**：训练环境 trace 记 `training`，真游戏终验 trace 记 `real_game`；报告与失败率按 `scope` 分开统计，**不得**把两套环境的 F 类标签合并成一个失败率。`state_hash` 把归因结果回链到 trace 的具体状态（`evaluation.trace` 从 `start` 起即写），保证可重放。**`counterfactual` / `affected_steps`**：用 oracle 最优动作做一次**确定性重放**对照，回答“这个错误值多少分、影响了哪些后续步”，不重跑 LLM；重放约定见 02 §5 / 03 §5，本文不复述。

## 5. Trace 解析与对齐（📋 `bench/trace.py` 未创建）

**输入是两路可对齐的记录**，不是随手一份日志：①`evaluation/trace.py` 的 JSONL（`schema_version = 2`，含 `start` / `step` / `decision_metric` / `end`、`state_hash`、错误码与延迟；字段见 `docs/implementation/evaluation-execution.md`）；②dsh 会话 trace `%USERPROFILE%\.dsh\session-*.jsonl.zstd`（zstd 解帧后解析 `turn/*`、`step/*`、`assistant/message`、`tool/call`、`tool/result`；行尾 `\r` 需 strip）。

| 步 | 做法 | 注意 |
|---|---|---|
| 1 | 每个 `tool/call` 展开为一次决策，与 trace 的 `step` 按 `step_index` 对齐 | 参数在 `tool/call`、结果在 `tool/result`；两边索引基数统一（都从 0 开始） |
| 2 | 对齐率统计 | **<95% 先修对齐，不要谈归因** |

**对齐失败的两个常见原因**：①索引 0/1 不一致；②Agent 一次消息并行发多个工具调用（需按顺序展开）。**定位原则**：不靠模型猜，靠**确定性重放**——用 `trace_id / step_index / state_hash / action` 把该步还原到环境；训练环境用“同一动作序列重放到该步”，真游戏用 `save`/`load` 回放（D11：captured-state alignment，不再说“同一 seed”）。

**真游戏侧（📋 依赖 07 §4 适配器，尚未接入）**：①按 `capture_id + step` 对齐终验 trace 与真游戏记录（seed 只保证真游戏内可复现，不承诺与训练环境同局面）；②用 `state_hash`（白名单字段规范化后哈希）把 trace 步回链到 `gamestate` 快照，哈希算法与字段白名单写进 `scenarios/v3/MANIFEST.json`；③决策点 `save` → `load` → 分别执行 oracle 最优与 Agent 动作，记真游戏分数与下一状态（服务最小反例与 F4）；④三方对齐率 ≥95% 才进入归因，且真游戏动作参数是**手牌下标**、须先用当前 `gamestate` 映射回稳定卡牌 id（07 §4.2）——F1–F4 只判 `SELECTING_HAND` 内的 play/discard，其余阶段单列 `phase_skipped`。

## 6. 人工标注与一致性检验（📋 待 90 局跑完后执行）

| 项 | 方案 |
|---|---|
| 样本 | 从 **90 个训练集 episode**（3 组 × 30 场景，📋 未跑）中分层抽 **24 条**（3 组 × 4 层，尽量均衡）；**降级档 18 条**（每类 ≥3），降级必须在报告写明；真游戏终验 12 局 trace 全量纳入（不抽样，只做描述统计） |
| 标注者 / 内容 | 本人（首选一位同学做双人；做不到则做 **intra-rater**，隔 3 天重标一次）；每条只标 `primary_failure` 一类（多标签会增加分歧），E1 单独标注、不计入 Agent 失败 |
| 工具 | 24 行（降级档 18 行）CSV：`episode_id, scope, step_id, 人工标签, 备注` |

```python
from sklearn.metrics import cohen_kappa_score, confusion_matrix
kappa_all = cohen_kappa_score(human, auto)              # 总体，仅作参照
for c in ["F1", "F2", "F3", "F4"]:                      # per-class（one-vs-rest）
    y_h = [x == c for x in human]; y_a = [x == c for x in auto]
    print(c, cohen_kappa_score(y_h, y_a), sum(y_h))
print(confusion_matrix(human, auto, labels=["F1", "F2", "F3", "F4", "F0"]))
abstain_rate = sum(x == "F0" for x in auto) / len(auto)
env_div_rate = sum(x == "E1" for x in scope_real) / len(scope_real)   # E1 不进 Agent 混淆矩阵
```

| 必须报告的项 | 格式 | 为什么 |
|---|---|---|
| 总体 κ | 点估计 + 95% CI | 与文献可比 |
| **per-class κ** | 每类一个 κ + 该类样本数 | 合并 κ 会掩盖个别类别崩塌 |
| **混淆矩阵** | 5×5（F1–F4 + F0） | 看出“哪两类总被互相错分” |
| **弃权率 / 冲突率** | `abstain=true` 占比 + 弃权样本的人工标签分布；一条 trace 命中 ≥2 类的比例 | 弃权太多说明判定器不可用；冲突率高说明分类学互斥性不足 |
| **E1 计数** | E1 条数 / 终验 trace 数 + `divergence_type` 分布 | **非 Agent 失败**；单列，不进 Agent κ 与失败率 |

### 诚实报告要求

- **不要为了达到 κ≥0.7 而调标签**；24 条（降级档 18 条）的 κ 置信区间很宽（约 ±0.2），须写明（数字为示例格式，须以实测替换）：“n=24，总体 κ=0.62（95% CI 约 [0.40, 0.84]），受样本量限制，该一致性仅作方向性参考。”
- **per-class κ 的样本门槛**：某类样本数 <5 时**不单独报该类 κ**，只报计数与混淆矩阵对应行，并注明“样本不足，无法估计该类一致性”。
- 若某类占比为 0% 或 100%，**先怀疑判定器**，单列“未检出任一例”而不是断言“该类不会发生”。
- E1 的 κ 不参与 Agent 一致性报告（它来自环境比对，不是人工-自动标注一致性）；E1 只报计数与 `divergence_type` 分布。
- 分歧条目逐条看：是“判定器太宽”还是“人工标错”。前者修规则并重测，后者记入备注。

## 10. 常见坑

1. **判定器太宽**：某类占比 100% 或 0% → 先怀疑判定器，不要急着解释。
2. **把“没声称分数”当算错 / F4 用在单回合场景**：前者必须返回空，后者无未来、不能判。
3. **对齐错位**：trace 的 step 与环境的 step 不是一回事（一个 turn 可能多 step）；真游戏还有选盲/商店阶段，需先按 `phase` 过滤。
4. **过度依赖 LLM 解释**：解释文字不进任何统计。
5. **把 E1 当 Agent 失败 / 只凭“分数不同”就判 E1**：环境分歧可能来自引擎/适配器/版本链，混进 Agent 失败率会低估 Agent 能力、也会掩盖对齐问题；判 E1 前必须先排除 F2（声称错误）与 F1（非法动作），并追到 A0–A3 的具体失败级别。
6. **拿训练环境 trace 冒充真游戏 trace**：`scope` 必须如实标注；`real_game` 的步必须有 `capture_id` 与 `gamestate` 快照。
