## 1. 实验矩阵（训练集 90 局 + 真游戏 12 局）

### 1.1 训练集主实验（ATE，3 组 × 30 场景 = 90 局）📋

| 组 | 模型 | Prompt | 想回答 |
|---|---|---|---|
| **A** | 本地 4B（q4） | 直接给动作 | 下界基线 |
| **B** | 本地 4B（q4） | CoT（先写推理再给动作） | CoT 对小模型有用吗 |
| **C** | 云端模型 | CoT | 规模差异有多大 |

- 三组统一用 `bench/tools.py` 的 5 个工具；规模 **3 组 × 30 场景 = 90 episode**（每场景 1 次）。60 个决策点是**场景池**，主表实际纳入的 30 个场景与选取规则在预注册中冻结（📋，见 [03](03-评测集与指标.md) §4.2）。执行用 `python -m evaluation batch`（并发 + 断点续跑 + 重试已实现），预计 **4–6h**（含排错）。**可选 D 组**（仅当时间富余）：云端 + 显式“先调 `get_state` 再决策”强约束，测 Tool Use 纪律性；加 D 组必须相应缩减其他章节。

### 1.2 真实游戏终验（RGFT，3 组 × 4 局 = 12 局）📋

配置组与主实验一致（A/B/C），每组 4 局，单局 Ante 1 三盲注（Small 300 / Big 450 / Boss 600），上限 15 分钟或 3 盲注结束（超时记 `timeout` 不剔除），**统计口径只有描述统计 + bootstrap 95% CI，不做显著性主张**；运行栈（Balatro 1.0.1o + Lovely + Steamodded + balatrobot）**尚未接入**，版本链写入 `scenarios/v3/MANIFEST.json`。**规模、划分、预算与降级方案的唯一来源是 [07](07-真实游戏接入与终验.md) §6.1 / §6.5**，本文只落地执行细节；终验是**最终环境测试**，不是批量主环境，不可达时降级为 `CAPTURE_REPLAY_ONLY` 并如实声明，**不得**用训练集结果替代。总计：训练集 90 局 + 真游戏 12 局 = **102 局**；另预留 4–6h 真游戏时间与 3–5h 环境安装。

## 2. 基线

| 基线 | 说明 | 用途 | 环境 |
|---|---|---|---|
| **Random** | 均匀随机选合法动作（`RandomAgent`，已实现） | 下界，验证指标不是噪声 | 训练集 |
| **Greedy-Oracle** | 每步取 Local Oracle 最优（`OracleGreedyAgent`，已实现） | 上界参照（≈0 regret，用于验证流水线） | 训练集 |
| 被测组 A/B/C | 见 §1.1 | 实验主体 | 训练集 + 真游戏终验 |

> Greedy-Oracle 跑通 = 整条链路正确（它的 regret 不接近 0 说明 oracle 或评分有 bug）。**真游戏终验不设 Random 基线**：n=12 且单局成本高，只做 A/B/C 描述统计，不声称“优于随机”。

## 3. 指标与统计

### 3.1 训练集主表（90 局）

| 指标 | 组间比较方法 | 报告内容 |
|---|---|---|
| Local Regret | 配对 Wilcoxon | 中位数、p、rank-biserial、bootstrap 95% CI；`exact=false` 场景单列 |
| Action Optimality / Legality Rate | McNemar | 差值、p、CI |
| Episode Progress | 描述统计（样本少） | 分布 + 均值 CI，不做检验 |
| 失败类型分布 | 卡方/Fisher（若样本够） | 占比 + CI；**E1 单列** |
| Cost / Latency | 描述统计 | 每局 token、每局秒、每决策秒 |

> **五层口径**：本表只覆盖 ① 合规门禁、② 单步战术、⑤ 诊断解释三层；③ 跨期资源分配层与 ④ 长程进度/失败恢复层**当前均未覆盖**（W3 候选，定义见 [03](03-评测集与指标.md) §3）。Local Regret 只衡量单步，**不得单独用来支撑“长线规划”主张**。**多重比较**：3 组两两 = 3 次 → **Holm 校正**，报告校正后 p；**必须同时给出** n、效应量、CI，只给 p 的结论不接受。

### 3.2 真游戏终验（12 局）📋

指标定义、精确性与验收见 [07](07-真实游戏接入与终验.md) §6.3 / §6.4，本文不重复；报告按该表全量出数（`blinds_cleared` / `ante1_win` / `legality_rate` / `timeout_rate` / `agent_failure_class` / `env_divergence` / `real_vs_training_gap` / `cost`），其中 **E1 与超时单列、不进 Agent 失败率**。**统计纪律**：n=12，只做描述统计与 bootstrap CI，**不报 p 值、不做“显著优于”结论**；报告限制章必须单列这一点（D10 与 07 §6.1）。

## 4. 预注册（跑实验前冻结，打 git tag）

```markdown
# prereg v4
- 主指标：Local Regret（L1+L2，按场景数加权；exact=false 场景单列或分层）；**只衡量单步，不作为长线规划证据**——③ 跨期资源分配与 ④ 失败恢复本轮未覆盖，不写进结论

- 训练集样本量：每组 30 场景（3 组 = 90 局）；主表 30 场景的选取规则在此冻结

- 归因一致性：计划 n=24（降级档 n=18）；总体 κ + per-class κ（每类 n≥5 才单独报）+ 混淆矩阵 + 弃权率；F4 不进任何显著性检验；E1 单列、不进 Agent 失败率，判定顺序 F1–F4 优先于 E1
- 剔除：基础设施错误（超时/MCP 断连/模型 5xx）可重跑一次并记录；模型决策错误不剔除；真游戏超时单列不剔除
- 禁止：跑后更换主指标、新增事后子组、只报显著结果、把训练集结果当终验、把 Pass^k 补做当结论
```

## 7. 简历表达建议（数字未实测前一律留空）

### 对「大模型评测」岗（重点：体系设计与 Trace 分析）

> 面向大模型 Agent 的**长线规划评测**：以可判定、可复现的 Balatro 规则子集为环境，围绕**跨回合资源分配 / 多步决策 / 长期构建 / 失败恢复**四支柱设计评测口径（当前交付单步战术与盲注内多步；③ 已有金钱/利息/商店载体但缺指标与场景集，②④ 缺口如实登记、排入 W3），
