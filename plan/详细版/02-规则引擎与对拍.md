## 2. 计分规格（等级 1）

```
chips = 牌型基础 Chips + Σ(参与计分牌的 rank chips；A=11, J/Q/K=10, 其余=点数)
        + Σ(+Chips 效果)
mult  = 牌型基础 Mult，然后按【Joker 槽位从左到右】逐项应用：
        +Mult 加算 / ×Mult 乘算
final = floor(chips × mult)        # Fraction 精确运算，只在末尾 floor 一次（候选口径）
```

| 牌型 | 基础 Chips | 基础 Mult | 计分牌张数 |
|---|---:|---:|---:|
| High Card | 5 | 1 | 1（只计最高一张） |
| Pair | 10 | 2 | 2 |
| Two Pair | 20 | 2 | 4 |
| Three of a Kind | 30 | 3 | 3 |
| Straight | 30 | 4 | 5 |
| Flush | 35 | 4 | 5 |
| Full House | 40 | 4 | 5 |
| Four of a Kind | 60 | 7 | 4 |
| Straight Flush | 100 | 8 | 5 |
| Five of a Kind（隐藏） | 120 | 12 | 5 |
| Flush House（隐藏） | 140 | 14 | 5 |
| Flush Five（隐藏） | 160 | 16 | 5 |

- **A 的点数**：计分时 A=11；顺子判定时 A 可作 1（A-2-3-4-5）或高点（10-J-Q-K-A）。
- **计分牌筛选**：只计参与牌型的牌；踢脚不计分（例如 4K + kicker 只计 4 张）。
- **顺序敏感**：`+4 Mult → ×2` 与 `×2 → +4 Mult` 结果不同；golden 测试固化。
- **取整**：Wiki 未明写最终取整与中间小数处理，`floor` 一次是**候选口径**（`rounding_status: CANDIDATE_FLOOR_UNVERIFIED`），不得写成已验证。
- **contains 关系**：三条含对子；四条**不含**两对；五条**不含**葫芦（结构超集口径，4K/5K 边界 ⏳ UNVERIFIED）。

## 4. 数据模型与动作

```python
# bench/model.py（字段示意；完整签名见 docs/implementation/api-reference.md）
Card       # suit 0♠1♥2♦3♣, rank 1(A)..13(K)；稳定 id 如 "c7h"
Joker      # jid / name / kind(add_chips|add_mult|mul_mult) / value / condition / rarity / cost
GameState  # hand / deck / discard_pile / jokers(≤5) / blind_idx / target /
           # total_score / hands_left / discards_left / phase / rng_state(str) / seed / steps
```

- **稳定身份**：`card_ids`（如 `c7h`）在整个 episode 内稳定；`label`（`7h`）仅供展示；`card_ids` 不排序，入参顺序保留。
- **合法动作**：`play` 1–5 张、`discard` 1–5 张；8 张手牌 ⇒ 218 + 218 = 436 条；场景可限制只允许 play 或 discard。
- **不变量**：`len(hand)+len(deck)+len(discard_pile)==52`；`card_ids` 唯一。
- **观察**：`Observation` 不含 oracle 结果、内部 RNG、完整牌堆顺序；只给合法动作计数，完整动作集用 `environment.legal_actions()`。

## 5. 状态转移与确定性

```
play(cards):
  result = score(cards, jokers)                 # 纯函数
  total_score += result.final_score ; hands_left -= 1
  补牌（先补牌，打出的牌之后才进弃牌堆）
  if total_score >= target: 下一盲注（Boss 后 done/win）
  elif hands_left == 0: done/loss

discard(cards):
  discards_left -= 1 ; 补牌（同上顺序）

choose_joker(idx):                               # 仅商店扩展
  jokers.append(shop_options[idx]) ; 进入下一盲注
```

- **纯函数转移**：`new_game` / `play` / `discard` / `choose_joker` 都先 `deepcopy` 再改，**从不修改入参**；规则层不做文件 IO。
- **换盲注**：重置资源 4/4、`total_score=0`、换目标；上一盲注手牌进弃牌堆后补满。
- **洗牌**：只有牌堆空才洗弃牌堆（消耗 RNG 并写回 `rng_state`）；两堆皆空时 `_draw` 静默少发（已文档化，未测试）。
- **复现**：`rng_state` 是完整 `getstate()` 的 JSON 字符串，可无损往返；seed 只保证本项目内可复现，**不承诺与真游戏同局面**。

## 6. Oracle（局部参照，必须标注精确性）

| 层 | 定义 | 实现 | 精确性 | 用途 |
|---|---|---|---|---|
| **O1 Local Oracle** | 当前手牌所有 play 动作中即时分最高者 | 枚举 218 → 取 max | **exact（局部）** | 单步 regret 分母 |
| **O2 弃牌 EV** | 每个 discard 后下一手 O1 分的期望 | K 次固定种子抽样补牌，输出 `{mean,min,max}` | **approx**（抽样模型与真实发牌不一致） | 弃牌质量排序参考 |
| **O3 Episode 参照** | 全程贪心（每步 O1）累计分 | 模拟执行 | **approx**（贪心上界，非全局最优） | 长程参照，不进主指标 |

**严禁宣称**：局部最优 = 全局最优；O3 贪心分 = 理论最高分；本 seed 与真游戏等价。

**精确性规则**（与 03 §2.1、07 §5.2 一致）：`exact: true` 仅当该局面全部 218 个合法动作都在真游戏中执行并记录得分；否则只能标 `exact: false`（top-k + 随机动作验证），报告写“已验证子集最优”。`best_score == 0` 的局面不进 regret 分母。

## 7. 对齐方案（A0–A4；当前 📋 未执行）

“对齐”不是口号，而是五级可验收契约；训练/开发集只允许包含通过 A0–A4 的局面（详见 07 §3）。

| 级别 | 对齐对象 | 要求 | 验收证据 |
|---|---|---|---|
| **A0 版本锁定** | 游戏/注入链/适配器 | 记录 `game_version`/`build_id`/`deck`/`stake`/`lovely`/`smods`/`balatrobot` 版本 | `scenarios/v3/MANIFEST.json` |
| **A1 状态/动作 schema** | `gamestate` ↔ `GameState` | 手牌、牌堆计数、Joker、盲注、目标、资源、阶段可映射；动作绑定稳定 id + 下标快照 | `tests/test_realgame_schema.py`（📋）+ 逐字段 diff |
| **A2 单步分数** | 引擎 ↔ 真游戏单手得分 | `engine_score == real_score`；不一致追根因或排除 | `docs/quality/engine-fidelity.md` A 表 + B 表 |
| **A3 规则子集** | 计分/牌型/筛选/Joker/盲注/资源 | 已实现规则与 vanilla 一致；未实现规则在 `excluded` 明列 | `scenarios/RULES_VERSION` + 金样测试 |
| **A4 场景来源与回放** | 训练/开发集 | 每个局面有 `origin`、`capture_id`、验证过的动作与分数 | `scenarios/v3/*.jsonl` + `evidence/W3/` |

**流水线**：捕获（`start`/`gamestate`/`save`/`play`/`discard`）→ 建集（30 锚点）→ 变体（`load` 执行不同动作，30 个）→ 验证（引擎重放，比 score/hand/deck/资源）→ 入集或 `rejected`（写原因）。

**辅助证据**（不能替代 A0–A4）：W2 的 20 例人工对拍 + 5 例第三方算分器抽检仍是 **0/20 + 0/5 `PENDING`**；即使补做，也只能作交叉抽检。

**降级**：真游戏不可达 → `CAPTURE_REPLAY_ONLY`（部分可用）或 `NOT_VERIFIED`（不可达）；报告/README 写“未对齐/未捕获”，**不得**标终验通过，也不得用引擎生成局面补 ATS。
