## 0. 先行结论（读其他节之前先看）

### 0.1 外部同名项目：`coder/balatrobench`（与本项目无隶属）

- 仓库：https://github.com/coder/balatrobench ｜站点：https://balatrobench.com/ ｜数据：Kaggle `s1m0n38/balatrobench`
- 规模：23★，MIT，2025-08 建，2026-05 仍在推送。
- 它是什么：**解析 `coder/balatrollm` 产生的对局记录 → 生成可交互排行榜与结果分析站点**；数据同步到 Kaggle。
- 它不是什么：不定义环境、不算 oracle、不做归因。
- **决策（D18，v4.0 已定稿）**：正式名 **`BalatroEval`（无副标题）**；定位为面向大模型 Agent 的长线规划测试集；与 `coder/balatrobench` 只在“相关工作”用一句客观区分（它做排行榜/结果展示，本项目做长线规划测试集），**不再作为命名规则或首段内容**；`CardBench-Lite` / `CardBench-Attrib` 备选名全部废止。

### 0.2 事实修正：`WilsontheWolf/balatro-calculator` 是 fork

- GitHub API 核对：`fork: true`，`parent = EFHIII/balatro-calculator`，0★，2024-03 后再无更新。
- **决策**：报告与文档只写“EFHIII 的 balatro-calculator **及其一个 fork**”，不并列成两个项目。

### 0.3 Jev / TypeSafe：存在，但没有可引用的结果

- 存在性可核：OpenRouter 有模型页（`typesafe/jev`），作者博客（2026-09）详述 Balatro 接入架构；另有**第三方**评测仓库 `wondertwins/jev-benchmark`（8★，非 Jev 官方产物）。
- 可核事实：它是**不生成文本、只给候选校准概率**的判别式模型；Balatro 侧是“balatrobot → 控制环（预打分候选 8–15 个）→ 模型 choice → 执行”，并有硬编码 Panic Filter。
- **不可核**：公开仓库、对照实验、任何分数/胜率；博客里的国际象棋数字是**转引**；价格数字（原 v2.0 记的 $0.042/MTok）**未核实，不得引用**。
- **决策（D11，v3.0 不变）**：只吸收方法论（精确计算归代码、只给已预打分候选、规则守卫兜底），**不引入模型**。

### 0.4 v3.0 决策反转：接入真游戏做终验与捕获

| 项 | v2.x（历史） | v3.0 |
|---|---|---|
| 真游戏 | **不接入**（人工对拍 20 例，0/20 PENDING） | **接入 balatrobot（MIT）**：四层运行栈（Balatro 1.0.1o + Lovely + Steamodded + balatrobot），只做**终验（12 局）与捕获**，不做批量主环境 |
| 自建引擎 | 唯一评测环境 | **对齐训练环境（L0 底座）**，W3 目标 L2 |
| 为什么反转 | — | 纯自建无法回答外部效度；balatrobot 有 `save`/`load`，正好支持“真游戏捕获 + 反事实回放”的训练集构建；MIT 许可允许调用 |
| 代价与边界 | — | 四层依赖 3–5h、版本链脆弱、单局 5–15 分钟；**只跑 12 局**、只做描述统计、不可达即降级 `CAPTURE_REPLAY_ONLY` |

> 当前状态：📋 **尚未接入**（`bridge/realgame.py`、`scenarios/v3/`、`runs/w5-real/` 均未创建）。任何“已接入/已对齐/已终验”的表述都属越线。

## 2. 汇总决策表（v3.0）

| 设计问题 | 备选 | 最终选择 | 理由 | 风险 | 验证方法 |
|---|---|---|---|---|---|
| 环境来源 | 真游戏唯一 / gym / balatro-rs / 自建唯一 | **两阶段：自建对齐训练环境（ATE）+ 真游戏终验（RGFT）** | 真游戏不可批量、不可 CI；纯自建无法回答外部效度；两阶段把“快”和“真”分开 | 两套环境不一致 | A0–A4 对齐契约 + 12 局终验 |
| 是否装 Mod 链 | 装 / 不装 | **装**（Balatro 1.0.1o + Lovely + Steamodded + balatrobot） | 终验与捕获需要真游戏控制面；balatrobot 是 MIT 事实标准，有 `save`/`load` | 四层依赖 3–5h、版本链脆弱、图形依赖 | `health`/`gamestate` 冒烟 + 版本锁定 + 失败即降级 |
| 真游戏用法 | 批量主环境 / 终验与捕获 | **只做终验（12 局）与捕获** | 单局 5–15 分钟、不可并行；批量主环境不可行 | 终验样本少、被误读为显著 | 预注册“描述统计”；失败/超时单列 |
| 训练集来源 | 引擎生成 / 真游戏捕获+回放 | **真游戏捕获 + `save`/`load` 反事实回放** | 避免“生成器与引擎共享同一套错误”的误差自洽 | 变体回放受版本兼容影响 | A4 + G1–G6；不通过进 rejected |
| 动作表示 | 手牌下标（balatrobot）/ 稳定 id | **稳定卡牌 id + 下标快照** | 下标在重排后不可复现；真游戏 API 用下标，需双向映射 | 映射成本 | 同动作序列重放一致 |
| 效果顺序模型 | 自创 / 对齐社区 | **`cardarea × phase` 分派 + vanilla Joker 槽位顺序** | 对齐 smods 与 Balatro-Simulation 语义，否则对拍系统性偏差 | 语义理解错 | 8 个 vanilla Joker 金样 + 9 牌型金样 |
| 随机性表达 | 单点值 / 三态 | **`{mean, min, max}` 三态** | 单点估计会被误读为精确值 | 实现成本 | 近似指标必须带区间 |
| 记分思想 | 自创 / 借 Evalatro | **借 `progress × legality` 作辅助** | 已被验证、易解释 | 主指标仍须换 regret | 报告中引用来源 |
| 结果完整性 | 无 / 重算 + hash | **重放重算 + code hash；真游戏另加 `state_hash` + 版本哈希** | 结论必须可被第三方复算；防“分数与轨迹不一致” | 少量成本 | 校验失败阻断出表 |
| 局部最优 | 自写 / 借 calculator | **自写（218 枚举）；仅全动作真游戏验证才标 `exact: true`** | 只需子集规则，依赖越少越好；精确性必须可审计 | oracle 被误称全局最优 | 金样 + A2 台账 + `validated_actions` |
| Gym 环境 | 采用 / 探针 | **不采用（探针取消）** | MDP 三要素 WIP | 无（省 2h） | — |
| 决策增强 | 引入 Jev / 不用 | **不用** | 目标是评测不是打牌；且无量化证据 | 无 | — |
| 数据来源 | 随意取用 / 清单化 | **清单化 + 许可标注** | 避免 GPL/NC 污染 | 漏标 | `docs/data-sources.md` |
| 真游戏文件入库 | 入库 / 不入库 | **不入库**（L8） | 版权/分发风险 | 证据形态受限 | 只提交脱敏 JSON / 分数 / trace / 版本清单 |

## 4. 生态空白（八条，v3.0 按“对齐 + 终验”更新）

1. **没有“既快又与真游戏对齐”的评测环境**：要么绑真游戏（不可 CI、不可枚举），要么只做局部（算分器/模拟库/种子工具）。v3.0 用“对齐训练环境 + 12 局真游戏终验”回答，但“对齐”本身仍需 A0–A4 证据（📋）。
2. **没有失败归因层**：非法动作只被计数，不分类、不定位到步；更没有人把“环境分歧”从 Agent 失败里隔离出来。→ 本项目 F1–F4 + F0 + **E1**。
3. **没有固定场景集**：现有工具面向“跑完整局”或“搜种子”，没有“单点决策局面 + oracle 最优动作 + 真游戏来源证据”。→ 本项目 60 决策点（30 捕获 + 30 反事实）。
4. **没有 oracle 驱动的过程指标**：无人算 regret / best-action match / oracle 分差；也没有人标注 oracle 是否全动作验证。→ 本项目 `exact` / `validated_actions`。
5. **没有规则实现之间的一致性基准**：各实现覆盖互相矛盾。v3.0 的 A2 对齐台账只回答“**我们的实现 vs 真游戏**在覆盖局面上是否一致”，**多实现横向对比仍空白**。
6. **没有统一的 action/state schema**：下标 / 枚举 / 回调三套并存。balatrobot 的 `gamestate` 已成为事实标准之一，v3.0 以它为 A1 映射目标；跨实现基准仍空白。
7. **MCP/工具化只是副产品**：只有 Evalatro 顺带暴露 MCP，没有人**为长程决策 Agent 设计过工具集**（本项 v3.0 不变，训练 4 工具 + 终验 5 工具）。
8. **没有可复现的失败数据集**：有 replay 日志，但没有失败类别标签、oracle 对照与环境分歧标注。→ 本项目目标；当前仍为空白（📋）。

## 5. 调研结论（v3.0：五句话）

1. **“真游戏 + LLM 基准”已被 Evalatro 占住，“排行榜/结果展示”已被 `coder/balatrobench` 占住**——本项目不重复这两层，改做 **“面向长线规划的测试集（跨回合资源 / 多步决策 / 长期构建 / 失败恢复）+ 与真游戏对齐的训练环境 + 真游戏终验”** 这个组合；失败归因仅作诊断报告层。
2. **“精确算分 + 局部最优”是成熟的**（calculator / Simulation / balatro-rs 都已证明），所以自建引擎的核心工作量是“把规则子集写对、把语义对齐（A0–A4）”，不是算法创新。
3. **“离线确定性引擎”也有人做了**（balatro-rs），但它只是库、无场景集/归因/MCP，且无许可证——这更说明本项目的位置在**评测协议层**而不是引擎层。
4. **“真游戏控制面”也成熟了**（balatrobot，MIT，`save`/`load`）——v3.0 直接用它做终验与捕获，不再自建控制层；但“可判定归因 + 对齐训练集 + 小样本真游戏终验”这个组合仍无公开实现（截至 2026-11-12 未发现）。
5. **生态里没有“可判定的失败归因”**——这是唯一真正稀缺的部分，也是 100h 应该押注的方向；v3.0 用 E1 把“环境不可靠”从归因里再剥离一层。
