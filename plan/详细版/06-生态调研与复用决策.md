## 0. 先行结论（读其他节之前先看）

### 0.1 外部同名与近名项目

- **`coder/balatrobench`**（与本项目无隶属）：https://github.com/coder/balatrobench ｜https://balatrobench.com/ ｜数据 Kaggle `s1m0n38/balatrobench`；23★，MIT，2025-08 建，2026-05 仍在推送。它**是**“解析 `coder/balatrollm` 对局记录 → 排行榜与结果分析站点”；它**不是**环境、不是 oracle、不做归因。**决策（v4.0 改名）**：正式名 **`BalatroEval`**，定位为长线规划测试集，与它只在“相关工作”用一句客观区分；`CardBench-Lite` / `CardBench-Attrib` 备选名全部废止。
- **`WilsontheWolf/balatro-calculator` 是 fork**：GitHub API 核对 `fork: true`、`parent = EFHIII/balatro-calculator`、0★、2024-03 后再无更新 → 只写“EFHIII 的 balatro-calculator **及其一个 fork**”，不并列成两个项目。

### 0.2 Jev / TypeSafe：存在，但没有可引用的结果

- 可核：OpenRouter 有模型页（`typesafe/jev`），作者博客（2026-09）详述 Balatro 接入架构；另有**第三方**评测仓库 `wondertwins/jev-benchmark`（8★，非官方产物）。它是**不生成文本、只给候选校准概率**的判别式模型；Balatro 侧是“balatrobot → 控制环（预打分候选 8–15 个）→ 模型 choice → 执行”，带硬编码 Panic Filter。**不可核**：公开仓库、对照实验、任何分数/胜率；博客里的国际象棋数字是**转引**；价格数字（$0.042/MTok）**未核实，不得引用**。**决策（不引入外部模型）**：只吸收方法论（精确计算归代码、只给已预打分候选、规则守卫兜底），**不引入模型**。

## 2. 汇总决策表（环境来源 / Mod 链 / 真游戏用法见 §0.3 与 07 §2；Gym / 决策增强 / 数据来源 / 入库见 §2.1 与 §3.3）

| 设计问题 | 备选 | 最终选择 | 理由 | 风险 | 验证方法 |
|---|---|---|---|---|---|
| 训练集来源 | 引擎生成 / 真游戏捕获+回放 | **真游戏捕获 + `save`/`load` 反事实回放** | 避免“生成器与引擎共享同一套错误”的误差自洽 | 变体回放受版本兼容影响 | A4 + G1–G6；不通过进 `rejected` |
| 动作表示 | 手牌下标（balatrobot）/ 稳定 id | **稳定卡牌 id + 下标快照** | 下标在重排后不可复现；真游戏 API 用下标，需双向映射 | 映射成本 | 同动作序列重放一致 |
| 效果顺序模型 | 自创 / 对齐社区 | **vanilla Joker 槽位顺序 + contains 条件判定**（不声称实现 SMODS 的 `cardarea × phase` 分派） | 顺序敏感必须与真游戏一致，否则对拍系统性偏差 | 语义理解错 | 8 个具名 Joker 金样 + 12 牌型金样（9 regular + 3 secret）；真游戏比对 📋 |
| 随机性表达 | 单点值 / 三态 | **`{mean, min, max}` 三态** | 单点估计会被误读为精确值 | 实现成本 | 近似指标必须带区间 |
| 记分思想 | 自创 / 借 Evalatro | **借 `progress × legality` 作辅助** | 已被验证、易解释 | 主指标仍须换 regret | 报告中引用来源 |
| 结果完整性 | 无 / 重算 + hash | **重放重算 + code hash；真游戏另加 `state_hash` + 版本哈希** | 结论必须可被第三方复算 | 少量成本 | 校验失败阻断出表 |
| 局部最优 | 自写 / 借 calculator | **自写（218 枚举）；仅全动作真游戏验证才标 `exact: true`** | 只需子集规则，依赖越少越好；精确性必须可审计 | oracle 被误称全局最优 | 金样 + A2 台账 + `validated_actions` |

### 3.1 可直接借鉴

| 借鉴点 | 来源 | 用在哪 |
|---|---|---|

| 重算校验 + code hash；工具注册表单一事实源 | Evalatro | 主表出数前的完整性闸；Runner 与 MCP 共用动作定义 |
| 分类学 + κ、per-class κ + 95% CI、低置信弃权；数值数据表与算分器抽检 | MAST / AgentDebug / Error Bars to Evals / Trust or Escalate；Wiki / Balatro HQ / EFHIII calculator | 4 类 Agent 判定器设计与一致性检验（04 §6）；牌型基础分、盲注目标分；第三方抽检（附录 D） |

### 3.2 需改造后借鉴

| 借鉴点 | 为什么不能照搬 | 改造 |
|---|---|---|
| 手牌下标动作 | 重排后不可复现；真游戏 API 只接受下标 | 稳定 id + 下标快照 + 双向映射 |
| 完整规则（150 jokers / 多牌组） | 100h 做不完 | 裁到 8 个具名 vanilla Joker / Red Deck + White Stake / Ante 1，并写明 `excluded` |
| 原版 RNG 复刻 / Ante 12 长局 | 成本高、随版本漂移、小模型跑不完 | 不复刻，改 captured-state alignment（D11）；主指标改局部 regret，终验只跑 Ante 1 |
| 进度百分比作主指标；合并 κ | 依赖子目标标注、方差大；合并 κ 掩盖单类低一致性 | 只作补充，主指标用 regret；per-class κ + 混淆矩阵 + 弃权率 |
| 真游戏单步对拍（人工 20 例） | 装链 3–5h 且脆弱；人工不可规模化 | **升级为 A0–A4 + 真游戏捕获/`save`–`load` 回放**；旧 20+5 降为辅助（附录 D） |
| Evalatro 的“真游戏全量跑” | 依赖游戏本体、不可 CI、单局慢 | 改为“训练环境批量 + 真游戏 12 局终验”，保留其重算/合法性思想 |

### 3.3 明确不借鉴

| 不借鉴 | 理由 |
|---|---|
| 把真游戏当批量主环境 | 四层依赖、不可 CI/并行；v3.0 只做 12 局终验与捕获 |
| Gymnasium 封装 / 视觉路线（YOLO+OCR） | MDP 三要素 WIP、探针取消；识别误差与决策误差不可分离 |
| 外部判别式小模型（Jev 类） / 排行榜产品化 | 闭源、无量化结果、目标漂移；已有 `coder/balatrobench` 与 Evalatro |
| 照抄 balatro-rs（无许可证）、Divvy 模拟库（GPL）、Steamodded/Lovely 源码（GPL/仅运行时）、搬运 Wiki 文本（CC BY-NC-SA）、复制游戏文件/存档/截图（商业软件） | 许可与合规红线，逐项见 §2.1 |

## 4. 生态空白（与 README/03/07 重复的论证已删，只留可核查缺口）

1. **没有“既快又与真游戏对齐”的评测环境**：要么绑真游戏（不可 CI、不可枚举），要么只做局部（算分器/模拟库/种子工具）。本项目用“对齐训练环境 + 12 局终验”回答，但“对齐”本身仍需 A0–A4 证据（📋）。
2. **没有失败归因层**：非法动作只被计数，不分类、不定位到步；没人把“环境分歧”从 Agent 失败里隔离出来。→ F1–F4 + F0 + E1（📋）。
3. **没有固定场景集、oracle 过程指标、统一 action/state schema、跨实现一致性基准、可复现的失败数据集**：现有工具面向“跑完整局”或“搜种子”，无人算 regret / best-action match，也无人标注 oracle 是否全动作验证；下标/枚举/回调三套 schema 并存（balatrobot 的 `gamestate` 已成事实标准之一，作 A1 映射目标）。→ 60 决策点 + `exact` / `validated_actions`（📋）；多实现横向对比与“失败类别 + oracle 对照 + 环境分歧”标签仍空白。

---

## 5. 调研结论（三句）

1. “真游戏 + LLM 基准”已被 Evalatro 占住，“排行榜/展示”已被 `coder/balatrobench` 占住——本项目不重复这两层，做**“长线规划测试集 + 与真游戏对齐的训练环境 + 真游戏终验”**的组合；失败归因仅作诊断报告层。
2. “精确算分 + 局部最优”与“离线确定性引擎”都已有成熟实现（calculator / Simulation / balatro-rs），所以自建引擎的工作量在**把规则子集写对、把语义对齐（A0–A4）**，不在算法创新；balatro-rs 无许可证、且只是库，更说明本项目位置在**评测协议层**。
3. “真游戏控制面”也成熟了（balatrobot，MIT，`save`/`load`），v3.0 直接用它做终验与捕获；但“可判定归因 + 对齐训练集 + 小样本真游戏终验”的组合仍无公开实现（截至 2026-11-12 未发现）。
