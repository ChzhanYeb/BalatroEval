## 八条核心原则（v3.0 由 6 条扩为 8 条：增补“对齐优先 / 两阶段”）

1. **正确性优先于功能量**：规则/算分错一次，全部结论作废。
2. **对齐优先（v3.0 新增）**：训练/开发环境必须是 vanilla 的**严格子集**——“实现到的规则与真游戏逐位一致，没实现的规则在场景中排除”，**不允许**用自定义公式近似已实现的规则（`07` §0 三条边界）。
3. **两阶段（v3.0 新增）**：训练环境负责“快、可枚举、可 CI”；真实游戏负责“最终证据”。两者**不是二选一**，也不是同一环境；结论必须标明来自哪一阶段。
4. **单一事实来源**：规则只在 `bench/` 实现一份，MCP Server 只转发；真游戏适配器是薄壳，**不写第二份规则**。
5. **Oracle 与 Agent 隔离**：被测 Agent 永远看不到 oracle 的动作与分数；求解器只提供 Ground Truth。
6. **精确与近似必须分开**：每个指标标注 `exact` 或 `approx`，近似指标不给强结论；`exact: false` 的 oracle 不得写成“全局最优”。
7. **可复现优先**：固定版本、固定场景、一条命令重跑；真游戏侧记录 `game_version`/`capture_id`/`adapter_version`。
8. **不夸大**：样本量不足就说不足；差异不显著就说没检出；12 局终验只做描述统计，不做显著性主张。

## 九条不能违反的设计底线

| # | 底线 | 违反后果 |
|---|---|---|
| L1 | 不得让 Agent 直接调用 oracle 或读取 oracle 结果 | 评测被污染，结论无效 |
| L2 | 不得把 Local Oracle 的分数称为“全局最优”；`exact: false` 只能写成“已验证子集最优” | 学术不诚实 |
| L3 | 不得让 LLM Judge 参与主指标 | 评测失去客观性 |
| L4 | 不得维护第二份规则实现（含真游戏适配器里复算规则/分数） | 两套规则必然漂移 |
| L5 | 不得修改或覆盖 `evidence/` 下的既有证据 | 失去可信度 |
| **L6**（v2.1 提出，**v3.0 改写**） | **口径是 captured-state alignment**：只承诺“单步状态/分数与真游戏捕获一致”，**不得声称“与真游戏同种子同局面”**（RNG 未复刻，且 v3.0 不再依赖同 seed 同局面） | 一旦被对齐台账推翻，全部保真度结论作废 |
| **L7**（v2.1） | 不得引入 GPL 代码、不得搬运 CC BY-NC-SA 文本；`balatro-rs` 只作设计对标 | 许可污染，仓库不可分发 |
| **L8**（v3.0 新增） | **真实游戏相关文件不得入库**：游戏本体、mod（Lovely/Steamodded/balatrobot）源码或二进制、`.jkr` 存档、含游戏素材的截图；仓库只保留脱敏后的状态 JSON、分数、trace、版本清单 | 版权/分发风险，仓库不可分发 |
| **L9**（v3.0 新增） | **不得把“真游戏捕获回放”写成“真实游戏终验”**；不得把“单步分数一致”写成“完整规则一致”；不得把 12 局小样本写成“统计显著” | 外部效度被夸大，结论不可信 |

> L6 在 v3.0 的含义变化：v2.1 的 L6 是“不承诺同种子同局面”（因为 RNG 未复刻）；v3.0 把它升级为**正面口径**——训练集局面来自**真游戏捕获 + `save`/`load` 回放**，因此保真度主张改为 captured-state alignment + A0–A4 对齐契约。
>
> L8/L9 是 v3.0 接入真游戏后的两条新护栏：前者管“什么东西不能进仓库”，后者管“什么话不能说”。

## 状态标记约定

文档中所有结论必须带标记：

- `✅ 已验证`：有命令输出、测试或证据文件支撑
- `⏳ 待验证`：合理假设，但尚未在本机确认
- `📋 规划`：计划要做，尚未开始
- `🔁 已被取代`：旧决策被新决策覆盖（保留可追溯，不再作为执行依据）

> 任何“规划”都不得写成“已实现”；任何“待验证”都不得写成“已验证”；被取代的旧决策必须显式标注，不得静默删除。

## v3.0 执行提醒（五条）

1. **命名（v4.0）**：正式名 **`BalatroEval`**（无副标题）；`coder/balatrobench` 只在“相关工作”用一句客观区分，不再作为命名规则；旧名 BalatroBench / CardBench-Lite / CardBench-Attrib 全部废止。
2. **口径**：保真度只承诺 **captured-state alignment**（单步状态/分数与真游戏捕获一致），不承诺同种子同局面；报告中每处“保真/对齐”都必须带这条限定（D13 / L6）。
3. **等级**：当前 **L0**；W3 目标 **L2**；W5 目标 **L3**（小样本终验）。写任何结论前先问“这是哪一级的证据”（`07` §3.1）。
4. **环境**：真游戏四层依赖（Balatro 1.0.1o + Lovely + Steamodded + balatrobot）**有图形依赖、不可 CI、不可并行、版本脆弱**；装不上就降级为“捕获回放验证”并如实声明，**不得**标为终验通过（`07` §6.5）。
5. **引用**：设计上借鉴了 `balatro-rs`（动作生成器/action mask/RNG 做法）、`Balatro-Simulation`（cardarea × phase 分派、min/exact/max 三态）与 Evalatro（重算校验、code hash、工具单一事实源），**只借鉴设计、不复制代码**，并在报告中注明来源（D14）。
