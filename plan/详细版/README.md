## 核心原则

1. **正确性优先于功能量**：规则/算分错一次，全部结论作废。
2. **对齐优先**：训练环境必须是 vanilla 的严格子集——“实现到的规则与真游戏逐位一致，没实现的规则在场景中排除”，不允许用自定义公式近似已实现规则。
3. **两阶段**：训练环境负责“快、可枚举、可 CI”；真实游戏负责“最终证据”；结论必须标明来自哪一阶段。
4. **单一事实来源**：规则只在 `bench/` 实现一份；适配器只转发，不写第二份规则。
5. **Oracle 与 Agent 隔离**：被测 Agent 永远看不到 oracle 的动作与分数。
6. **精确与近似分开**：每个指标标注 `exact`/`approx`；`exact: false` 不得写成“全局最优”。
7. **可复现优先**：固定版本、固定场景、一条命令重跑；真游戏侧记录版本与 capture id。
8. **不夸大**：样本不足就说不足；12 局终验只做描述统计，不做显著性主张。

## 九条设计底线

| # | 底线 | 违反后果 |
|---|---|---|
| L1 | 不得让 Agent 直接调用 oracle 或读取 oracle 结果 | 评测被污染 |
| L2 | 不得把 Local Oracle 分数称为“全局最优”；`exact: false` 只能写“已验证子集最优” | 学术不诚实 |
| L3 | 不得让 LLM Judge 参与主指标 | 评测失去客观性 |
| L4 | 不得维护第二份规则实现（含适配器里复算规则/分数） | 两套规则必然漂移 |
| L5 | 不得修改或覆盖 `evidence/` 下的既有证据 | 失去可信度 |
| L6 | 口径是 **captured-state alignment**：只承诺“单步状态/分数与真游戏捕获一致”，不得声称“与真游戏同种子同局面” | 保真度结论作废 |
| L7 | 不得引入 GPL 代码、不得搬运 CC BY-NC-SA 文本；`balatro-rs` 只作设计对标 | 许可污染，仓库不可分发 |
| L8 | 真实游戏相关文件不得入库：游戏本体、mod、`.jkr` 存档、含素材截图；只保留脱敏状态 JSON、分数、trace、版本清单 | 版权/分发风险 |
| L9 | 不得把“捕获回放”写成“真游戏终验”；不得把“单步分数一致”写成“完整规则一致”；不得把 12 局写成“统计显著” | 外部效度被夸大 |

## 状态标记

- `✅ 已验证`：有命令输出、测试或证据文件支撑。
- `⏳ 待验证`：合理假设，尚未在本机确认。
- `📋 规划`：计划要做，尚未开始。
- `🔁 已被取代`：旧决策被新决策覆盖，保留可追溯，不再作为执行依据。

> 任何“规划”不得写成“已实现”；任何“待验证”不得写成“已验证”；被取代的旧决策必须显式标注。
