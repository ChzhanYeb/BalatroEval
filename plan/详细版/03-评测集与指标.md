## 1. 场景集设计（60 个决策点，📋 目标态）

### 1.1 来源构成（v3.0 口径）

| 类别 | 数量 | 来源（`origin`） | 说明 |
|---|---:|---|---|
| **R 类：真游戏锚点** | 30 | `real_capture` | 从真游戏 Ante 1（Red Deck / White Stake）捕获；覆盖无 Joker / 单 Joker / 双 Joker / 含 ×Mult / 多弃牌 |
| **C 类：反事实变体** | 30 | `real_counterfactual` | 在锚点局面 `load` 后执行不同合法动作、真游戏实测得分；用于“同一局面、不同选择”的 oracle 对照 |
| 合计 | **60** | — | 不再由引擎“生成后直接入集” |

> 每个决策点必须有真游戏 `capture_id` 与 `saved_state`（脱敏引用/哈希），否则不得入集（A4）。
> **现状**：真游戏捕获 **0 个**；`scenarios/v3/` 不存在；`scenarios/dev/` 的 6 个场景只用于调试 loader/validator/runner 与冒烟，**不是 ATS，不进评测集、不出主表**。

### 1.2 难度分层（“决策难度”）

| 层 | 数量 | 构造 | 测的能力 | 决策点 |
|---|---:|---|---|---|
| **L1 基础** | 20 | 单回合、无 Joker、标准牌型 | 会不会选最优牌型 | play |
| **L2 组合** | 20 | 1–2 个 vanilla Joker，涉及 +Chips / +Mult / ×Mult 取舍 | 懂不懂机制与优先级 | play |
| **L3 长程** | 15 | 同一盲注内多次 play / discard（连续决策点） | 盲注内资源使用顺序、短程前瞻（**不跨盲注**） | play / discard |
| **L4 极限** | 5 | 高目标 / 必须搏特定牌型；仍以真游戏可回放为前提 | 风险决策 | play / discard |

> 层数量以 07 §5.1 为准（20/20/15/5 = 60，与 00 D5 一致）；调整必须先改 07 再改本文。

**当前分层的能力缺口（不得据此声称已覆盖长线规划）**：

- **L1 + L2 = 40/60 是单步战术**：一个局面、一次 `play`，考“这一手选得对不对”，不涉及跨回合安排。
- **L3 只是“同一盲注内”的多次 play/discard**：有盲注内顺序，但**不跨盲注**；**L4 是高风险单步**，仍是单个决策点。
- **经济载体已就绪（2026-11-22 v2），但场景与指标还没做**：`money`/`interest`/`shop_economy` 已从 `excluded` 移出，引擎能提供“存钱吃利息 vs 现在买 Joker”的取舍；当前只有 1 个 dev 经济决策点（`dev-shop-buy-or-bank`），**没有**跨盲注构建、经济取舍指标、失败恢复（“先失败后重新规划”）的构造与恢复率指标。
- **手数/弃牌仍每盲注重置**：`hands`/`discards` 不跨期积累，所以“省资源到下一盲注”在本环境里**只能靠钱**，不能靠手数。

> 因此只能声称“**单步战术 + 盲注内多步**”，**不能**声称覆盖“长线规划”。③ 跨回合资源分配**已有载体、缺指标与场景集**；② 长期构建 / ④ 失败恢复 / 长线指标**未覆盖**，登记 **W3 场景改造候选**（来源：[README](../../README.md)「定位与当前实现差距」）。

### 1.3 三轴标签（v2.1 新增，保留）

| 标签 | 取值 | 用途 |
|---|---|---|
| `decision_depth` | 1（单步）/ 2–3（短程）/ ≥4（长程） | 看 regret 是否随步数上升 |
| `branch_count` | 该局面合法动作数：8 张手牌 ⇒ **218 个出牌动作**（另有 218 个弃牌动作，合计 436） | 看 regret 是否随选择空间扩大上升 |
| `horizon_need` | 0（只看当前）/ 1（看下一手）/ 2（看下一盲注） | 看“前瞻需求”是否与规划不足类失败相关 |

> 标签由捕获/变体流水线自动写入（📋），人工只复核 10 个样本。报告可按任一轴分组，但**同一张表内只能用一个轴**。

## 2. 场景 Schema（v3，📋 规划字段；**尚未创建任何 v3 场景**）

> 下列字段是 07 §5.2 的 **v3 设计**。当前实现的场景 Schema 是 `scenario_schema_version = 1`（`scenarios/schema.py`）；`scenarios/dev/` 的 6 个场景 `origin: synthetic_dev`，只用于开发冒烟，**不是 ATS、不带 `oracle` / `validation` 字段**。
> `schema_version: 3` 下，Agent 可见字段只有 `initial_state` 的渲染文本；`oracle`、`available_actions`、`validation` 仅评测器使用。

```jsonc
{
  "scenario_id": "L2-0007",
  "schema_version": 3,
  "origin": "real_capture",              // real_capture | real_counterfactual
  "game": { "version": "1.0.1o", "build_id": "...", "deck": "RED", "stake": "WHITE",
            "seed": "ABC123", "capture_id": "cap-20261120-001",
            "saved_state": "data/realgame/saves/cap-...-step03.jkr" },  // 仅脱敏引用/哈希
  "initial_state": { /* GameState 投影 */ },
  "available_actions": ["play:c3h,c7s", "discard:c5d"],                 // 稳定卡牌 id
  "oracle": { "best_actions": ["play:c3h,c7s"], "best_score": 48,
              "exact": true, "validated_actions": 218, "unvalidated_actions": 0 },
  "validation": { "engine_score_equals_real": true, "legal_actions_match": true,
                  "state_transition_match": true, "evidence": "evidence/W3/align/L2-0007.json" },
  "tags": { "decision_depth": 1, "branch_count": 436, "horizon_need": 0 },
  "expected_constraints": { "max_steps": 12, "must_finish": true },
  "metadata": { "rules_version": "vanilla_1.0.1o_subset_v2", "notes": "同花顺陷阱：手牌含 4 张同花" }
}
```

> 动作一律用**稳定卡牌 id**（见 02 §4）；手牌下标快照仅供展示与对照 balatrobot，**不参与判定与重放**，不能作回放主键（07 §4.2）。

### 2.1 Oracle 精确性规则

- `exact: true`：该局面**全部 218 个出牌动作**都在真游戏回放并记录得分（成本高，只做少量，如 6 个 L1 局面）。
- `exact: false`：只验证 **top-k（k=3）+ 2 个随机动作**；`best_actions` 是“已验证动作中的最优”，报告必须注明**不是全局最优**。
- `best_score == 0` 的局面不进 regret 分母，单独计数。
- **禁止**把 `exact: false` 写成“全局最优”，也禁止把 `validated_actions` 写成“全部动作”。

### 2.2 入集门槛 G1–G6（缺一不可）

- [ ] **G1 版本/来源完整**（A0）：`version` / `build_id` / `deck` / `stake` / `capture_id` / 依赖版本齐全；
- [ ] **G2 状态字段可映射**（A1）：`gamestate` ↔ `GameState` 逐字段 diff 通过；
- [ ] **G3 单步分数一致**（A2）：至少一个动作的真游戏分数 == 引擎分数（证据填 `docs/quality/engine-fidelity.md` A/B 表，第三方抽检为辅）；
- [ ] **G4 合法动作集一致**（A1/A3）；**G5 状态转移字段一致**（分数、手牌、剩余出牌/弃牌；牌堆只比计数）；**G6 证据文件存在且可重放**（`evidence/W3/align/<scenario_id>.json`）。

不满足任一项 → 进 `rejected` 并写原因，**不得**“先入集、以后补验证”。

## 3. 指标体系（五层结构）

> **五层口径**：① 合规门禁 → ② 单步战术 → ③ 跨期资源分配 → ④ 长程进度/失败恢复 → ⑤ 诊断解释。
> **硬约束**：Local Regret 只衡量单步，**不得单独支撑“长线规划”主张**；长线结论须由 ③④ 层指标支撑（当前均未覆盖）。

| 层 | 指标 | 当前覆盖 | 关键事实 |
|---|---|---|---|
| **① 合规门禁** | Legality Rate、非法动作计数 | ✅ 可算 | `evaluation/` 每局输出 `legality_rate`；对应 04 §3 F1 |
| **② 单步战术** | Local Regret（主）、Action Optimality、Discard EV Gap | ✅ play 决策可算 | O1 精确 argmax；只覆盖单步、不跨回合；Discard EV Gap 未进指标表（📋）；real model 未实测 |
| **③ 跨期资源分配** | 跨回合资金 / 利息 / 商店经济取舍 | ⚠️ 载体已就绪 / 指标未定义 | v2 已实现 `money` 跨盲注保留、利息 cap $5、2 报价付费商店（买/卖/reroll）；**没有**跨期效率/商店决策收益差指标，只有 1 个 dev 场景 → W3 必做 |
| **④ 长程进度 / 失败恢复** | Episode Progress、失败恢复率 | ⚠️ 粗粒度 / ❌ 未定义 | 进度只数“盲注档数 / 3”；恢复率无定义、无场景 → W3 候选 |
| **⑤ 诊断解释** | 首次失败步、F1–F4 / F0、E1 `env_divergence` | 📋 未实现 | `bench/attrib.py` 未创建；E1 是数据质量门禁、非 Agent 失败类 |

### 3.1 ①② 合规门禁与单步战术（✅ 可算；real model 未实测）

- **Legality Rate / 非法动作计数**（①）：合法调用 ÷ 总调用；非法计数 = `tool/result.isError` + 白名单外调用（= 04 的 F1）。`evaluation/` 每局输出 `legality_rate`，exact，只反映协议层。
- **Local Regret**（主，②）：`(best − actual) / best`，**只对 `play` 决策**、以 O1 的 218 个出牌候选为 oracle（exact）；`evaluation/` 输出 `mean_regret` / `max_regret`。
- **Action Optimality**（②）：命中最优动作的比例（并列算命中），`evaluation/` 输出 `optimality_rate`。
- **Discard EV Gap**（辅，②）：`(EV_best − EV_actual) / EV_best`，用 O2 的 `mean`（**approx**，须报 min/max）；目前只用于 oracle-greedy 的弃牌选择，**未进指标表**（📋）。

> 本层回答“单个决策点选得对不对”，**不回答**“跨回合安排是否合理”；real model 未实测（HTTP Adapter 仅 fake transport 测试）。

### 3.2 ③ 跨期资源分配（⚠️ 载体已就绪、指标未定义）

事实（`scenarios/RULES_VERSION`，v2）：`money` / `interest` / `shop_economy` **已不再 excluded**，引擎已实现“起始 $4 + 通关奖励 3/4/5 + 每手/每弃牌 $1 + 利息 cap $5 + 2 报价付费商店（买/卖/reroll/离开）”；`money` **跨盲注保留**，是唯一可累积的跨期资源；`hands` / `discards` 仍每盲注固定重置 4/4，**不跨期积累**。

**缺口**：没有跨盲注资源调度 / 经济取舍 / 构建路径的**指标定义**与**场景集**（当前只有 1 个 dev 经济决策点 `dev-shop-buy-or-bank`），**不能用现有指标声称跨回合资源分配能力**。登记 W3（跨期资源效率、商店决策收益差、利息机会成本、跨盲注构建路径）——**定义与实现均未开始**。

> 经济口径提示：价格是稀有度中值、商店候选均匀抽样、利息按入账前金额，三条均 `unverified`；基于这些口径算出的“经济最优”不可外推到真游戏。

### 3.3 ④ 长程进度 / 失败恢复（⚠️ 粗粒度 / ❌ 未定义）

- **Episode Progress**：通过的盲注档数 ÷ 3，终局统计，exact 但**粒度粗、方差大**（小模型常恒为 0）。
- **失败恢复率**：**未定义/未实现**——无“先失败、后恢复”场景与恢复代价定义 → W3 候选。经济层给了构造前提（买错 Joker → 后续盲注用剩余钱补救），但**尚未构造任何该形态的场景**。
- `Pass^k` 子集已在 v3.0 **取消**（为真游戏终验腾预算），不再作为交付项。

> 本层是长线规划主张的主要证据层，当前**不成立**。

### 3.4 ⑤ 诊断解释（📋 设计已定、未实现）

- **首次失败步**：regret 首次超阈值（默认 0.5）的步序号，可从 trace 的 `decision_metric` 事件派生；**聚合中尚无该字段**。
- **失败类型分布 F1–F4 / F0**：按 04 分类学统计占比，F1–F3 exact、F4 heuristic；`bench/attrib.py` **未创建**（📋）。
- **`env_divergence`（E1 / 非 Agent）**：真游戏结果与训练环境预期不一致的次数/占比，是**数据质量门禁、不是 Agent 失败类**，不进失败率、单独报（04 §2.1）。

> 本层只解释“错在哪类、哪一步”，**不承担能力结论**，是错误分析 / 题目元数据素材。

### 3.5 跨环境与成本（不属于五层）

- **Cost / Latency**：每局 token、墙钟、每决策延迟；`evaluation/` 已记录 `latency_ms` / `total_usage`（exact，受网络波动影响）。
- **`real_vs_training_gap`**：同模型训练集 regret ↔ 真游戏 `blinds_cleared` / `ante1_win` 的方向性差异；n=12、**只描述不检验**（📋）。

> **报告原则**：主表数字必须同时给 **n、效应量、95% CI**；近似指标带区间，不允许只报点值。真游戏终验指标（`blinds_cleared` / `ante1_win` / `legality_rate` / `timeout_rate` / `agent_failure_class` / `cost`）见 07 §6.3，本文件不重复。

### regret 边界处理

- `best_score == 0` → **不计入 regret**，单独计数（否则分母为 0）。
- Agent 在该出牌时选 `discard`（合法但零得分）→ 记 `actual = 0`，regret = 1。
- Agent 未做动作即终止 → 该 episode 记 `premature_stop`，不参与 regret 均值，单列比例。
- **`oracle.exact=false`** → 只能作为**已验证子集**指标，报告带 `exact=false` 标记，不得与 `exact=true` 混算同一均值。

### 不准做的事

- ❌ 把 Episode Progress 当主指标（小模型恒 0）
- ❌ 用 Discard EV Gap 下强结论（近似）
- ❌ 把不同难度层的 regret 混在一起算平均（分层报告）
- ❌ 把 `env_divergence` 计入 Agent 失败率或 regret
- ❌ 把单步 Local Regret 写成“长线规划能力”证据；❌ 把 ③④ 的“未覆盖”写成“已覆盖/部分覆盖”

## 4. 配对实验设计（📋 未执行）

### 4.1 三组配置

| 组 | 模型 | Prompt | 说明 |
|---|---|---|---|
| **A** | 本地 4B（q4） | 直接给动作 | 下界基线 |
| **B** | 本地 4B（q4） | 先推理后给动作（CoT） | 测 CoT 对小模型的作用 |
| **C** | 云端模型 | CoT | 测规模差异 |

**配对键**：`(scenario_id, capture_id, model_config_version, prompt_version, tool_version)` —— 同场景、同捕获状态、同工具描述，只变模型/Prompt。v3.0 用 `capture_id` 取代旧 `seed` 作为局面身份（D11：不复刻 RNG）。

### 4.2 样本量

- **训练集主实验**：3 组 × **30 场景** = **90 局**（每场景 1 次）。60 个决策点是**场景池**，主表纳入哪 30 个、按什么规则选，必须在预注册中冻结（📋）；事前估算每组约需 50 局才谈得上显著性，30 场景不足 ⇒ 事前按“描述统计 + CI”预注册，**不承诺显著性**。
- **真游戏终验**：3 组 × **4 局** = **12 局**，只做描述统计（07 §6.1、05 §1.2）。

### 4.3 统计方法

- regret（连续、配对）→ Wilcoxon signed-rank：p、rank-biserial 效应量、bootstrap 95% CI。
- optimality / legality（二值、配对）→ McNemar：p、差值 CI。
- 三组两两比较（3 次）→ **Holm 校正**；失败类型分布 → 卡方 / Fisher（样本够时）报占比 + CI。
- 真游戏终验（n=12）→ **只做描述统计 + bootstrap 95% CI**，不做显著性主张、不报 p 值。

**必须同时报**：样本量、效应量、CI。只报 p 值不接受。
