> 目标：60 个**与真游戏对齐**的固定决策点（目标态；当前仍是 **L0 未对齐**，📋）+ 一组**定义清晰、局限明确**的指标 + 可执行的统计方案。
> 版本：v3.0-2026-11-13 ｜ 状态：📋 规划（`scenarios/v3/` 未创建）
> 决策基线：[07-真实游戏接入与终验.md](07-真实游戏接入与终验.md)（§5 场景集、§6 终验）；与 `00-项目全貌.md` 的 D3/D4/D5/D6/D9/D10 同步。
>
> **v3.0 改了什么**：①场景集 60 = **30 真游戏锚点（`real_capture`）+ 30 反事实变体（`real_counterfactual`）**，不再由引擎“生成后直接入集”；②Schema 升 **v3**，新增 `origin` / `game` / `capture_id` / `saved_state` / `oracle.exact+validated_actions` / `validation`；③新增入集门槛 **G1–G6** 与 oracle 精确性规则（**全部 218 动作验证才 `exact: true`**）；④指标新增 `real_vs_training_gap` 与 `env_divergence`（**非 Agent 失败**）；⑤实验规模 3 组 × 60 = 180 → **3 组 × 30 场景 = 90 局**，`Pass^k` 取消；⑥三轴标签与 CI 要求**不变**。
>
> **v2.1（历史）**：场景增加三轴标签；指标增加 Pass^k 子集与首次失败步；主表数字一律带 n 与 95% CI；复现要素扩为五项（含重放重算 + code hash）。其中 Pass^k 已被 v3.0 取消，其余保留。
>
> **v4.0 改了什么（本文件）**：①项目正式名 **BalatroEval**（无副标题），定位改为**面向大模型 Agent 的长线规划测试集**，失败归因降为诊断报告层/错误分析章节；②§1.2 补「当前分层的定位缺口」（L1/L2 40/60 为单步战术、L3 仅盲注内、L4 为高风险单步；无跨盲注构建/经济/恢复场景）；③§3 指标体系**重组为五层**（只重组已有指标，**不新增指标实现**），③④ 两层登记 W3 候选；④覆盖事实以 `scenarios/RULES_VERSION` 的 `excluded` 与 `long_horizon_pillars` 为准。

## 1. 场景集组成（60 个决策点）

### 1.1 来源构成（v3.0 核心变更）

| 类别 | 数量 | 来源（`origin`） | 说明 |
|---|---:|---|---|
| **R 类：真游戏锚点** | 30 | `real_capture` | 从真游戏 Ante 1（Red Deck / White Stake）捕获；覆盖无 Joker / 单 Joker / 双 Joker / 含 ×Mult / 多弃牌 |
| **C 类：真游戏反事实变体** | 30 | `real_counterfactual` | 在锚点局面 `load` 后执行不同合法动作、真游戏实测得分后入集；覆盖“同一局面、不同选择”的 oracle 对照 |
| 合计 | **60** | — | 与旧计划 60 场景规模一致；**不再由引擎“生成后直接入集”** |

> 每个决策点必须有真游戏 `capture_id` 与 `saved_state`（`save` 存档路径或脱敏引用），否则不得入集（A4）。

### 1.2 难度分层（语义改为“决策难度”）

| 层 | 数量 | 构造 | 测的能力 | 决策点 |
|---|---:|---|---|---|
| **L1 基础** | 20 | 单回合、无 Joker、标准牌型 | 会不会选最优牌型 | play |
| **L2 组合** | 20 | 1–2 个 vanilla Joker，涉及 +Chips / +Mult / ×Mult 的取舍 | 懂不懂机制与优先级 | play |
| **L3 长程** | 15 | 同一盲注内多次 play / discard（真游戏捕获的连续决策点） | 盲注内资源使用顺序、短程前瞻（**不跨盲注**） | play / discard |
| **L4 极限** | 5 | 高目标 / 必须搏特定牌型；**仍以真游戏可回放为前提** | 风险决策 | play / discard |

> 层数量以 07 §5.1 为准（20/20/15/5 = 60，与 00 D5 一致）。任何调整必须先改 07 再改本文。
> **为什么不是 280**：3 组配置 × 60 场景 = 180 局已是旧口径；v3.0 主实验再压到每组 30 场景（见 §4.2），并新增真游戏终验 12 局。**宁可 60 个可信，不要 280 个跑不完。**

**当前分层的定位缺口（v4.0 登记，不得据此声称已覆盖长线规划）**：

- **L1 基础（20）+ L2 组合（20）= 40/60 是单步战术**：一个局面、一次 `play` 决策，考的是“这一手选得对不对”，**不涉及**跨回合安排。
- **L3 长程（15）只是“同一盲注内”的多次 play/discard**：有“剩余出牌/弃牌怎么用完”的盲注内顺序，但**不跨盲注**、不涉及商店/金钱/利息等经济取舍、不涉及构建路径。
- **L4 极限（5）是高风险单步**：目标高、需要搏特定牌型，但仍是**单个决策点**，不是长程规划。
- **当前没有**跨盲注长期构建场景、经济取舍场景（`money` / `interest` / `shop_money` 在 `RULES_VERSION.excluded`；shop 仅免费三选一；`hands/discards` 每盲注重置）、失败恢复场景（无“先失败后重新规划”的构造与恢复率指标）。

> 因此本轮只能声称“**单步战术 + 盲注内多步**”（L1/L2 单步、L3 盲注内、L4 高风险单步），**不能**声称已覆盖“长线规划”。四支柱（跨回合资源分配 / 长期构建 / 失败恢复 / 长线指标）**均未覆盖**，统一登记为 **W3 场景改造候选**（事实来源：[README](../../README.md)「定位与当前实现差距」、`scenarios/RULES_VERSION` 的 `long_horizon_pillars`）。

### 1.3 三轴标签（v2.1 新增，v3.0 保留）

除难度层 `L1–L4` 外，每个场景额外打三个**正交标签**，用于“按能力维度”而不是“按游戏场景”分组报告（避免“L3 的 regret 高”这类无法解释的结论）：

| 标签 | 取值 | 用途 |
|---|---|---|
| `decision_depth` | 1（单步）/ 2–3（短程）/ ≥4（长程） | 看 regret 是否随步数上升 |
| `branch_count` | 该局面的合法动作数（v3.0 通常为 **218**，8 张手牌全枚举；弃牌另计） | 看 regret 是否随选择空间扩大上升 |
| `horizon_need` | 0（只看当前）/ 1（看下一手）/ 2（看下一盲注） | 看“前瞻需求”是否与规划不足类失败相关 |

> 标签由捕获/变体流水线自动写入，人工只复核 10 个样本。报告里允许按任一轴分组，但**同一张表内只能用一个轴**（避免多重比较）。

## 2. 场景 Schema（v3）

> 与 07 §5.2 完全一致；`schema_version: 3`。Agent 可见字段只有 `initial_state` 的渲染文本；`oracle`、`available_actions`、`validation` 仅评测器使用。

```jsonc
{
  "scenario_id": "L2-0007",
  "schema_version": 3,
  "origin": "real_capture",              // real_capture | real_counterfactual
  "game": {
    "version": "1.0.1o",
    "build_id": "...",
    "deck": "RED",
    "stake": "WHITE",
    "seed": "ABC123",
    "capture_id": "cap-20261120-001",
    "saved_state": "data/realgame/saves/cap-...-step03.jkr"   // 仅脱敏引用/哈希，不入库原始存档
  },
  "initial_state": { /* GameState 投影 */ },
  "available_actions": ["play:c3h,c7s", "discard:c5d"],  // 稳定卡牌 id
  "oracle": {
    "best_actions": ["play:c3h,c7s"],
    "best_score": 68,
    "exact": true,                        // true 仅当所有合法动作都在真游戏验证过
    "validated_actions": 218,             // 真游戏实际执行并记录的动作数
    "unvalidated_actions": 0
  },
  "validation": {
    "engine_score_equals_real": true,
    "legal_actions_match": true,
    "state_transition_match": true,
    "evidence": "evidence/W3/align/L2-0007.json"
  },
  "tags": { "decision_depth": 1, "branch_count": 218, "horizon_need": 0 },
  "expected_constraints": { "max_steps": 12, "must_finish": true },
  "metadata": {
    "rules_version": "3.0-vanilla-subset",
    "notes": "同花顺陷阱：手牌含 4 张同花"
  }
}
```

> 动作一律用**稳定卡牌 id**（见 02 §4）；手牌下标快照仅用于展示与对照 balatrobot，**不参与判定与重放**，也不能作为回放主键（07 §4.2）。

### 2.1 Oracle 精确性规则（v3.0 新增）

- `exact: true`：该局面**全部 218 个合法动作**都在真游戏回放并记录得分（成本高，只做少量，如 6 个 L1 局面）。
- `exact: false`：只验证 **top-k（k=3）+ 2 个随机动作**；`best_actions` 是“**已验证动作中的最优**”，报告必须写“oracle 为已验证子集最优，**不是全局最优**”。
- `best_score == 0` 的局面不进入 regret 分母，单独计数。
- **禁止**把 `exact: false` 的 oracle 写成“全局最优”，也禁止把 `validated_actions` 写成“全部动作”。

### 2.2 入集门槛 G1–G6（缺一不可）

- [ ] **G1 版本/来源完整**（A0）：`game.version` / `build_id` / `deck` / `stake` / `capture_id` / 依赖版本齐全；
- [ ] **G2 状态字段可映射**（A1）：`gamestate` ↔ `GameState` 逐字段 diff 通过；
- [ ] **G3 至少一个动作的真游戏分数与引擎分数一致**（A2；全动作一致才可标 `exact`；证据填 `docs/engine-fidelity.md` **A 表（真游戏捕获）+ B 表（`save`/`load` 反事实回放）**；第三方抽检见附录 D，辅助）；
- [ ] **G4 合法动作集一致**（A1/A3）；
- [ ] **G5 状态转移覆盖字段一致**（分数、手牌、剩余出牌/弃牌；牌堆只比计数）；
- [ ] **G6 证据文件存在且可重放**（`evidence/W3/align/<scenario_id>.json`）。

不满足任一项 → 进 `rejected` 清单并写原因，**不得**用“先入集、以后补验证”绕过。

## 3. 指标体系（v4.0：五层结构）

> **五层口径**：指标按“门禁 → 能力 → 解释”分为五层——① 合规门禁层、② 单步战术层、③ 跨期资源分配层、④ 长程进度/失败恢复层、⑤ 诊断解释层。**当前只有 ①②⑤ 有定义与（部分）实现路径；③④ 均未覆盖**（登记 W3 候选，见 §3.3 / §3.4）。
> **硬约束（v4.0）**：Local Regret 只衡量单步，**不得单独用来支撑“长线规划”主张**；长线结论须由 ③④ 层指标支撑（当前均未覆盖）。本节只**重组**已有指标并逐层标注“当前覆盖/缺口”，**不新增任何指标实现**；指标定义与 exact/approx 标注与原表一致。

| 层 | 指标 | 当前是否覆盖 | 证据 / 缺口 |
|---|---|---|---|
| **① 合规门禁层** | Legality Rate、非法动作计数 | ⚠️ 定义已定、可直接算 | trace 的 `tool/result.isError` + 工具白名单（对应 04 §3 F1 `LEGAL_001/002`）；**无独立指标表产物（📋）** |
| **② 单步战术层** | Local Regret（主）、Action Optimality、Discard EV Gap | ✅ 单步已覆盖 | O1 精确 argmax（全部合法动作）+ O2 弃牌 EV 采样（approx）；**只覆盖单个决策点**，不跨回合 |
| **③ 跨期资源分配层** | 跨回合资金 / 利息 / 商店经济取舍 | ❌ **未覆盖** | `money` / `interest` / `shop_money` 在 `RULES_VERSION.excluded`；shop 仅免费三选一（无价格/购买/出售/reroll）；`hands/discards` 每盲注重置、不跨期积累 → 登记 **W3 指标候选** |
| **④ 长程进度/失败恢复层** | Episode Progress、失败恢复率、Pass^k | ⚠️/❌ 粗粒度 / 未定义 | Episode Progress 只数“通过盲注档数 / 3”，粒度粗；**失败恢复率未定义/未实现**；`Pass^k` 已取消 → 登记 **W3 指标/场景候选** |
| **⑤ 诊断解释层** | 首次失败步、F1–F4 / F0、E1 `env_divergence` | ⚠️ 设计已定、实现 📋 | `bench/attrib.py` 未创建（W4）；F4 为 heuristic；**E1 是数据质量门禁、非 Agent 失败类**，单独统计 |

### 3.1 ① 合规门禁层（当前覆盖：已定义，可直接算）

| 指标 | 定义 | 计算 | 适用 | 精确性 | 局限 |
|---|---|---|---|---|---|
| **Legality Rate** | 合法调用 / 总调用 | trace 统计 | 全部 | exact | 只反映协议层 |
| **非法动作计数** | `tool/result.isError` 条数 + 白名单外工具调用条数（= 04 的 F1 命中数） | trace 逐条计数 | 全部 | exact | 计数依赖工具白名单版本；是门禁，不是能力指标 |

### 3.2 ② 单步战术层（当前覆盖：单步，主指标层）

| 指标 | 定义 | 计算 | 适用 | 精确性 | 局限 |
|---|---|---|---|---|---|
| **Local Regret**（主） | `(best − actual) / best` | 仅对 `play` 决策；用 O1 | L1–L4 | exact（**相对已验证动作集**） | 只衡量“这一步”；若 `oracle.exact=false`，只能报“已验证子集 regret 下界”；**不能外推为长线规划能力** |
| **Action Optimality** | 命中最优动作的比例（并列算命中） | `hits / play_decisions` | L1–L4 | exact（同上） | 对“次优但接近”不敏感；`exact=false` 时“最优”仅指已验证子集 |
| **Discard EV Gap**（辅） | `(EV_best − EV_actual) / EV_best`，用 O2 的 `mean` | 仅 `discard` 决策 | L3 | **approx** | MC 误差，须同时报 `min/max` 区间 |

> 本层回答“单个决策点选得对不对”，**不回答**“跨回合安排是否合理”。L3 的 Discard EV Gap 仍是**同一盲注内**的一次选择，不是跨期资源分配。

### 3.3 ③ 跨期资源分配层（当前覆盖：**未覆盖**）

**事实**（证据来源：`scenarios/RULES_VERSION` 的 `excluded` 与 `long_horizon_pillars`）：

- `money` / `interest` / `shop_money` 在 `RULES_VERSION.excluded` 明列，**训练集不得构造依赖金钱/利息的局面**；
- 引擎的 shop 只做“免费三选一 Joker”，无价格、购买、出售、reroll；
- `hands` / `discards` 每盲注固定重置（4/2），**不跨期积累**，因而不存在“省资源到下一盲注”的取舍。

**缺口**：没有“跨盲注资源调度”“经济取舍”“构建路径”的指标定义，也没有对应场景；因此**不能用现有指标声称跨回合资源分配能力**。

**登记**：W3 指标候选（跨期资源效率、商店决策收益差、跨盲注构建路径）——**仅为候选方向，定义与实现均未开始**，不得作为本轮交付项。

### 3.4 ④ 长程进度/失败恢复层（当前覆盖：部分 / 未定义）

| 指标 | 定义 | 计算 | 适用 | 精确性 | 当前覆盖/缺口 |
|---|---|---|---|---|---|
| **Episode Progress** | 通过的盲注档数 / 3 | 终局统计 | L3 | exact | **粒度粗、方差大**；只能看“走了多远”，看不出“为什么没走远”，小模型常恒为 0 |
| **失败恢复率** | （待定义） | — | — | — | **未定义/未实现**：无“先失败、后恢复”场景构造，也无恢复率/恢复代价定义 → W3 指标/场景候选 |
| **Pass^k（子集）**（v2.1 历史，**v3.0 取消**） | 同一场景独立跑 k 次全部成功的比例 | 原计划 L1 10 场景 × k=3 | — | — | 已被 v3.0 取消（为真游戏终验腾时间）；留作历史，不得再作为交付项 |

> 本层是**长线规划主张的主要证据层**，当前**不成立**：进度指标粒度粗、失败恢复率未定义、Pass^k 已取消。

### 3.5 ⑤ 诊断解释层（当前覆盖：设计已定，实现 📋）

| 指标 | 定义 | 计算 | 适用 | 精确性 | 局限 |
|---|---|---|---|---|---|
| **首次失败步** | regret 首次超过阈值（默认 0.5）的步序号 | 从 `episode.jsonl` 扫描 | L2–L4 | exact | 阈值须在预注册中冻结 |
| **失败类型分布 F1–F4 / F0** | 按 04 的分类学统计每类占比；F4 为 **heuristic** | trace × 判定器 | 训练集 + 真游戏 | F1–F3 exact / F4 heuristic | F4 只作分组，**不进任何显著性检验** |
| **`env_divergence`**（v3.0，**E1 / 非 Agent**） | 真游戏结果与训练环境预期不一致的次数/占比 | 终验 trace × 对齐台账比对 | 真游戏终验 | exact（可用适配器状态判定） | **数据质量门禁，不是 Agent 失败类**；不进 Agent 失败率，单独报；见 04 §2.1 |

> 本层只解释“错在哪类、哪一步”，**不承担能力结论**；它是错误分析章节 / 题目元数据的素材，不是主结果。

### 3.6 跨环境与成本指标（不属于五层，单列）

| 指标 | 定义 | 计算 | 适用 | 精确性 | 局限 |
|---|---|---|---|---|---|
| **Cost / Latency** | 每局 token 数、每局墙钟、每决策延迟 | runner 记录 | 全部 | exact | 受网络波动影响 |
| **`real_vs_training_gap`**（v3.0） | 同一模型在训练集 regret 与真游戏终验表现的方向性差异 | 训练集 regret ↔ `blinds_cleared` / `ante1_win` | 真游戏终验 | **描述性**（n=12） | 样本少，只描述不检验 |

> **报告原则（v3.0 不变）**：主表数字必须同时给 **n、效应量、95% CI**（借鉴 Miller, *Adding Error Bars to Evals*）；近似指标必须带区间，不允许只报点值。
> **真游戏终验指标**（`blinds_cleared` / `ante1_win` / `legality_rate` / `timeout_rate` / `agent_failure_class` / `cost` 等）见 07 §6.3；本文件只定义训练环境指标与两项跨环境指标。

### regret 的边界处理

- `best_score == 0`（不可能得分的局面）→ **不计入 regret**，单独计数并报告（否则分母为 0）。
- Agent 在该出牌时选择了 `discard`（合法但零得分）→ 记 `actual = 0`，regret = 1。
- Agent 未做任何动作即终止 → 该 episode 记 `premature_stop`，不参与 regret 均值，单列比例。
- **`oracle.exact=false`** → 该场景的 regret/optimality 只能作为**已验证子集**的指标，报告中必须带 `exact=false` 标记，不得与 `exact=true` 场景混算同一均值（应分层或分列）。

### 不准做的事

- ❌ 把 Episode Progress 当主指标（小模型恒 0，测不出差异）
- ❌ 用 Discard EV Gap 下强结论（它是近似）
- ❌ 把不同难度层的 regret 混在一起算平均（分层报告）
- ❌ 把 `env_divergence` 计入 Agent 失败率或 regret（它是环境问题，不是 Agent 决策错误）
- ❌ 把单步 Local Regret 写成“长线规划能力”证据（它只衡量单步；长线结论须由 ③④ 层指标支撑，当前均未覆盖）
- ❌ 把 ③④ 层的“未覆盖”写成“已覆盖/部分覆盖长线规划”（只能写“目标能力，尚未覆盖，登记 W3 候选”）

## 4. 配对实验设计

### 4.1 三组配置

| 组 | 模型 | Prompt | 说明 |
|---|---|---|---|
| **A** | 本地 4B（q4） | 直接要求给出动作 | 下界基线 |
| **B** | 本地 4B（q4） | 先推理后给动作（CoT） | 测 CoT 对小模型的作用 |
| **C** | 云端模型 | CoT | 测规模差异 |

**配对键**：`(scenario_id, capture_id, model_config_version, prompt_version, tool_version)`
→ 同场景、同真游戏捕获状态、同工具描述，**只变模型/Prompt**。v3.0 用 `capture_id` 取代旧 `seed` 作为局面身份（D13：不复刻 RNG，局面身份来自真游戏捕获）。

### 4.2 样本量（power analysis，事前做；v3.0 规模已定）

- **训练集主实验**：3 组 × **30 场景** = **90 局**（每场景 1 次）。60 个决策点是**场景池**，主表实际纳入的 30 个场景及其选取规则必须在预注册中冻结（📋），不得事后更换。
- **真游戏终验**：3 组 × **4 局** = **12 局**，只做描述统计（详见 07 §6.1、05 §1.2）。

```python
# 用 pilot（10 局/组）估 regret 的配对差值标准差 σ_d
# n = ((z_{1-α/2} + z_{1-β}) * σ_d / Δ)²
# 例：σ_d=0.25, Δ=0.10, α=0.05, β=0.2 → n ≈ 50 / 组
# v3.0 每组只有 30 场景 < 50 → 事前就按“描述统计 + CI”写预注册，不承诺显著性
```

若需要的 n > 30（每组场景数上限），**降低主张**：只报描述统计 + 置信区间，不做“显著优于”的结论。

### 4.3 统计方法

| 比较对象 | 方法 | 输出 |
|---|---|---|
| regret（连续、配对） | Wilcoxon signed-rank | p、rank-biserial 效应量、bootstrap 95% CI |
| optimality / legality（二值、配对） | McNemar | p、差值 CI |
| 三组两两比较（3 次） | **Holm 校正** | 校正后 p |
| 失败类型分布 | 卡方 / Fisher（样本够时） | 占比 + CI |
| 真游戏终验（n=12） | **只做描述统计 + bootstrap 95% CI** | 分布、均值/中位数与区间；**不做显著性主张**，不报 p 值 |

**必须同时报**：样本量、效应量、CI。只报 p 值的结论不接受。

### 4.4 Pass^k 子集（v2.1 历史，**v3.0 取消**）

- **取消原因**：为真游戏终验（12 局，约 4–6h）腾预算；`00` v3.0 ⑥ 已明确“取消 Pass^k 子集”。
- **历史设计（仅留档，不得再作为交付项）**：L1 的 10 个场景 × k=3 × 3 组 = 90 局，或按 60 场景 × k=8 不可行。
- **纪律**：不得在跑完主实验后“顺手补做”并当作结论；若未来恢复，必须重新预注册并单列，不与 regret 混报。
