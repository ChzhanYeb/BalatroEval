## 0. 术语

| 术语 | 含义 |
|---|---|
| 训练/开发环境（ATE） | 自建的快速、确定性、规则为 vanilla 严格子集的训练/开发环境（`bench/` + `evaluation/`） |
| 真实游戏终验（RGFT） | 用 Balatro + balatrobot 跑的小样本最终环境测试（12 局） |
| 对齐契约（AC） | 自建引擎与真实游戏之间的五级检查清单：A0 版本 / A1 schema / A2 单步分数 / A3 规则子集 / A4 场景来源与回放 |
| 对齐等级 L0–L3 | L0 未对齐 / L1 分数对齐 / L2 规则子集对齐 / L3 真游戏终验通过 |
| ATS | 对齐训练集：60 个决策点（30 真游戏锚点 + 30 反事实变体），当前未创建 |
| 场景 / episode | 一个固定初始局面 + 合法动作集 + oracle；episode 是 Agent 从初始局面到终止的完整交互序列 |
| Local Oracle / Local Regret | 仅基于当前手牌的精确最优出牌；`(oracle分 − agent分)/oracle分`，只在 play 决策上定义 |
| Trace | `evaluation.trace` 的 JSONL 事件流（schema 2），含 state hash、决策指标、错误与延迟 |
| 诊断报告层 | 把一次失败映射到 F1–F4/F0 诊断标签并附证据；**不是主定位** |
| 环境分歧（E1） | 真游戏结果与训练环境预期不一致；数据质量门禁，不是 Agent 失败类 |

## 1. 项目定位

BalatroEval 用可判定、可复现的 Balatro 规则子集评测 Agent 的四个能力维度：

| 维度 | 含义 | 当前是否覆盖 |
|---|---|---|
| 跨回合资源分配 | 跨盲注/跨回合分配有限资源（出牌、弃牌、金钱、商店取舍） | **载体已就绪、指标未定义**（v2 已实现金钱/利息/付费商店；money 跨盲注保留；无跨期效率指标与场景集） |
| 多步决策 | 在一局内做多步 play/discard 决策 | **部分**：单盲注内多步可跑，但无 ATS 场景集 |
| 长期构建 | 沿 build 路径做 Joker/卡组协同的长期投资 | **未覆盖**（商店能买 Joker，但无 build 路径场景与评分） |
| 失败恢复 | 失败后重新规划并恢复 | **未覆盖**（经济给了构造前提，但未构造场景） |

环境可信由两阶段保证：

```text
自建训练/开发环境（快、可枚举、可 CI）
        │  对齐契约 A0–A4：版本 / schema / 单步分数 / 规则子集 / 场景来源
        ▼
真实游戏终验（慢、不可并行、最终证据）
```

**规则实现完成 ≠ 与真游戏对齐验证完成。** 当前 `fidelity_status: NOT_VERIFIED`、`alignment_level: L0`。

## 2. 目标与非目标

### 目标（按优先级）

| # | 目标 | 验收形态 |
|---|---|---|
| G1 | 规则、状态、算分与真游戏对齐 | A1–A3 通过：覆盖局面上单步分数 100% 一致、合法动作集一致、状态字段可映射；`docs/engine-fidelity.md` 有实测行 |
| G2 | Agent 能通过 MCP 完成真实多步交互 | 训练环境一局完整 episode（≥3 次工具调用）+ 真游戏适配器一局 Ante 1 的 trace |
| G3 | 小规模、固定版本、与真游戏对齐的训练/开发集 | 60 个决策点，每个带 oracle、合法动作集、三轴标签、来源与验证证据 |
| G4 | 指标可信且可解释 | 每个指标有定义、局限说明、`exact/approx` 标注与 95% CI；主指标并报首次失败步分布 |
| G5 | 诊断报告层（非主目标） | F1–F3 合规/规则理解、F4 规划（heuristic）、F0 证据不足、E1 数据质量门禁；判定器 + 证据链 + κ/CI |
| G6 | 可复现的配对实验 + 统计报告 | 训练集 3 组 × 30 场景 = 90 局 + 真游戏 3 组 × 4 局 = 12 局；一条命令重跑主表 |
| G7 | 与已有工作划清界限且合规 | 显式覆盖 Evalatro / `coder/balatrobench` / `balatro-rs` / EXAG 2026 前作 / balatrobot；数据来源可查；遵守 L7–L9 |
| G8 | 真实游戏最终环境测试成立 | 12 局终验有完整 trace、指标与诊断标签；小样本只做描述统计；未完成则如实写“未执行” |

### 非目标

- 不训练/微调模型；不改造推理引擎；不追求本地小模型性能。
- **不把真实游戏作为批量主环境**；真游戏只做最终小样本终验（12 局）。
- 不做“自动通关”型 Agent（求解器只提供 Ground Truth）。
- 不引入额外编排框架；不让 LLM Judge 进入主指标或归因判定。
- 不复刻原版 RNG；训练集用真游戏捕获的固定局面，不声称“与真游戏同种子同局面”。
- 不引入 GPL 代码、不搬运 CC BY-NC-SA 文本、不把游戏文件/存档/截图提交到仓库。

## 4. 系统架构

```text
┌──────────────────────────────────────────────────────────────────────┐
│  dsh / 评测脚本（被测 Agent 只能看到 MCP 工具）                        │
└───────────────┬──────────────────────────────────┬───────────────────┘
                │ MCP (stdio)                      │ MCP (stdio)
┌───────────────▼──────────────────┐  ┌────────────▼───────────────────┐
│ 阶段一：训练环境 bridge/server.py │  │ 阶段二：终验 bridge/realgame.py │
│  · 5 工具（get_state/play_cards/ │  │  · 5 工具（含 shop_action/     │
│    discard_cards/choose_joker/   │  │    advance_phase）📋 规划       │
│    reset_episode）               │  │  · 薄壳：校验 → balatrobot RPC │
│  · 薄壳：校验 → bench.tools     │  └────────────┬───────────────────┘
└───────────────┬──────────────────┘               │ HTTP JSON-RPC 2.0
                │ import（同进程，零 RPC）          │
┌───────────────▼──────────────────┐  ┌────────────▼───────────────────┐
│ bench/ ← 训练环境唯一规则权威     │  │ Balatro（Steam 1.0.1o）        │
│ rules_version/model/hand_eval/   │  │ + Lovely + Steamodded          │
│ scoring/jokers/engine/actions/   │  │ + balatrobot（:12346）         │
│ environment/observation/tools/   │  │ 真实游戏：最终环境测试          │
│ oracle/serialize/rng/errors      │  │ （不实现第二份规则）            │
└───────────────┬──────────────────┘  └────────────┬───────────────────┘
                │ 产物                              │ 产物
      runs/<run_id>/{manifest,results,traces}       runs/w5-real/<run_id>/
      scenarios/v3/*.jsonl（📋）                    evidence/W3/align/*.json（📋）
```

**架构决策**：

- **训练环境与终验环境分离**：训练环境追求“快、可枚举、可 CI”；终验环境追求“真”。两者只共享动作语义与状态 schema 投影。
- **规则只有一份实现**：`bench/` 是唯一规则实现；`evaluation`/`scenarios`/`bridge` 只做调度、校验、转发，不复算分数。
- **真游戏适配器是薄壳**：只做 JSON-RPC、字段映射、动作 id↔下标转换、统一错误码。
- **完整性校验**：`evaluation` 已提供 manifest + code hash + state hash；真游戏终验另记 `game_version`/`capture_id`/`adapter_version`。

**📋 规划的 W3 模块**：

| 模块 | 职责 |
|---|---|
| `bench/realgame.py` | balatrobot JSON-RPC 客户端（health/gamestate/start/save/load/play/discard/…） |
| `bench/convert.py` | `gamestate` ↔ `GameState` 字段映射、稳定 id ↔ 下标 |
| `bench/capture.py` | 捕获真游戏决策点、存档、写 `evidence/W3/align/` |
| `bench/align.py` | 引擎重放 + 分数/动作/状态三项 diff，生成入集/拒绝清单 |
| `scenarios/v3/` | 对齐后的 60 个决策点 + `MANIFEST.json` |
| `bridge/realgame.py` | 真游戏 MCP 薄壳（5 工具） |

## 5. 核心技术决策

| # | 决策 | 选择 | 理由 / 风险 |
|---|---|---|---|
| D1 | 评测环境 | **两阶段：自建训练 + 真游戏终验** | 真游戏无法批量、不可 CI；纯自建无法回答外部效度 |
| D2 | 是否接入真游戏 | **接入 balatrobot（MIT），只做终验与捕获** | `save`/`load` 可做反事实回放；风险是四层依赖与版本脆弱 |
| D3 | Oracle 层级 | **Local 精确 + 弃牌 EV 近似（三态）** | 出牌 218 组合可精确枚举；整局最优不可行 |
| D4 | 主指标 | **分层**：合规门禁 → 单步战术（Local Regret 主）→ 跨期资源（未覆盖）→ 长程/恢复（未覆盖）→ 诊断解释 | 连续、低方差；单步 regret 不能支撑“长线规划”主张 |
| D5 | 评测集规模 | **60 个决策点**（L1 20 / L2 20 / L3 15 / L4 5）；训练集 90 局 + 真游戏 12 局 | 本机算力上限；事前 power analysis，不足则只报描述统计 + CI |
| D6 | 工具形态 | 训练环境 **5 个工具**（含 `reset_episode`）；真游戏终验 5 个；动作绑定稳定卡牌 id | 小模型上下文有限；两套工具动作语义一致 |
| D7 | 规则实现位置 | **`bench/` 唯一实现**；真游戏侧只读 | 双实现必漂移 |
| D8 | 诊断层标签 | F1–F4 + F0 + E1（数据质量门禁） | LLM 判定不可复现；只作诊断报告层 |
| D9 | 实验矩阵 | **3 组**（本地直答 / 本地 CoT / 云端 CoT）；90 + 12 局 | 保留 CoT 对照；终验样本少 |
| D10 | 统计方法 | **配对 Wilcoxon + McNemar + Holm + bootstrap CI**；真游戏只做描述统计 | 配对、非正态、多次比较；n=12 不做显著性 |
| D11 | 种子与保真度口径 | **不复刻 RNG；训练集局面来自真游戏捕获**（captured-state alignment） | 复刻成本高且随版本漂移；seed 只保证真游戏内可复现 |
| D12 | 数据来源与许可 | **建立来源清单**；数值取 Wiki/HQ、描述自写、不引入 GPL 代码、不搬运 CC 文本 | 见 `docs/data-sources.md`；L7–L9 |
| D13 | 结果完整性 | **manifest + code hash + state hash**；真游戏另加版本哈希 | 结论可被第三方复算 |
| D14 | 真实游戏终验协议 | **小样本终验**：3 组 × 4 局 = 12 局，Ante 1，单局上限 15 分钟 | 不可达则降级 `CAPTURE_REPLAY_ONLY` 并如实声明 |

## 6. 主要风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 真游戏四层依赖装不上/版本断链 | 终验无法执行 | 先做 `health`/`gamestate` 冒烟；失败即降级 `CAPTURE_REPLAY_ONLY` |
| 真游戏单局慢、不可并行 | 终验样本少 | 只跑 12 局；训练集靠捕获+回放 |
| 自建引擎与真游戏规则仍不一致 | 训练集 oracle 错 | A2/A3 对齐契约；每个入集局面三项 diff；不一致追根因或排除 |
| 训练集自建变体无法回放 | 场景不可信 | `save`/`load` 在真游戏执行变体；每个变体有 `real_game_score` |
| 12 局终验被误读为“显著” | 结论夸大 | 预注册写“描述统计”；限制章单列 n=12 |
| 游戏文件/截图入库 | 许可/分发风险 | L8：只提交脱敏 JSON、分数、trace、版本清单 |
| 归因把环境分歧算成 Agent 错 | 归因失真 | E1 单列，优先级最低 |
| 扩功能导致 W3 延期 | 全局崩 | 每周 20h 上限 + 砍单顺序（见 01）；真游戏接入不可砍 |

## 7. 与已有工作的关系

完整逐项评估与许可边界见 **[06-生态调研与复用决策.md](详细版/06-生态调研与复用决策.md)**。一句话区分：

- **Evalatro**：真游戏 + LLM 基准，只给一个总分；本项目做分层指标 + oracle/regret + 诊断层，**定位对照、方法借鉴**。
- **`coder/balatrobench`**：排行榜/结果展示站点，与本项目无隶属；只在“相关工作”一句客观区分。
- **`coder/balatrobot`**：真游戏 JSON-RPC 控制面（MIT），本项目只作终验/捕获适配层，不改源码。
- **`balatro-rs`**：离线 Rust 规则引擎（无许可证），只作设计对标，不复制。
- **EXAG 2026 前作**：Rust 模拟器 + PPO，用训练曲线评测；本项目把“长线规划测试集 + 对齐训练环境 + 真游戏终验”作为差异。
