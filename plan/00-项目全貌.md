## 1. 项目定位

> 用一个**规则可判定、分数可精确计算**的卡牌游戏环境，评测 LLM Agent 的**多步决策能力**，
> 并给出**可自动判定的失败归因**；最后用**真实游戏**回答“这个结论离开自建环境还成立吗”。

三个关键词，缺一不可：

| 关键词 | 含义 | 为什么重要 |
|---|---|---|
| **可判定**（decidable） | 训练环境的规则与分数由确定性程序给出，不依赖人评或 Judge | 评测结论可复现、可反驳 |
| **多步决策**（long-horizon） | 不是单轮问答，要跨回合分配有限资源 | 这正是 Planning 的可测形式 |
| **归因**（attribution） | 不只给分，还要回答“为什么错、错在哪一类” | 评测岗的核心交付，也是本项目与已有工作的分界 |

v3.0 增加第四个关键词：**对齐**（aligned）。不是“再做一个模拟器”，而是：

```
自建训练环境（快、可枚举、可 CI）
        │  对齐契约 A0–A4：版本 / schema / 单步分数 / 规则子集 / 场景来源
        ▼
真实游戏终验（慢、不可并行、最终证据）
```

**不是**：自动打牌 Agent、Balatro 攻略、模型训练/微调、推理引擎优化、排行榜产品、完整 Balatro 复刻。

### 1.1 命名（D12 最终确认）

- **正式名**：`BalatroBench — Balatro 子集的可判定评测与失败归因`
- **中文简称**：`BalatroBench 可判定评测与失败归因`
- **英文副标题**：`A Decidable Evaluation and Failure-Attribution Benchmark for Long-Horizon Agents`
- **仓库/包名**：`balatrobench`（代码命名不变，避免破坏 W2 基线）
- **备选名**：`CardBench-Attrib`（若同名冲突仍造成评审误判，改用此名；不再使用不含“归因”的 `CardBench-Lite`）
- GitHub 已有同名 `coder/balatrobench`（BalatroLLM 对局记录的排行榜/结果分析工具，做展示不做判定）。本项目与它**同名不同目标**：它回答“谁分高”，本项目回答“为什么低、错在哪类决策”。所有对外材料**必须带副标题**，且首段显式区分。

## 2. 目标与非目标

### 目标（按优先级）

| # | 目标 | 验收形态（v3.0） |
|---|---|---|
| G1 | 规则、状态、算分与真游戏对齐 | 单测全绿 + **A1–A3 对齐契约**通过：覆盖局面上单步分数 100% 一致、合法动作集一致、状态字段可映射；`docs/engine-fidelity.md` 有实测行；当前 **L0，目标 W3 达 L2** |
| G2 | Agent 能通过 MCP 完成真实多步交互 | 训练环境一局完整 episode（≥3 次工具调用）+ **真实游戏适配器**一局 Ante 1 的 trace（≥3 次工具调用），工具带前置状态校验与统一错误码 |
| G3 | 有一套小规模、固定版本、**与真游戏对齐**的训练/开发集 | 60 个决策点（30 真游戏锚点 + 30 真游戏反事实变体），每个带 oracle、合法动作集、三轴标签、**来源与验证证据**；未通过 A1–A4 的局面不得入集 |
| G4 | 指标可信且可解释 | 每个指标有定义、局限说明、`exact/approx` 标注与 **95% CI**；主指标并报 Pass^k（若保留）与首次失败步分布 |
| G5 | **4 类 Agent 失败 + 1 类环境分歧**能自动判定 | F1–F4 + F0，另设 `env_divergence`（非 Agent 失败）；判定器 + 证据链（`rule_id` / `state_hash` / 最小反例）+ per-class Cohen's κ + 95% CI + 混淆矩阵 + 弃权率 |
| G6 | 一组可复现的配对实验 + 统计报告 | 训练集 3 组 × 30 场景 = 90 局 + **真实游戏 3 组 × 4 局 = 12 局**；一条命令重跑训练集主表；报告含“相关工作与差异化”和“真实环境终验”两节 |
| G7 | 与已有工作划清界限且合规 | 报告显式覆盖 Evalatro / `coder/balatrobench` / `balatro-rs` / EXAG 2026 前作 / balatrobot；数据来源与许可清单可查；遵守 L7–L9 |
| **G8** | **真实游戏最终环境测试成立** | 12 局真游戏终验有完整 trace、指标与失败归因；小样本只做描述统计；未完成则如实写“未执行”，不得用训练集替代 |

### 非目标（明确不做）

- 不训练/微调模型（SFT、RL 一律不做）；“训练集”仅指 Agent 开发/评测用场景集
- 不改造推理引擎；不追求 8GB 本地大模型性能
- **不把真实游戏作为批量主环境**；真游戏只做最终小样本终验（12 局）
- 不做完整规则复刻；只做 vanilla 的严格子集（Ante 1、Red Deck、White Stake、8 个 Joker）
- 不做“自动通关”型 Agent（求解器只提供 Ground Truth，不替 Agent 决策）
- 不引入 LangGraph 等额外编排框架
- 不让 LLM Judge 进入主指标或归因判定
- 不在 100h 内追求完整 Balatro 策略求解
- 不做排行榜/结果展示产品（该位置已被 `coder/balatrobench` 与 Evalatro 占据）
- **不复刻原版 RNG**；训练集用真游戏捕获的固定局面，不声称“与真游戏同种子同局面”（见 D13）
- 不引入 GPL 代码、不搬运 CC BY-NC-SA 文本、不把游戏文件/存档/截图提交到仓库（见 D14 / L7–L9）

## 3. 系统架构

```
┌──────────────────────────────────────────────────────────────────────┐
│  dsh（Headless，Windows 原生）                                        │
│  被测 Agent：只能看到工具，看不到文件系统/Shell/Oracle                │
└───────────────┬──────────────────────────────────┬───────────────────┘
                │ MCP (stdio)                       │ MCP (stdio)
┌───────────────▼──────────────────┐  ┌────────────▼───────────────────┐
│ 阶段一：训练环境 bridge/server.py │  │ 阶段二：终验 bridge/realgame.py │
│  · 4 工具（get/play/discard/     │  │  · 5 工具（+ shop_action/      │
│    choose_joker）                │  │    advance_phase）             │
│  · 薄壳：校验 → bench.tools      │  │  · 薄壳：校验 → balatrobot RPC │
└───────────────┬──────────────────┘  └────────────┬───────────────────┘
                │ import（同进程，零 RPC）           │ HTTP JSON-RPC 2.0
┌───────────────▼──────────────────┐  ┌────────────▼───────────────────┐
│ bench/  ← 训练环境唯一规则权威    │  │ Balatro（Steam 1.0.1o）        │
│  model / cards / rng / scoring    │  │ + Lovely + Steamodded          │
│  jokers / actions / engine        │  │ + balatrobot（:12346）         │
│  oracle / logging / render        │  │ 真实游戏：最终环境测试          │
│  scenarios / metrics / attrib     │  │ （不实现第二份规则）            │
└───────────────┬──────────────────┘  └────────────┬───────────────────┘
                │ 产物                              │ 产物
      runs/<run_id>/episode.jsonl          runs/w5-real/<run_id>/
      scenarios/v3/*.jsonl                 · episode.jsonl
      evidence/W3/align/*.json             · state snapshots / screenshots
                                           · real_game_scores.jsonl
```

**关键架构决策**：

- **训练环境与终验环境分离**：训练环境追求“快、可枚举、可 CI”；终验环境追求“真”。两者不共享规则实现，只共享**动作语义**与**状态 schema 投影**。
- **不分服务、不写 DSH 原生插件**：训练环境的 MCP Server 与规则引擎在同一个 Python 包里，靠 `import` 连接；真游戏适配器是独立薄壳，不 import `bench` 的规则。
- **规则只有一份实现**：训练环境的 `bench/` 是唯一规则实现；真游戏侧只读 `gamestate` 与动作结果，不做规则复算。
- **完整性校验**：`bench/report.py` 仍保留两道闸——①重放重算；②code hash。真游戏终验额外记录 `game_version`、`capture_id`、`adapter_version` 与状态哈希。

**v3.0 新增模块（规划，W3）**：

| 模块 | 职责 |
|---|---|
| `bench/realgame.py` | balatrobot JSON-RPC 客户端（health/gamestate/start/save/load/play/discard/…） |
| `bench/convert.py` | `gamestate` ↔ `GameState` 字段映射、稳定 id ↔ 下标 |
| `bench/capture.py` | 捕获真游戏决策点、存档、写 `evidence/W3/align/` |
| `bench/align.py` | 引擎重放 + 分数/动作/状态三项 diff，生成入集/拒绝清单 |
| `scenarios/v3/` | 对齐后的 60 个决策点（真游戏锚点 + 反事实变体） |
| `bridge/realgame.py` | 真游戏 MCP 薄壳（5 工具） |

## 4. 核心技术决策

| # | 设计问题 | 备选方案 | 最终选择 | 理由 | 风险 | 验证方法 |
|---|---|---|---|---|---|---|
| D1 | 评测环境用真游戏还是自建 | ①真游戏唯一 ②自建唯一 ③**两阶段：自建训练 + 真游戏终验** ④balatro-rs | **③两阶段** | 真游戏无法批量、不可 CI；纯自建又无法回答外部效度。两阶段把“快”和“真”分开，训练集用真游戏捕获保证对齐 | 两套环境不一致 | A0–A4 对齐契约 + 12 局真游戏终验 |
| D2 | 是否接入真游戏 | 接入 / 不接入 | **接入**（balatrobot；只做终验与捕获，不做批量主环境） | balatrobot 是 MIT 的事实标准，22 个方法 + JSON-RPC + 完整 GameState；`save`/`load` 可做反事实回放，正好解决“训练集对齐”问题 | 四层依赖、版本脆弱、单局慢 | `health`/`gamestate` 冒烟 + 12 局终验 + 版本锁定 |
| D3 | Oracle 层级 | Local / Horizon / Full-episode | **Local（精确）+ 弃牌 EV（近似，三态输出）** | 出牌 218 组合可精确枚举；整局最优不可行，不做；弃牌 EV 用 K=50 抽样并输出 `{mean, min, max}` | 近似部分被误读为精确 | 报告中逐指标标注 `exact`/`approx`，近似值必须带区间 |

| D7 | 规则实现位置 | Python 包 / DSH 插件 / 双实现 | **训练环境 Python 包唯一实现**；真游戏侧只读不实现 | 双实现必漂移；MCP 薄壳只转发；真游戏适配器不写规则 | 单点故障 | 一处改动只需跑一套测试；8 个 Joker 逐一对照语义文档 |

| **D13** | **种子与保真度口径** | ①逐字节复刻原版 RNG ②不复刻、用真游戏捕获固定局面 | **②不复刻 RNG，但训练集局面来自真游戏捕获** | 复刻成本高且随版本漂移；v3.0 不再依赖“同 seed 同局面”，而是直接捕获状态、`save`/`load` 回放；seed 只保证真游戏内可复现 | 被误解为“与真游戏同局面” | 文档统一写“captured-state alignment”；`RULES_VERSION.verified_against` 只写真游戏捕获/回放证据 |

| **D15** | **结果完整性** | 无校验 / 重放重算 + code hash | **重放重算 + code hash**；真游戏终验另加 game/adapter 版本哈希与状态哈希 | 评测结论必须可被第三方复算；防篡改、防“分数与轨迹不一致” | 增加少量实现成本 | 主表出数前强制校验；校验失败即阻断并报错 |
| **D16** | **相关工作与差异化** | 不写 / 报告内一节 | **报告新增“相关工作与差异化”0.5 页** | 生态里已有 Evalatro（总分基准）、`coder/balatrobench`（排行榜）、`balatro-rs`（引擎库）、EXAG 2026 前作（RL 曲线）、balatrobot（控制面），不写清就会被认为重复 | 篇幅 | 必须覆盖这五个对象，并逐条写“它做了什么 / 没做什么 / 我们的差异” |

## 5. 主要风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 真实游戏四层依赖装不上/版本断链 | 终验无法执行 | W3 第一天先做 `health`/`gamestate` 冒烟；失败即降级为“捕获回放验证”，报告写 `CAPTURE_REPLAY_ONLY`，不得声称终验通过 |
| 真游戏单局慢、不可并行 | 终验样本少 | 只跑 12 局；训练集靠捕获+回放，不靠真游戏批量；HandyBalatro 只作可选加速，不作为依赖 |
| 自建引擎与真游戏规则仍不一致 | 训练集 oracle 错 | A2/A3 对齐契约；每个入集局面三项 diff；不一致追根因或排除，不允许“大致一致” |
| 训练集自建变体无法回放 | 场景不可信 | 用 `save`/`load` 在真游戏执行变体；每个变体有 `real_game_score`；不通过即 rejected |
| 12 局终验被误读为“显著” | 结论夸大 | 预注册写“描述统计”；报告限制章单列 n=12；不报 p 值 |
| 游戏文件/截图入库 | 许可/分发风险 | L8：只提交脱敏 JSON、分数、trace、版本清单；截图只放 `evidence/` 且不对外分发 |
| 归因把环境分歧算成 Agent 错 | 归因失真 | 新增 E1 `env_divergence`，与 F1–F4 分开报；判定优先级最低 |
| 扩功能导致 W3 延期 | 全局崩 | 每周硬性 20h 上限 + 砍单顺序（见 `01-每周任务.md`）；真游戏接入不可砍，先砍批量实验与 Pass^k |
| 样本量不足以做显著性 | 结论不可靠 | 事前 power analysis；不足则只报描述统计 + CI；真游戏终验明确不做显著性 |
| 命名冲突（同名 `coder/balatrobench`） | 评审误判“重复工作” | 正式名 + 强制副标题 + 首段区分；备选 `CardBench-Attrib` |
| 许可污染 | 仓库不可分发 | D14 / L7–L9；`docs/data-sources.md` 逐项登记；GPL 只作运行时依赖，不复制代码 |

## 6. 术语

| 术语 | 含义 |
|---|---|
| 对齐训练环境（ATE） | 自建的快速、确定性、规则为 vanilla 严格子集的训练/开发环境 |
| 真实游戏终验（RGFT） | 用 Balatro + balatrobot 跑的小样本最终环境测试（12 局） |
| 对齐契约（AC） | A0 版本 / A1 schema / A2 单步分数 / A3 规则子集 / A4 场景来源与回放 |
| 真游戏锚点 | 从真游戏捕获的决策点（`origin: real_capture`） |
| 反事实变体 | 在锚点局面上 `load` 后执行不同合法动作、真游戏实测得分的决策点（`origin: real_counterfactual`） |
| 场景（scenario） | 一个固定的初始局面 + 合法动作集 + oracle，是评测的最小单位 |
| episode | Agent 从初始局面到局面结束的完整交互序列 |
| Local Oracle | 仅基于当前状态、穷举当前合法动作得到的精确最优动作与分数 |
| Local Regret | `(oracle分 − agent分) / oracle分`，仅在 play 决策上定义 |
| Action Optimality | Agent 选中最优动作（并列算命中）的比例 |
| Legality Rate | 合法工具调用次数 / 总调用次数 |
| Trace | dsh 记录的事件流（含 message、tool/call、tool/result） |
| 归因 | 把一次失败映射到预定义失败类别，并附证据 |
| 环境分歧（E1） | 真游戏结果与训练环境预期不一致；非 Agent 失败，单列 |
| 精确指标 / 近似指标 | 前者由枚举得出，后者带采样误差，报告中必须区分 |
| 三态评估 | 对近似量输出 `{mean, min, max}`，避免把单点估计当精确值 |
| Pass^k | 同一场景独立跑 k 次、全部成功的比例；v3.0 降为可选，默认取消 |
| 首次失败步 | 一条 episode 中 regret 首次超过阈值（默认 0.5）的步序号 |
| 归因证据链 | `rule_id` + `state_hash` + 最小反例 + 受影响后续步 |
| 最小反例 | 把该步动作替换为 oracle 最优后，后续 regret 的变化量 |
| captured-state alignment | 只保证单步状态/分数与真游戏捕获一致，不保证同种子同局面 |
| 重放重算 | 用记录的动作序列重跑引擎并比对分数，保证结果可被第三方复算 |
| L0–L3 | 对齐等级：L0 未对齐 / L1 分数对齐 / L2 规则子集对齐 / L3 真游戏终验通过 |

## 8. 与已有工作的关系（v3.0 按真游戏接入更新）

> 完整论证与逐项目的目的/原理/效果见 `docs/调研报告.md` 2.4 节；本节只留“决策所需的一句话”。

| 工作 | 它做什么 | 它不做什么 | 本项目的关系 |
|---|---|---|---|
| **Evalatro**（[repo](https://github.com/alesha-pro/evalatro)） | 真游戏 + LLM 基准：`score = progress × legality × 100`，Ante 12 目标，服务端重算 transcript + code hash，工具注册表兼作 MCP | 只给**一个总分**；`legality` 只计非法动作数，不分类不定位；无 oracle、无 regret、无归因 | **定位上直接对照、方法上借鉴**（重算校验、code hash、工具单一事实源），不复用代码 |
| **`coder/balatrobench`** | 解析 BalatroLLM 对局记录 → 排行榜与结果分析站点 | 不定义环境、不算 oracle、不归因 | **同名不同目标**，必须在对外材料中显式区分（D12） |
| **`coder/balatrobot`** | 真游戏 JSON-RPC 2.0 控制面（`:12346`，22 方法，`save`/`load`，前置状态校验 + 统一错误码） | 不定义评测协议、不算 oracle、不归因 | **v3.0 接入（📋 未执行）**（MIT）：作为真游戏终验与捕获的唯一适配层；动作下标由本仓库映射为稳定 id |
| **`balatro-rs`** | 离线 Rust 规则引擎 + 穷举动作 + 固定 action mask + 逐字节 RNG + PyO3 | 无固定场景集、无 oracle 最优动作、无失败分类、无 MCP；joker 仅 74/150；**未声明许可证** | **设计对标，不复制**（动作生成器、action mask、RNG 做法可参考） |
| **EXAG 2026 前作**（arXiv:2610.39049） | Rust 模拟器（对真实客户端 state-diff）+ 双策略 PPO | 用**训练曲线**评测；无 oracle regret、无自动归因 | **最直接前作**：证明环境可行、任务真实；本项目把“可判定评测 + 归因 + 真游戏终验”作为差异 |
| **`balatro-gym`** | Gymnasium 封装 | Observation/Action/Reward 三节均标 WIP | **不采用，探针取消** |
| **EFHIII balatro-calculator** | 交互式算分器，求最优打法 | 网页非 API；自述少数 joker 可能不准 | 作为**第三方抽检参照**（5 例，辅助） |
| **Balatro-Simulation / Preview**（DivvyCr） | 按 `cardarea × phase` 分派 effect，随机性用 `{min, exact, max}` 三态 | GPL-3.0、依赖游戏运行时 | **设计上强烈借鉴**（effect 组合器、三态随机、裁剪原则），不拷代码 |
| **DemoEvolve**（arXiv:2605.24539） | 把 Balatro 当长程稀疏反馈评测环境，held-out seeds，报进度 | 只报标量进度，无归因 | 佐证“Balatro 可作评测环境”，并提醒 seed 划分协议 |
| **Zenodo 课程提案** | 提出“超越胜率”的指标需求 | 无实验、无代码 | 只作研究动向引用，不作成果 |
| **Jev / TypeSafe** | 闭源判别式小模型 + 个人 Balatro 接入博客（预打分候选 + Panic Filter） | 无公开仓库、无量化结果、价格未核实 | **只吸收方法论**（精确计算归代码、只给已预打分候选、规则守卫），不引入模型 |

**一句话分界（v3.0 更新）**：生态里“能操作真游戏”和“能算分”已成熟，“能评测但只给总分”已有两个项目；本项目不重复“真游戏+总分”，而是做 **“可判定归因 + 与真游戏对齐的训练环境 + 真游戏终验”** 这个组合。截至 2026-11-12 未发现公开实现。
